# 大模型与数学基础：从零到 LLM、Agent 与 AI 安全

> 适用对象：从零开始，希望最终能读懂本学习库中的 LLM、RAG、Agent、数据投毒和 AI 安全项目。
>
> 阅读原则：先理解直觉，再理解公式；公式不是为了背诵，而是为了精确说明模型在计算什么。

## 使用方式：零基础快速查询入口

```text
不懂名词 → 先查直觉和输入/输出
看不懂代码 → 先查张量 shape 与每层作用
看不懂公式 → 明确变量、目标函数和优化方向
做安全测试 → 画出数据、指令、权限和副作用链
```

打靶前最少应能回答：

```text
[ ] 模型在预测什么
[ ] token、embedding、logit 和 probability 分别是什么
[ ] training 与 inference 有什么区别
[ ] loss、gradient 和 optimizer 如何改变参数
[ ] Prompt、RAG、memory、tool calling 分别在哪一层
[ ] 哪些内容属于不可信数据
[ ] 模型输出会不会被下游当作指令执行
```

推荐查阅顺序：

```text
线性代数与概率直觉
→ 神经网络与梯度下降
→ Transformer / LLM
→ RAG / Agent / 工具调用
→ 数据投毒、提示词注入和输出注入
→ 评估、证据与分层防御
```

这是一份原理底册，不替代各专项笔记的现场检查清单。

## 0. 先看全景：大模型到底处在什么位置

从大到小可以这样理解：

```text
人工智能 AI
└─ 机器学习 ML：从数据中学习规则
   └─ 深度学习 DL：使用多层神经网络学习复杂规则
      └─ 基础模型 Foundation Model：用大规模数据训练，可适配很多任务
         └─ 大语言模型 LLM：以语言 token 为主要处理对象的基础模型
            ├─ Chat Model：经过指令与偏好对齐，适合对话
            ├─ RAG：LLM + 外部检索
            ├─ Agent：LLM + 工具 + 状态 + 执行循环
            └─ 多模态模型：同时处理文本、图像、音频等
```

LLM 最核心的训练任务可以压缩成一句话：

> 给定前面的 token，预测下一个 token 的概率分布。

例如输入：

```text
中国的首都是
```

模型不会先在内部数据库中执行一条“首都查询”。它会根据训练形成的参数和当前上下文，为词表中的候选 token 计算分数，再生成“北京”等 token。

LLM 应用的完整安全对象则是：

```text
模型 + Prompt + 上下文 + 数据 + 检索 + 工具 + 权限 + 输出处理 + 人员与流程
```

所以，“模型拒绝了某个请求”不等于整个应用安全；“模型答错了”也不一定是模型本身的唯一问题。

## 1. AI、机器学习与深度学习基础

### 1.1 传统程序与机器学习

传统程序主要由人写规则：

```text
数据 + 人工规则 → 输出
```

机器学习则让算法从示例中拟合规则：

```text
训练数据 + 学习算法 → 模型参数
新数据 + 模型参数 → 预测
```

这里的“学习”，本质是不断调整一组数字参数，使模型在训练数据上的错误变小。

### 1.2 样本、特征与标签

- 样本（sample）：一条数据，例如一封邮件。
- 特征（feature）：用于描述样本的数值，例如词频、长度或神经网络学到的表示。
- 标签（label）：希望模型预测的答案，例如“垃圾邮件/正常邮件”。
- 参数（parameter）：模型通过训练学到的数值，例如权重和偏置。
- 超参数（hyperparameter）：训练前人为设定的配置，例如学习率、batch size、层数。

若第 $i$ 条样本的特征是 $\mathbf{x}_i$，标签是 $y_i$，训练集可写成：

$$
\mathcal{D}=\{(\mathbf{x}_i,y_i)\}_{i=1}^{N}
$$

### 1.3 监督、无监督与自监督学习

- 监督学习：有人工或业务标签，例如用“恶意/正常”样本训练分类器。
- 无监督学习：没有目标标签，寻找聚类、结构或异常。
- 自监督学习：标签由数据本身构造。LLM 的“下一个 token”答案直接来自原文本，因此可以利用海量未人工标注文本。
- 强化学习：Agent 与环境交互，根据奖励学习行为策略。

LLM 预训练主要是自监督学习；指令微调通常是监督学习；部分偏好对齐会使用强化学习或直接偏好优化。

### 1.4 训练集、验证集与测试集

- 训练集：用于更新参数。
- 验证集：用于选超参数、阈值和模型版本。
- 测试集：最后一次客观评估，不应反复拿来调模型。

三者必须尽量独立。若同一任务的改写、翻译或相近样本同时落入训练集和测试集，就会发生数据泄漏，测试结果可能虚高。

### 1.5 拟合、泛化、欠拟合与过拟合

- 拟合：模型学习训练数据中的规律。
- 泛化：模型在未见数据上仍然有效。
- 欠拟合：模型太简单或训练不足，训练集和测试集都表现差。
- 过拟合：模型记住训练细节，训练集很好、测试集变差。

模型的目标不是背下训练集，而是学习可迁移的规律。AI 安全研究还要进一步问：模型学到的是安全边界，还是长度、格式、关键词等“捷径特征”。

## 2. 数学地基一：标量、向量、矩阵与张量

### 2.1 四种基本对象

- 标量：一个数，如学习率 $0.001$。
- 向量：一列数，如一条样本的特征 $\mathbf{x}=[x_1,x_2,\ldots,x_d]$。
- 矩阵：二维数表，如一批样本组成的 $X\in\mathbb{R}^{N\times d}$。
- 张量：更高维数组。LLM 中常见形状为 `batch × sequence × hidden_dimension`。

维度必须匹配。例如：

$$
X_{N\times d}W_{d\times h}=H_{N\times h}
$$

这表示每条 $d$ 维输入经权重矩阵变成 $h$ 维隐藏表示。

### 2.2 点积：衡量方向相似，也用于加权求和

两个向量的点积：

$$
\mathbf{a}\cdot\mathbf{b}=\sum_{j=1}^{d}a_jb_j
$$

在线性模型中，$\mathbf{w}^T\mathbf{x}$ 是各特征乘权重后的总分。在注意力中，Query 与 Key 的点积用于计算一个 token 应该关注另一个 token 的程度。

### 2.3 范数与距离

L2 范数表示向量长度：

$$
\lVert\mathbf{x}\rVert_2=\sqrt{\sum_jx_j^2}
$$

两个向量的欧氏距离：

$$
d(\mathbf{x},\mathbf{y})=\lVert\mathbf{x}-\mathbf{y}\rVert_2
$$

这在最近邻、特征碰撞和扰动限制中很常见。Clean Label Attack 中的
$\lVert x_p-x_b\rVert\le\epsilon$ 表示污染样本不能偏离原样本太远。

### 2.4 余弦相似度

$$
\cos(\mathbf{a},\mathbf{b})=
\frac{\mathbf{a}\cdot\mathbf{b}}
{\lVert\mathbf{a}\rVert\lVert\mathbf{b}\rVert}
$$

它主要比较方向，值越大通常表示语义越相似。RAG 常使用余弦相似度或与之近似的距离检索文档。

重要限制：

> 向量相似只表示表示空间中的接近，不表示内容真实、可信、有权限或没有恶意指令。

## 3. 数学地基二：函数、导数、梯度与链式法则

### 3.1 函数与损失函数

模型可以看成参数为 $\theta$ 的函数：

$$
\hat y=f_{\theta}(x)
$$

损失函数 $L(\theta)$ 衡量预测与目标之间有多错。训练就是寻找使损失较小的参数：

$$
\theta^*=\arg\min_{\theta}L(\theta)
$$

### 3.2 导数与梯度

一元函数的导数表示输入稍微变化时，输出怎样变化。多参数函数的所有偏导数组成梯度：

$$
\nabla_{\theta}L=
\left[
\frac{\partial L}{\partial\theta_1},
\ldots,
\frac{\partial L}{\partial\theta_m}
\right]
$$

梯度指向损失增长最快的方向，因此梯度下降沿反方向更新：

$$
\theta_{t+1}=\theta_t-\eta\nabla_{\theta}L
$$

其中 $\eta$ 是学习率。太大可能震荡或发散，太小则训练很慢。

### 3.3 链式法则与反向传播

神经网络由许多嵌套函数组成。若 $y=f(g(x))$，则：

$$
\frac{dy}{dx}=\frac{df}{dg}\frac{dg}{dx}
$$

反向传播就是从最终损失开始，利用链式法则逐层计算每个参数对损失的影响。它不是另一种模型，而是高效求梯度的方法。

### 3.4 Mini-batch、SGD 与 Adam

- Batch Gradient Descent：每次用全部训练数据，稳定但昂贵。
- SGD：每次用一个样本，噪声大。
- Mini-batch：每次用一小批样本，是深度学习常见做法。
- Adam：结合动量和自适应学习率，是 LLM 训练常见优化器家族。

Epoch 表示完整看过一遍训练集；step 表示完成一次参数更新。

## 4. 数学地基三：概率、信息量与统计

### 4.1 概率与条件概率

条件概率：

$$
P(A\mid B)=\frac{P(A\cap B)}{P(B)}
$$

语言模型计算的正是条件概率，例如：

$$
P(x_t\mid x_1,x_2,\ldots,x_{t-1})
$$

整段 token 序列的概率可由链式分解表示：

$$
P(x_1,\ldots,x_T)=\prod_{t=1}^{T}P(x_t\mid x_{<t})
$$

### 4.2 Logit、Sigmoid 与 Softmax

Logit 是模型送入概率转换前的原始分数，不是概率。

二分类常用 Sigmoid：

$$
\sigma(z)=\frac{1}{1+e^{-z}}
$$

多分类和 LLM 词表预测常用 Softmax：

$$
P(i)=\frac{e^{z_i}}{\sum_{j=1}^{V}e^{z_j}}
$$

其中 $V$ 是类别数或词表大小。Softmax 把所有候选 logit 转为总和等于 1 的概率分布。

### 4.3 对数为什么常见

很多很小概率连乘会数值下溢。取对数后，乘法变加法：

$$
\log\prod_tp_t=\sum_t\log p_t
$$

因此训练通常最大化正确 token 的对数似然，等价于最小化负对数似然。

### 4.4 信息熵、交叉熵与 KL 散度

信息熵衡量分布的不确定性：

$$
H(P)=-\sum_iP(i)\log P(i)
$$

交叉熵衡量真实分布 $P$ 与模型分布 $Q$ 的差异：

$$
H(P,Q)=-\sum_iP(i)\log Q(i)
$$

当真实答案是 one-hot 标签时，交叉熵就是正确类别概率的负对数。模型越不相信正确答案，惩罚越大。

KL 散度衡量两个概率分布的差异：

$$
D_{KL}(P\|Q)=\sum_iP(i)\log\frac{P(i)}{Q(i)}
$$

它不对称，因此严格说不是距离。模型蒸馏、分布约束和对齐算法中经常出现。

### 4.5 均值、方差与标准差

均值：

$$
\bar x=\frac{1}{N}\sum_{i=1}^{N}x_i
$$

方差衡量波动：

$$
s^2=\frac{1}{N-1}\sum_{i=1}^{N}(x_i-\bar x)^2
$$

只报告一次实验结果不可靠。应使用多个随机种子，报告均值、波动和置信区间。

### 4.6 Bootstrap 置信区间

Bootstrap 的直觉是：从现有测试单位中“有放回抽样”很多次，每次重新计算指标，由这些指标的分布估计 95% 置信区间。

若评估单位是 Agent trajectory，应按 trajectory 或 scenario 抽样，而不是把同一 trajectory 内的 token 当成互相独立的样本。配对比较时，两种方法必须在每次重采样中保留相同样本配对。

置信区间不是“真实值有 95% 概率在这个已算出的区间里”的简单陈述；更准确地说，若反复按同一方法取样并构造区间，约 95% 的区间会覆盖真实参数。

## 5. 从 Logistic Regression 理解“模型怎样学习”

本学习库的标签翻转实验使用 Logistic Regression，它是理解神经网络和投毒的最佳入口。

### 5.1 线性打分

$$
z=\mathbf{w}^T\mathbf{x}+b
$$

权重 $\mathbf{w}$ 表示各特征对结果的影响，偏置 $b$ 调整整体门槛。

### 5.2 概率与分类

$$
p=P(y=1\mid\mathbf{x})=\sigma(z)
$$

默认阈值为 0.5 时，$z\ge0$ 判为 1，$z<0$ 判为 0。

### 5.3 二元交叉熵

$$
L=-\frac{1}{N}\sum_{i=1}^{N}
[y_i\log p_i+(1-y_i)\log(1-p_i)]
$$

标签翻转把正确的 $y_i$ 改成错误值，使梯度要求模型朝相反方向调整参数。这就是错误标签推动决策边界移动的数学原因。

### 5.4 决策边界与几何距离

二维线性模型的决策边界为：

$$
w_1x_1+w_2x_2+b=0
$$

点到边界的距离：

$$
d(\mathbf{x})=\frac{|\mathbf{w}^T\mathbf{x}+b|}{\lVert\mathbf{w}\rVert}
$$

距离小的样本裕量小，边界轻微变化就可能使其分类翻转，所以边界附近样本常是定向投毒的高价值目标。

### 5.5 从线性模型到神经网络

Logistic Regression 只有一次线性变换。神经网络把“线性变换 + 非线性激活”重复很多次：

$$
\mathbf{h}^{(l)}=\phi(W^{(l)}\mathbf{h}^{(l-1)}+\mathbf{b}^{(l)})
$$

没有非线性激活，多层线性变换仍可合并成一层线性变换，无法表示复杂边界。常见激活函数包括 ReLU、GELU 和 SiLU。

## 6. 神经网络、表示与深度学习

### 6.1 神经元和层

一个人工神经元完成：加权求和、加偏置、过激活函数。很多神经元形成层，很多层形成深度网络。

网络中间产生的向量称为隐藏表示（hidden representation）或 hidden state。它不是人类直接设计的“含义字段”，而是模型为完成训练目标学到的高维特征。

### 6.2 参数量

参数主要来自权重矩阵和偏置。一个 $d_{in}\to d_{out}$ 的全连接层约有：

$$
d_{in}d_{out}+d_{out}
$$

个参数。LLM 所说的 7B、70B，通常表示约 70 亿、700 亿可学习参数，不表示训练文档数量，也不直接等同于能力或内存占用。

### 6.3 正则化与泛化

常见手段包括：

- Weight decay：限制参数过度增大。
- Dropout：训练时随机屏蔽部分激活。
- Early stopping：验证集不再改善时停止。
- 数据增强：构造合理变体。
- 更严格的数据划分：阻止重复和模板泄漏。

### 6.4 计算精度与显存

模型权重可用 FP32、FP16、BF16、INT8、INT4 等格式保存或计算。低位量化可降低显存和提高推理速度，但可能带来精度损失。

粗略权重内存：参数量 × 每参数字节数。例如 7B 模型若仅以 FP16 保存权重，理论权重约 14 GB；实际运行还需要 KV cache、激活、框架开销等。训练还需梯度和优化器状态，远高于只做推理。

## 7. 文本怎样进入大模型：Tokenization 与 Embedding

### 7.1 Token 不是字，也不一定是词

Tokenizer 把文本切成词表中的 token ID：

```text
文本 → token 序列 → token ID 序列
```

中文字符、英文词根、空格、标点和代码片段都可能形成不同 token。不同模型的 tokenizer 不同，所以字符数不能精确等同于 token 数。

特殊 token 可标记消息边界、序列开始/结束或工具调用结构。

### 7.2 词表与 Embedding 表

词表大小为 $V$，隐藏维度为 $d$ 时，Embedding 矩阵可写为：

$$
E\in\mathbb{R}^{V\times d}
$$

根据 token ID 取出对应行，就得到该 token 的初始向量。Embedding 是模型训练出的连续表示，不是一本人工编写的词义字典。

### 7.3 位置信息

纯注意力本身不知道 token 顺序，因此模型需要位置编码。常见方案包括绝对位置编码、相对位置偏置和 RoPE（旋转位置编码）。

位置机制让“人咬狗”和“狗咬人”产生不同表示，也影响模型能否外推到更长上下文。

### 7.4 上下文窗口

上下文通常包括：

- system/developer/user 消息；
- 历史对话；
- RAG 文档；
- 工具定义与工具结果；
- 应用添加的元数据；
- 模型将要生成的输出。

超过窗口时，系统可能截断、摘要或丢弃内容。上下文更长不保证模型能同等重视每个位置；“能放进去”不等于“能稳定利用”。

## 8. Transformer：LLM 的核心架构

### 8.1 为什么需要 Attention

一句话中的每个 token，其含义依赖其他 token。Attention 允许模型为当前 token 动态聚合其他位置的信息。

### 8.2 Query、Key、Value

输入表示矩阵为 $X$，通过三个投影得到：

$$
Q=XW_Q,\quad K=XW_K,\quad V=XW_V
$$

直觉上：

- Query：我正在寻找什么信息？
- Key：我能被什么查询匹配？
- Value：如果关注我，应该取走什么内容？

### 8.3 Scaled Dot-Product Attention

$$
\operatorname{Attention}(Q,K,V)=
\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}+M\right)V
$$

逐步理解：

1. $QK^T$：计算每个 Query 与所有 Key 的匹配分数。
2. 除以 $\sqrt{d_k}$：避免维度大时点积过大，Softmax 过度饱和。
3. 加掩码 $M$：禁止关注不应看到的位置。
4. Softmax：把分数变成权重。
5. 乘 $V$：按权重汇总信息。

### 8.4 Causal Mask

自回归 LLM 在预测第 $t$ 个 token 时不能偷看后面的真实 token，因此使用因果掩码屏蔽未来位置。

```text
位置 1 可看：1
位置 2 可看：1,2
位置 3 可看：1,2,3
```

### 8.5 Multi-Head Attention

多个注意力头使用不同投影，允许模型同时学习多种关系，再拼接并投影：

$$
\operatorname{MHA}(X)=
\operatorname{Concat}(head_1,\ldots,head_h)W_O
$$

“某个头必然对应某种人类语法规则”通常不能未经验证地断言；注意力模式可能是分布式和上下文相关的。

### 8.6 一个 Transformer Block

典型 Block 包含：

```text
输入
→ LayerNorm
→ Self-Attention
→ 残差连接
→ LayerNorm
→ MLP / Feed-Forward
→ 残差连接
```

- 残差连接让信息和梯度更容易跨层传播。
- LayerNorm 稳定激活尺度。
- MLP 对每个 token 位置进行非线性特征变换。

很多 Block 堆叠后形成深层 Transformer。

### 8.7 Hidden State 与 Attention 不等于解释

每层每个 token 都有 hidden state。安全项目可以训练 linear probe，从 hidden state 预测“是否可能发生未授权工具调用”。但高准确率不自动证明模型内部存在一个清晰的“恶意意图神经元”。探针可能学到：

- 文本长度；
- JSON 格式；
- 某个工具名；
- 某类攻击模板；
- 是否出现第二条指令；
- 语言差异。

因此需要 authorization-matched 数据、强文本基线、分组 OOD 划分和消融实验，证明信号对应真正的授权冲突而非表面捷径。

### 8.8 计算复杂度与 KV Cache

标准全注意力需要构造长度 $n$ 的两两关系，时间和注意力矩阵内存大致为 $O(n^2)$。这也是长上下文昂贵的重要原因。

推理时 KV cache 保存已生成 token 的 Key/Value，避免每生成一个 token 都重算全部历史。它会随序列长度、层数、batch 和并发增长，占用显存。

## 9. LLM 如何训练

### 9.1 预训练：Next-Token Prediction

给定 token 序列 $x_1,\ldots,x_T$，训练损失为：

$$
L=-\sum_{t=1}^{T}\log P_{\theta}(x_t\mid x_{<t})
$$

模型通过海量文本学到语言形式、事实关联、代码模式和一定程度的推理模式。它学习的是分布规律，不是经过完整事实审计的知识库。

### 9.2 Perplexity（困惑度）

若平均交叉熵为 $L$，困惑度为：

$$
PPL=e^L
$$

越低通常表示模型越能预测该数据集中的 token。但不同 tokenizer、数据集和任务间不可简单横比；低困惑度也不等于事实可靠或应用安全。

### 9.3 Instruction Tuning / SFT

监督微调（SFT）使用“指令—理想回答”样本，让基础模型学会遵循任务、对话格式和输出风格。

Base Model 更像文本续写器；经过 SFT 的 Chat Model 更擅长回答用户问题。但这仍是统计行为，不是硬权限系统。

### 9.4 Preference Alignment

人或模型对多个候选回答进行偏好比较，再用于对齐：

- RLHF：训练奖励模型，再用强化学习优化策略。
- RLAIF：偏好反馈主要由 AI 产生。
- DPO：直接利用偏好对优化策略，无需完整 RL 循环。

对齐能提高有用性和安全行为，但不能证明对所有越狱、注入和分布外输入都可靠。

### 9.5 Fine-tuning、LoRA 与量化微调

- 全参数微调：更新模型全部参数，成本和存储高。
- LoRA：冻结原权重，用低秩矩阵学习增量，显著减少可训练参数。
- QLoRA：在量化基础模型上训练 LoRA adapter，进一步节省显存。

微调适合改变行为、风格或专业任务能力，不适合频繁注入不断变化的事实。业务知识更新通常更适合 RAG。

### 9.6 训练数据风险

训练数据可能包含：

- 错误、偏见、重复和版权敏感内容；
- 个人信息或密钥；
- 恶意标签；
- 后门触发器；
- 不安全代码；
- 被污染的数据处理逻辑。

所以要建立数据来源、版本、哈希、处理代码、访问权限和发布门禁的完整谱系。

## 10. LLM 如何生成：解码与推理参数

### 10.1 从 Logits 到下一个 Token

模型先得到词表 logits，再通过 Softmax 得到概率。然后选择或采样一个 token，追加到上下文，重复这一过程直到结束条件。

### 10.2 Greedy、Temperature、Top-k 与 Top-p

- Greedy：每次选概率最高 token，较稳定但不保证全局最佳。
- Temperature：对 logits 除以 $T$ 后再 Softmax。$T<1$ 更集中，$T>1$ 更随机。
- Top-k：只在概率最高的 k 个 token 中采样。
- Top-p：选择累计概率达到 p 的最小候选集合再采样。

Temperature 为 0 的接口行为取决于具体实现；即使使用贪心，同一服务也可能因模型版本、并行计算或后端变化出现差异。

### 10.3 为什么“高 token 概率”不等于事实正确

概率表示某段语言在模型分布中自然，不表示它已通过现实世界核验。一个常见但错误的说法也可能有很高概率。

### 10.4 输出长度与停止条件

生成可因结束 token、最大输出 token、停止字符串、工具调用或应用中断而停止。上下文预算通常要同时容纳输入和输出。

## 11. Prompt、消息角色与多轮对话

### 11.1 Prompt 的组成

一个完整 Prompt 可能包含角色、目标、背景、限制、示例、输出 schema 和不可信数据。清晰的 Prompt 能提升可用性，但不能成为唯一安全控制。

### 11.2 System、Developer、User 与 Tool 内容

现代 Chat API 会用不同消息角色和特殊 token 表示指令层级，模型也可能接受过指令层级训练。但这是一种模型行为约束，不是操作系统式内存隔离或访问控制。

因此更准确的表述是：

> 模型能识别并通常遵循角色优先级，但不能把这种遵循当作不可绕过的安全边界。

真正的权限、对象级授权、网络出口限制和危险操作确认必须由确定性应用代码实施。

### 11.3 多轮对话

模型通常没有独立于输入的永久“聊天记忆”。应用把历史消息、摘要或保存的状态重新加入上下文，模型才表现出记忆。

风险包括：历史注入持续生效、敏感内容跨轮泄露、错误摘要固化、旧授权被错误沿用。

### 11.4 Prompt Engineering 与 Prompt Injection

- Prompt Engineering：合法设计输入以提高输出质量。
- Prompt Injection：不可信输入试图改变模型原任务、泄露数据或触发未授权动作。
- Jailbreak：重点是绕过模型的内容或行为安全限制。

两者可能重叠，但攻击目标不同。注入更关注应用中的指令/数据混淆；越狱更关注模型政策绕过。

## 12. RAG：让模型临时查资料

### 12.1 标准流程

```text
文档 → 清洗/切块 → Embedding → 向量库
用户问题 → Embedding → 相似度检索 → 重排
→ 拼接检索内容与指令 → LLM 生成 → 引用/后处理
```

### 12.2 Chunking

文档通常被切成 chunk。太小会丢失上下文，太大则引入噪声并消耗 token。常使用重叠窗口、标题层级或语义边界切分。

### 12.3 Dense、Sparse 与 Hybrid Retrieval

- Sparse retrieval：如 BM25，依赖词项匹配。
- Dense retrieval：使用 embedding 语义相似度。
- Hybrid：结合两者。
- Reranker：对初步候选做更精细排序。

### 12.4 RAG 不会自动消除幻觉

RAG 可以提供较新或私有证据，但仍可能：

- 没检索到正确文档；
- 检索到错误或过期文档；
- 模型忽略证据；
- 模型引用与结论不匹配；
- 权限过滤失败；
- 恶意文档发起间接 Prompt Injection。

### 12.5 RAG 的安全边界

必须分别控制：

1. 文档能否进入知识库；
2. 哪个用户能检索哪个 chunk；
3. 文档来源和可信度；
4. 检索内容只能作为数据，不能获得工具权限；
5. 输出中的引用和事实能否回溯；
6. 敏感数据是否会被拼入不必要的上下文。

相似度检索不是授权检查，Prompt 中写“不要执行文档指令”也不是完整防御。

## 13. Agent 与 Function Calling

### 13.1 Agent 是什么

```text
Agent = LLM + 目标 + 状态/记忆 + 工具 + 执行循环 + 停止条件
```

典型循环：

```text
观察环境 → 规划/选择动作 → 产生候选工具调用
→ 安全与授权检查 → 工具执行 → 返回观察结果 → 继续或结束
```

### 13.2 Function Calling 不是让模型直接执行函数

正常实现中，模型输出结构化候选调用，例如：

```json
{"name":"get_weather","arguments":{"city":"Shanghai"}}
```

应用负责：解析、schema 校验、鉴权、执行业务函数并返回结果。模型提出调用，不应拥有最终授权。

危险实现包括把模型文本交给 `eval`、`exec`、shell 或动态 SQL，或者只凭模型自述“用户是管理员”完成授权。

### 13.3 Excessive Agency

当 Agent 权限、工具范围、自动执行能力或持续时间超过任务所需时，错误和注入的爆炸半径扩大。控制措施包括：

- 最小权限和短期凭证；
- 工具 allowlist 与参数约束；
- 服务端对象级授权；
- 高风险动作人工确认；
- dry-run、事务和可撤销操作；
- 网络和文件系统沙箱；
- 预算、步数和时间上限；
- 完整审计日志。

### 13.4 Provenance 与 Goal–Action Authorization

Provenance 表示信息来自可信用户、网页、邮件还是工具结果。授权门应判断：

```text
可信用户目标 + 候选工具 + 精确参数 + 数据来源 + 当前环境状态
```

输出可为 `ALLOW / BLOCK / CONFIRM`。这比只检测“文本是否恶意”更贴近真实安全边界：同一个工具和参数，在用户明确授权时可能合法，被网页暗中诱导时则未授权。

## 14. 多模态模型

多模态模型会把图片、音频、视频或文档编码为模型可处理的表示，再与文本共同推理。

风险不只来自文本框：

- 图片中的可见或隐蔽指令；
- OCR 提取的恶意文本；
- PDF 元数据、批注或隐藏层；
- 音频中的语音指令；
- 视频帧中的短暂内容；
- 不同模态间的指令冲突。

安全原则仍相同：外部内容默认是不可信数据，不因模型“看懂了”就获得指令权或工具权限。

## 15. 幻觉、事实性与不确定性

### 15.1 幻觉是什么

幻觉是模型生成了流畅、看似可信但不受输入或现实证据支持的内容。可分为：

- 事实冲突：与客观事实冲突。
- 输入冲突：摘要或抽取添加了输入中不存在的信息。
- 上下文冲突：同一回答或多轮状态互相矛盾。

### 15.2 为什么发生

LLM 的原生目标是预测语言，而不是执行数据库级事实验证。训练数据的错误、知识截止、模糊 Prompt、检索失败和应用强迫回答都会增加幻觉。

### 15.3 三类置信信号的局限

- Logit-based：token 高概率不等于事实正确。
- Verbalized confidence：模型说“95%”不代表经过校准。
- Consistency-based：多次都一样可能是稳定地答错。

更可靠的设计是把答案、证据、未知项和复核要求分开，并用外部可信来源或确定性规则核验。

### 15.4 Calibration

若模型对一批事件都给出 80% 置信度，理想校准意味着其中约 80% 确实正确。准确率高不一定校准好。

Brier Score：

$$
\operatorname{Brier}=\frac{1}{N}\sum_i(p_i-y_i)^2
$$

越低越好。ECE 则把预测概率分箱，比较每箱平均置信度与实际正确率的差异。

## 16. 评估指标：怎样知道模型好不好

### 16.1 混淆矩阵

二分类有四种结果：

| 真实/预测 | 预测正 | 预测负 |
|---|---:|---:|
| 真实正 | TP | FN |
| 真实负 | FP | TN |

### 16.2 Accuracy、Precision、Recall、F1

$$
Accuracy=\frac{TP+TN}{TP+TN+FP+FN}
$$

$$
Precision=\frac{TP}{TP+FP}
$$

$$
Recall=\frac{TP}{TP+FN}
$$

$$
F1=2\frac{Precision\cdot Recall}{Precision+Recall}
$$

- Precision 回答：“模型判为正的样本中，有多少真是正？”
- Recall 回答：“所有真实正样本中，模型找到了多少？”

类别极不平衡时，Accuracy 可能严重误导。例如 1% 样本是攻击，永远预测正常也有 99% Accuracy，但安全检测能力为零。

### 16.3 Macro、Micro 与 Weighted

- Macro：每个类别指标等权平均，重视少数类。
- Micro：汇总所有样本计数再计算，受大类影响更大。
- Weighted：按各类别样本数加权。

### 16.4 ROC、AUROC、PR 与 AUPRC

- TPR = Recall。
- FPR = $FP/(FP+TN)$。
- ROC 曲线展示不同阈值下 TPR 与 FPR。
- AUROC 可理解为随机抽一正一负时，正样本得分高于负样本的概率。
- PR 曲线展示 Precision–Recall 权衡；正类稀少时通常更值得关注 AUPRC。

高 AUROC 不代表某个部署阈值可用。安全系统还应报告 `TPR@1% FPR`、`FPR@95% TPR` 等低误报工作点。

### 16.5 生成式任务指标

- Exact Match：答案必须完全一致，严格但可能低估同义正确答案。
- ROUGE/BLEU：基于词片段重合，适合有限场景，不等于事实性。
- Human evaluation：灵活但昂贵，需明确 rubric 和一致性。
- LLM-as-a-Judge：规模化方便，但可能有偏差、提示敏感、被注入或版本漂移。

能用环境状态、数据库字段或单元测试作为 oracle 时，应优先于自由文本 judge。

### 16.6 Agent 安全指标

- ASR（Attack Success Rate）：攻击成功比例。
- Clean Utility：无攻击时正常任务完成能力。
- Utility Under Attack：受攻击时仍完成合法目标的能力。
- Invalid/Abstain Rate：无效运行或拒绝比例。
- Confirmation Rate：请求人工确认的比例。
- Latency、成本、显存和危险动作前 lead time。

只降低 ASR 但把全部请求都阻止，不是有用的安全系统；必须同时报告 utility。

## 17. AI 数据管线与数据投毒

### 17.1 六阶段数据管线

```text
收集 → 存储 → 处理/转换 → 分析/训练 → 部署 → 监控/反馈/再训练
```

每阶段都可能改变最终模型：不只原始数据文件，标签映射代码、特征处理、模型文件、部署下载链和在线反馈也是攻击面。

### 17.2 Label Flipping

攻击者修改训练标签。随机翻转可能降低整体性能；定向翻转只影响特定类别、群体或边界区域，可能更隐蔽。

标签变化会改变交叉熵梯度，从而改变参数和决策边界。必须用同一个干净测试集比较干净模型与污染模型，并检查分类别指标、概率、校准和边界，而不只看 Accuracy。

### 17.3 Targeted Label Attack

攻击目标是让某个类别或样本朝指定类别误判。目标类到攻击类的定向误判率可写为：

$$
TMR_{a\rightarrow b}=
\frac{\#\{y=a,\hat y=b\}}{\#\{y=a\}}
$$

二分类中若把正类 1 定向误判为 0，则：

$$
TMR_{1\rightarrow0}=\frac{FN}{TP+FN}=1-Recall_1
$$

还应按供应商、地区、语言等分群检查，否则总体指标可能掩盖局部伤害。

### 17.4 Clean Label Attack

Clean Label Attack（干净标签攻击）的关键不是把标签改错，而是利用“人看到的输入”和“模型用于分类的内部表示”之间并不完全一致这一点。

#### 17.4.1 三个样本和一个特征提取器

先定义四个对象：

- $x_b$（base sample）：基础样本，来自攻击者希望伪装成的类别。
- $x_p$（poison sample）：由基础样本修改得到、最终加入训练集的污染样本。
- $x_t$（target sample）：攻击者希望模型在未来误分类的目标样本。
- $f_\theta(\cdot)$：模型的特征提取器，把原始输入映射为内部表示。

例如，攻击者希望某张真实属于 Class 1 的目标图片 $x_t$ 被判成 Class 0：

```text
x_b：一张真实的 Class 0 图片
x_p：由 x_b 轻微修改得到，标签仍为 Class 0
x_t：真实的 Class 1 目标图片
```

攻击者希望同时满足两件看起来矛盾的事情：

```text
输入空间：x_p 接近 x_b
→ 人或普通数据检查仍认为 x_p 属于 Class 0

表示空间：f(x_p) 接近 f(x_t)
→ 模型内部却认为 x_p 和目标 x_t 很相似
```

#### 17.4.2 输入空间是什么

输入空间是模型收到的原始数值空间。例如一张 RGB 图片可以表示成：

$$
x\in[0,1]^{H\times W\times3}
$$

如果图片高为 $H$、宽为 $W$，每个像素有红、绿、蓝三个通道，那么每个像素值都是输入空间的一个坐标。文本、表格和传感器数据也都有各自的原始输入空间。

污染样本与基础样本的输入距离可写为：

$$
d_{\mathrm{input}}(x_p,x_b)
=\lVert x_p-x_b\rVert_2
$$

若添加硬约束：

$$
\lVert x_p-x_b\rVert_2\leq\epsilon
$$

就表示 $x_p$ 必须留在以 $x_b$ 为中心、半径为 $\epsilon$ 的高维球体中。$\epsilon$ 越小，允许的总体修改越少。

但是，L2 距离小只表示数值变化有限，不自动等于“人眼绝对无法察觉”或“语义一定不变”。实际实验还要说明：

- 输入是否归一化到 $[0,1]$ 或其他范围；
- $\epsilon$ 是针对整张图片还是单个像素；
- 使用 L2、L∞ 还是感知距离；
- 修改后是否仍由人工或可靠标注器判为原类别。

#### 17.4.3 表示空间是什么

深度模型不会直接用原始像素做最终分类。前面的多层网络会把输入转换为隐藏表示：

$$
z=f_\theta(x)
$$

这里的 $z$ 可以是几百或几千维向量，包含模型为完成训练任务学到的边缘、纹理、形状和更抽象的类别信息。最后的分类头再根据 $z$ 计算类别分数：

$$
\operatorname{logits}=Wz+b
$$

因此模型真正用于画决策边界的主要对象不是原始输入 $x$，而是表示 $f_\theta(x)$。

污染样本与目标样本的表示距离为：

$$
d_{\mathrm{feature}}(x_p,x_t)
=\lVert f_\theta(x_p)-f_\theta(x_t)\rVert_2
$$

攻击者希望这个距离尽量小，即发生“特征碰撞”：

$$
f_\theta(x_p)\approx f_\theta(x_t)
$$

#### 17.4.4 为什么两种距离可能完全不同

$f_\theta(\cdot)$ 是由很多矩阵运算和非线性激活组成的复杂映射，不是保持距离不变的简单坐标转换。因此通常不存在：

$$
\lVert x_p-x_b\rVert_2\text{ 很小}
\quad\Longrightarrow\quad
\lVert f_\theta(x_p)-f_\theta(x_b)\rVert_2\text{ 也一定很小}
$$

可能出现两种现象：

1. 原始输入只变化很少，内部表示却跨过了重要的特征方向。
2. 原始输入看起来差别很大，内部表示却因共享语义而非常接近。

这就像两张图片在“像素坐标系”中很远，但模型把它们都概括成“带轮子的车辆”，所以在语义表示空间中很近。反过来，一些人眼难以察觉的纹理变化也可能显著影响模型依赖的特征。

#### 17.4.5 联合优化目标

典型的简化优化目标是：

$$
\min_{x_p}\;
\underbrace{\lVert f_\theta(x_p)-f_\theta(x_t)\rVert_2^2}
_{\text{让污染表示接近目标表示}}
+
\beta
\underbrace{\lVert x_p-x_b\rVert_2^2}
_{\text{让污染输入接近基础输入}}
$$

第一项是攻击效果项：如果它变小，说明污染样本与目标样本在模型眼中越来越相似。

第二项是隐蔽性或保真项：如果它变小，说明污染样本仍接近原始基础样本。

$\beta$ 控制两者的权衡：

- $\beta$ 较小：更重视特征碰撞，攻击可能更强，但输入变化可能更明显。
- $\beta$ 较大：更重视保持原样，污染更隐蔽，但可能无法靠近目标表示。
- $\beta$ 不是安全常数，必须结合数据范围、模型和威胁模型调节。

若同时使用硬约束，可以写成：

$$
\begin{aligned}
\min_{x_p}\quad&
\lVert f_\theta(x_p)-f_\theta(x_t)\rVert_2^2\\
\text{s.t.}\quad&
\lVert x_p-x_b\rVert_2\leq\epsilon
\end{aligned}
$$

这表示：在所有“离基础样本不超过 $\epsilon$”的候选中，寻找表示最接近目标的那个样本。

#### 17.4.6 梯度到底怎样修改污染样本

令目标函数为：

$$
J(x_p)=
\lVert f_\theta(x_p)-f_\theta(x_t)\rVert_2^2
+\beta\lVert x_p-x_b\rVert_2^2
$$

对 $x_p$ 求梯度，可抽象写成：

$$
\nabla_{x_p}J
=
2J_f(x_p)^T
\bigl(f_\theta(x_p)-f_\theta(x_t)\bigr)
+2\beta(x_p-x_b)
$$

其中 $J_f(x_p)$ 是特征提取器相对于输入的 Jacobian，用来描述“每个输入位置轻微变化时，内部表示怎样变化”。

两部分梯度分别产生相反作用：

- 第一部分寻找能让 $f_\theta(x_p)$ 朝 $f_\theta(x_t)$ 移动的输入方向。
- 第二部分像一根弹簧，把 $x_p$ 拉回基础样本 $x_b$。

梯度下降更新为：

$$
x_p^{(k+1)}
=x_p^{(k)}-\eta\nabla_{x_p}J
$$

若存在 $\epsilon$ 约束，更新后还要投影回允许区域：

$$
x_p^{(k+1)}
=\Pi_{\mathcal{B}(x_b,\epsilon)}
\left(
x_p^{(k)}-\eta\nabla_{x_p}J
\right)
$$

$\Pi$ 表示投影操作，$\mathcal{B}(x_b,\epsilon)$ 表示以 $x_b$ 为中心的允许扰动区域。直觉上就是：先按照梯度修改，再把越界部分拉回合法范围。

#### 17.4.7 为什么把污染样本加入训练集会影响目标

构造完成后，训练集包含：

$$
(x_p,y_b)
$$

其中标签 $y_b$ 仍然是基础类别的正确标签，所以人工标签检查可能不会发现问题。但是在表示空间中：

$$
f_\theta(x_p)\approx f_\theta(x_t)
$$

分类器训练时被要求把 $f_\theta(x_p)$ 判为基础类别。为了降低这条训练样本的损失，分类边界会扩大基础类别在该区域的覆盖范围。由于目标表示 $f_\theta(x_t)$ 就在附近，目标也可能落入基础类别区域：

```text
攻击前：
Class 0 区域 | 决策边界 | x_t（Class 1）

加入标签仍为 Class 0 的 x_p，且 f(x_p) 靠近 f(x_t)
                         ↓
模型为了正确分类 x_p，移动边界
                         ↓
攻击后：
Class 0 区域扩张并覆盖 x_p 和 x_t
```

因此，污染样本本身的标签没有错，真正被操纵的是训练过程所学习的表示与决策边界。

#### 17.4.8 为什么迁移学习场景尤其典型

在经典特征碰撞攻击中，预训练特征提取器 $f_\theta$ 通常被冻结，只重新训练最后的线性分类头。这样攻击者优化 $x_p$ 时使用的表示空间，与受害者训练分类头时使用的表示空间比较稳定。

如果受害者会端到端更新全部网络参数，那么加入污染样本后，$f_\theta$ 自己也会变化。简单的固定特征碰撞目标可能失效，需要考虑“污染如何影响训练后的参数”的双层优化：

$$
\begin{aligned}
\theta^*(x_p)
&=\arg\min_\theta L_{\mathrm{train}}
\bigl(\theta;\mathcal{D}\cup\{(x_p,y_b)\}\bigr)\\
\min_{x_p}\quad&
L_{\mathrm{attack}}\bigl(\theta^*(x_p);x_t,y_{\mathrm{attack}}\bigr)
\end{aligned}
$$

内层模拟模型如何在污染数据上训练，外层优化污染样本，使训练后的模型在目标上产生攻击者希望的结果。这比固定特征提取器昂贵得多。

#### 17.4.9 一个二维直觉例子

假设表示空间只有两个维度：

```text
Class 0 表示主要在左侧
Class 1 表示主要在右侧
x_t 位于右侧但靠近边界
```

攻击者从 Class 0 选择基础样本 $x_b$，构造标签仍为 Class 0 的 $x_p$，却让 $f(x_p)$ 出现在 $x_t$ 附近。线性分类器面对这条训练数据时有两个选择：

1. 把 $x_p$ 判错，承担较大训练损失；
2. 移动边界，把 $x_p$ 所在区域纳入 Class 0。

训练优化通常会推动第二种变化。如果 $x_t$ 原本就靠近边界，它可能随之被一起划入 Class 0。目标越远离边界，通常需要更多或更强的污染样本。

#### 17.4.10 它与相邻攻击的区别

| 攻击 | 修改对象 | 攻击发生阶段 | 典型目标 |
|---|---|---|---|
| Label Flipping | 训练标签 | 训练前/训练中 | 破坏或定向移动边界 |
| Clean Label Attack | 训练输入，标签保持合理 | 训练前/训练中 | 让指定目标在训练后误分类 |
| Adversarial Example | 推理时输入 | 推理阶段 | 让当前输入立即误分类 |
| Backdoor | 训练数据中的触发器关联 | 训练与推理 | 遇到 trigger 时产生指定行为 |

Clean Label 的核心判定不是“代码里有没有改标签”，而是：

- 污染样本的标签是否仍与人类可见语义一致；
- 攻击是否通过训练过程影响未来模型；
- 目标误分类是否能在独立干净测试目标上复现；
- 攻击是否依赖特定模型、冻结层或数据处理假设。

#### 17.4.11 防御与实验检查

仅检查标签不足以发现这种攻击。还需要：

- 记录数据来源、上传者、版本和转换过程；
- 检查原始输入和派生特征是否异常；
- 在表示空间执行局部近邻、一致性和聚类检查；
- 比较多个模型或特征提取器对可疑样本的表示；
- 对高损失、高影响和边界附近样本执行复核；
- 做样本移除消融，观察删除可疑点后目标行为是否恢复；
- 使用独立干净测试集和多个随机种子验证；
- 同时报告目标攻击成功率与正常任务性能。

这说明“标签正确、肉眼正常”不代表训练数据对模型是安全的。

### 17.5 Backdoor / Trojan

后门让模型在正常输入上表现正常，但遇到特定 trigger 时产生攻击者指定行为。总体测试集很容易漏掉，因此必须有 trigger 专项测试、来源审计和模型供应链验证。

### 17.6 在线投毒

若用户反馈、点击或模型输出会自动进入再训练，攻击者可以通过正常业务入口逐步污染未来模型。防御需要反馈隔离、贡献上限、异常检测、延迟发布和人工/规则门禁。

## 18. LLM 应用的主要安全风险

### 18.1 Direct Prompt Injection

攻击者直接在用户输入中要求模型忽略原任务、泄露信息或调用工具。根因不是一句特定 payload，而是把概率模型的指令遵循当作授权机制。

### 18.2 Indirect Prompt Injection

恶意指令藏在网页、邮件、PDF、CSV、RAG 文档或工具结果中，被应用带入上下文。完整链路是：

```text
攻击者控制外部内容
→ 系统读取内容
→ 内容进入模型上下文
→ 模型把数据误当指令
→ 输出或工具调用受影响
```

### 18.3 Jailbreak

通过角色扮演、虚构场景、编码、拆分、多轮或对抗后缀等方式绕过模型安全策略。拒绝一条直接请求不能证明所有变体安全。

### 18.4 Sensitive Information Disclosure 与 Exfiltration

泄露可能来自训练记忆、Prompt、RAG、工具结果、日志或跨用户缓存。Exfiltration 强调数据真正离开信任边界，例如模型生成带秘密查询参数的外部图片 URL，前端自动加载后把秘密发往攻击者服务器。

关键控制是数据最小化、对象级权限、输出净化、外连限制和浏览器 CSP，而不只是要求模型“不要泄露”。

### 18.5 Improper Output Handling

模型输出是不可信数据。若直接送入下游解释器，可能形成：

- HTML/Markdown 渲染 → XSS 或自动外连；
- SQL 执行 → SQL 注入或越权查询；
- shell/代码解释器 → Command/Code Injection；
- `eval/exec` → 任意代码执行；
- 工具参数 → SSRF、路径穿越或业务越权。

正确做法是结构化输出、严格 schema、参数化查询、安全 API、上下文编码和沙箱。

### 18.6 Excessive Agency

模型拥有过大权限、过多工具或无需确认的执行能力。解决方案在权限架构，而不只在 Prompt。

### 18.7 System Prompt Leakage

System Prompt 可能包含业务逻辑、内部路径或秘密。应假定行为规则可能被推断或泄露，绝不能把 API key 等秘密放进 Prompt。安全性不能依赖攻击者不知道规则。

### 18.8 Vector and Embedding Weaknesses

包括知识库投毒、跨租户检索、恶意 chunk 高排名、敏感文档召回和向量库权限错误。Embedding 相似度不提供可信度或授权语义。

### 18.9 Misinformation、Hallucination 与 Abuse

- Hallucination：模型无意生成不受证据支持的内容。
- Misinformation：错误信息风险，可来自幻觉或人为滥用。
- Abuse：攻击者有意利用模型规模化生成诈骗、操纵、仇恨或恶意内容。

防御既需要内容层，也需要账户、速率、分发、审计和人工处置。

### 18.10 Unbounded Consumption

攻击者通过超长输入、高并发、循环 Agent、昂贵工具或反复重试消耗 token、算力和费用。应限制输入/输出、并发、步数、工具预算、总时间和用户配额。

### 18.11 Supply Chain

模型、数据集、Python 包、容器、Prompt 模板、LoRA adapter、模型序列化文件和第三方 API 都属于供应链。尤其不能把不可信 Pickle 模型文件当作纯数据安全加载。

### 18.12 OWASP LLM Top 10 与 Google SAIF

两者用途不同：

- OWASP LLM Top 10：面向 LLM 应用的主要风险分类，适合漏洞识别、测试清单和整改沟通。
- Google SAIF（Secure AI Framework）：面向组织和生命周期的安全框架，强调供应链、检测响应、控制自动化、风险适配和治理。

本库覆盖的主要 OWASP 2025 映射为：

| 风险 | 本库对应主题 |
|---|---|
| LLM01 Prompt Injection | 直接/间接注入、越狱、RAG 注入 |
| LLM02 Sensitive Information Disclosure | 数据泄露与 Exfiltration |
| LLM03 Supply Chain | 模型、数据、依赖和序列化文件安全 |
| LLM04 Data and Model Poisoning | 标签翻转、定向投毒、Clean Label、后门 |
| LLM05 Improper Output Handling | XSS、SQL、Code Injection |
| LLM06 Excessive Agency | Function Calling、Agent 工具越权 |
| LLM07 System Prompt Leakage | 系统规则与隐藏上下文泄露 |
| LLM08 Vector and Embedding Weaknesses | RAG、向量库和跨租户检索 |
| LLM09 Misinformation | 幻觉、错误引用、滥用生成 |
| LLM10 Unbounded Consumption | Token、并发、Agent 循环与费用消耗 |

框架是检查视角，不是安全证明。真实评估仍需威胁模型、可复现证据、业务影响、确定性控制和修复后复测。

## 19. 从现有安全项目理解前沿研究方法

### 19.1 Authorization-Matched 数据

为了避免检测器只记住工具名和参数，需要构造配对：候选 action 完全相同，但一条来自可信用户授权，另一条来自不可信外部诱导。真正变化的应是授权关系。

这类设计在检验：

> detector 识别的是“未授权动作”，还是仅识别了“攻击文本长得像攻击”。

### 19.2 Linear Probe

冻结 LLM，提取 hidden state $h$，训练简单分类器：

$$
\hat y=\sigma(\mathbf{w}^T\mathbf{h}+b)
$$

线性 probe 成功说明相关信息可被线性读取，但不证明该信息是模型决策的因果原因，也不证明其在新工具、新语言和新攻击模板上泛化。

### 19.3 Activation Delta

比较模型读外部数据前后的表示：

$$
\Delta h=h(\text{goal + external data})-h(\text{goal})
$$

它可能捕捉任务漂移，但也可能捕捉长度、语言和格式变化，因此必须有匹配对照和消融。

### 19.4 OOD 与 Grouped Split

OOD（Out-of-Distribution）测试模型面对训练分布外数据的能力。安全项目应按攻击模板、工具族、任务、语言、suite 或模型分组切分，禁止同任务改写跨 train/test。

随机 sample split 通常只回答“能否识别相似样本”，不能充分回答“能否防御新攻击”。

### 19.5 Oracle 与 Judge

- Oracle：用于确定真值的可靠机制，例如工具执行后的数据库状态。
- LLM Judge：另一个模型对文本结果评分。

Agent 安全优先使用环境状态 oracle；不得把未经校准、可能受注入影响的 LLM judge 当作唯一真值。

### 19.6 Ablation（消融实验）

逐个移除输入特征、模型组件或信号，观察性能变化。例如去掉 tool name、长度、hidden state 或 provenance。消融用于判断增益来自哪里，并发现捷径。

## 20. 常见误区纠正

1. **“LLM 是搜索引擎。”** 不是。原生 LLM 从参数生成；只有接入搜索/RAG 时才查外部资料。
2. **“参数越多一定越好。”** 不一定。数据、训练、推理预算、任务匹配和评估同样重要。
3. **“上下文越长就记得越好。”** 不一定。位置、噪声、检索质量和注意力分配都会影响利用率。
4. **“Temperature 设为 0 就绝对确定。”** 不保证跨后端、版本和硬件完全一致。
5. **“模型概率就是事实置信度。”** 不是，它首先是语言分布概率。
6. **“RAG 能消除幻觉。”** 不能，只能在检索与使用正确时降低部分风险。
7. **“System Prompt 是权限边界。”** 不是，权限必须由应用代码和基础设施实施。
8. **“模型输出的是 JSON，所以安全。”** JSON 只提供结构，值仍需验证与鉴权。
9. **“总体 Accuracy 高，攻击就失败。”** 目标类、分群、概率校准和后门触发行为可能已恶化。
10. **“标签没错就是干净数据。”** Clean Label Attack 正说明特征和表示也可被攻击。
11. **“高 AUROC 就能部署。”** 仍要检查低 FPR 工作点、校准、OOD、延迟和 utility。
12. **“注意力权重就是模型解释。”** 不能直接等同，需因果干预和多种证据支持。
13. **“Fine-tuning 会自动记住所有新事实。”** 它更适合改变行为和任务能力，精确动态事实通常更适合 RAG。
14. **“模型拒绝危险请求就表示 Agent 安全。”** 工具权限、参数校验和外部数据注入仍可能失效。

## 21. 一条推荐的零基础学习路线

### 阶段一：概念与最小数学闭环

目标：能解释样本、特征、标签、参数、损失、梯度、概率、向量。

实践：手算一次 Logistic Regression 的 logit、Sigmoid、交叉熵和混淆矩阵。

### 阶段二：神经网络与 Transformer

目标：能画出 `token → embedding → attention/MLP blocks → logits → softmax`。

实践：用小矩阵手算一次点积注意力，确认 mask 和 Softmax 的作用。

### 阶段三：训练与推理

目标：区分预训练、SFT、偏好对齐、Fine-tuning、LoRA、量化与解码。

实践：比较不同 temperature/top-p 的多次输出，记录复现性。

### 阶段四：RAG 与 Agent

目标：能画出数据流、信任边界和权限边界。

实践：构建只读本地 RAG；再实现一个只允许固定 schema 的无害工具调用。

### 阶段五：AI 安全

目标：从攻击链而不是 payload 清单理解 Prompt Injection、输出处理、投毒和 Agent 越权。

实践：所有测试使用授权环境、无害 marker、干净对照、可重复记录和修复后复测。

### 阶段六：研究项目

目标：能设计 authorization-matched 数据、grouped OOD split、强 baseline、bootstrap CI 和系统级 utility 评估。

实践：先复现小型 baseline，再验证新信号是否真的提供独立增益。

## 22. 最小必记公式表

| 主题 | 公式 | 作用 |
|---|---|---|
| 线性变换 | $z=\mathbf{w}^T\mathbf{x}+b$ | 特征加权打分 |
| Sigmoid | $\sigma(z)=1/(1+e^{-z})$ | 二分类概率 |
| Softmax | $p_i=e^{z_i}/\sum_je^{z_j}$ | 多类别/token 概率 |
| 梯度下降 | $\theta\leftarrow\theta-\eta\nabla L$ | 更新模型参数 |
| 交叉熵 | $-\sum_i y_i\log p_i$ | 惩罚正确类低概率 |
| 余弦相似度 | $(a\cdot b)/(\|a\|\|b\|)$ | 比较向量方向 |
| Attention | $softmax(QK^T/\sqrt{d_k})V$ | 动态聚合上下文 |
| 语言模型损失 | $-\sum_t\log P(x_t\mid x_{<t})$ | 训练下一个 token 预测 |
| 困惑度 | $PPL=e^L$ | 衡量 token 预测难度 |
| Precision | $TP/(TP+FP)$ | 预测为正有多准 |
| Recall | $TP/(TP+FN)$ | 真实正类找回多少 |
| F1 | $2PR/(P+R)$ | Precision/Recall 调和平均 |
| Brier | $N^{-1}\sum_i(p_i-y_i)^2$ | 概率预测质量 |

## 24. 最终总结

1. LLM 是用 Transformer 构建、通过下一个 token 预测训练出来的概率模型。
2. 文本先被切成 token，再变为 embedding；多层 Attention 和 MLP 产生 hidden state，最终生成词表 logits。
3. Softmax 把 logits 变成概率，解码策略决定怎样选下一个 token。
4. 训练依靠交叉熵、反向传播和梯度优化；数据质量会直接改变模型学到的参数和行为。
5. 预训练学习通用模式，SFT 学习指令行为，偏好对齐改善有用性和安全性，Fine-tuning 适配任务，RAG 临时提供外部知识。
6. RAG 的相似度不是可信度或权限；Agent 的模型输出不是最终授权。
7. System Prompt 是软约束，不是不可绕过的安全边界。权限、网络、文件和高风险动作必须由确定性系统控制。
8. 幻觉来源于语言预测与事实验证目标不一致；模型自报置信度或多次一致不能替代证据。
9. AI 安全必须覆盖模型、Prompt、数据、检索、工具、权限、输出处理和供应链。
10. 科学评估要有干净基线、独立测试集、分类别与分群指标、多随机种子、置信区间、OOD 测试和 utility 权衡。

理解这条主线后，本库中的提示词注入、数据外泄、XSS/SQL/Code Injection、标签翻转、Clean Label Attack、Agent 授权门与 hidden-state detector 就不再是零散漏洞，而是同一个系统问题的不同位置：

> 不可信数据如何影响概率模型，以及模型产生的概率性输出如何被安全地接入真实世界的确定性权限与执行系统。
