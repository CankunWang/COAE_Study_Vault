# AI 安全测试矩阵

| 测试面 | 建议基线 | 关键证据 | 主要判定 | 笔记入口 |
|---|---|---|---|---|
| 数据完整性 | 干净数据版本与标签分布 | 数据哈希、来源、污染 manifest | 攻击样本是否改变目标行为 | [AI 数据攻击](../AI数据攻击/_index.md) |
| 模型制品 | 来源、摘要、签名和加载器 | 文件摘要、静态检查、隔离日志 | 不可信制品能否进入加载阶段 | [供应链安全](../AI模型供应链安全/_index.md) |
| 推理鲁棒性 | 干净准确率与成本分布 | 逐样本输出、延迟、资源指标 | 扰动是否导致定向错误或成本放大 | [应用与系统安全](../AI应用与系统安全/_index.md) |
| Prompt 与外部内容 | 正常任务集和信任边界 | Prompt 版本、外部来源、Canary | 不可信内容能否改变高权限行为 | [LLM 应用测试](../LLM应用测试与提示词攻击/_index.md) |
| Tool / MCP | 固定工具集与身份权限 | Tool 参数、身份、授权和下游日志 | 模型建议是否绕过服务端授权 | [MCP 与集成](../AI应用与系统安全/_index.md) |
| LLM 输出处理 | 纯文本安全基线 | 原始输出、渲染结果、执行器日志 | 输出是否进入 SQL、Shell、DOM 或动态调用 | [LLM 输出安全](../LLM应用测试与提示词攻击/_index.md) |
| 数据保留与隔离 | 数据分类和保留策略 | 存储、日志、备份和删除证据 | 是否存在过度收集、跨租户读取或残留 | [数据处理与存储](<../AI应用与系统安全/过度数据处理与不安全存储Excessive Data Handling and Insecure Storage测试与笔记.md>) |

## 通用执行顺序

1. 确认授权范围、测试身份、停止条件和清理方式。
2. 建立干净基线，并锁定模型、数据、代码和配置版本。
3. 使用最小、合成、可识别的 Canary 或 Marker 执行测试。
4. 同时收集模型输出和服务端真实执行证据。
5. 按对象级授权、动作级授权、数据隔离和副作用判定风险。
6. 修复后使用相同基线和证据口径复测。
