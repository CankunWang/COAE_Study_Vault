## 字段规则

| 字段 | 要求 | 说明 |
|---|---|---|
| `id` | 必填且唯一 | 稳定标识，文件改名后不修改 |
| `title` | 必填 | 与正文 H1 保持一致 |
| `aliases` | 必填，可为空数组 | 英文名、缩写或旧名称 |
| `domain` | 必填，数组 | 内容笔记使用现有一级主题目录名称；仓库级索引、模板和规范使用 `vault` |
| `note_type` | 必填，数组 | 表示文档承担的角色 |
| `attack_phase` | 必填，数组 | 表示攻击或控制所在阶段 |
| `status` | 必填 | 表示内容成熟度，而不是完成百分比 |
| `tags` | 必填，数组 | 只保留少量横向标签 |
| `updated` | 必填 | 内容发生实质变化时更新 |

## 合法值

`note_type`：

- `concept`：概念、原理和威胁模型。
- `lab`：实验、靶场、案例和代码审计。
- `checklist`：测试步骤、审计清单和判定口径。
- `cheatsheet`：速查表和高密度复习材料。
- `guide`：方法、技巧和操作指南。
- `index`：索引、路线和知识地图。
- `template`：可复用模板。
- `standard`：仓库规范。

`attack_phase`：

- `foundation`、`governance`、`data`、`training`、`artifact`、`deployment`、`inference`、`agent`、`operations`。

`status`：

- `draft`：内容可用，但尚未完成系统复核。
- `reviewed`：已完成结构与技术内容复核。
- `validated`：关键实验或结论已有可复核证据。
- `deprecated`：保留用于历史追踪，不再作为当前结论。

## 文档拆分规则

出现下列任意两项时，应评估拆分：

- 超过约 1200 行；
- 同时包含概念、完整实验、逐行代码审计和复习卡片；
- 正文中多次出现“当前总结”“更新后的进度”；
- 某个补充案例已经属于另一个安全领域；
- 通用模板占据较大篇幅并在多篇笔记中重复。

拆分后保留一个概览页，负责解释阅读顺序并链接到实验、清单和案例页。

## Markdown 统一格式

### 标题

- 每篇文档只保留一个 H1，且必须与 Front Matter 的 `title` 完全一致。
- H2 表示主要章节，H3 表示章节内子主题；不要从 H2 直接跳到 H4。
- 编号章节统一写成 `## 1. 标题`、`### 1.1 标题`。
- 标题前后各保留一个空行，不在标题末尾添加句号。

### 代码、公式与表格

- 围栏代码块必须标注语言，例如 `python`、`powershell`、`bash`、`json`、`yaml` 或 `text`。
- 仅用于说明流程、伪代码和终端输出的代码块使用 `text`。
- 标记为 `python` 的代码块必须是语法完整、可单独复制的代码；只有 `if ...:`、函数签名或切片表达式等逐行讲解残片必须标为 `text`。
- 考试代码按“算法、输入适配、输出编码、验证、提交”拆块；算法函数不得直接读取固定 URL 或 Challenge JSON。
- 临时靶机地址、动态 Flag 和单题完整 solver 不进入复用代码库；接口路径与字段集中写成带 `TODO` 的适配常量。
- 行内变量、函数名、路径和命令使用反引号；独立公式使用 `$$...$$`。
- Markdown 表格保留表头分隔行，单元格内容尽量简短；复杂解释放到表格之后。

### 链接与导航

- 仓库内部使用相对 Markdown 链接，不写本机绝对路径。
- 文件名含空格时用尖括号包住链接目标。
- 新内容笔记必须加入所属领域 `_index.md`；跨阶段主题还应加入 `_索引` 下的路线或生命周期索引。
- 可执行复用代码集中放在 `_工具`，知识笔记只保留必要片段并链接到完整文件。

### 文件格式

- Markdown 文件使用 UTF-8、无尾随空格，并以一个换行符结束。
- Front Matter 字段顺序遵循本规范示例。
- 只有内容发生实质修改时才更新 `updated`，格式审计也视为一次实质维护。
