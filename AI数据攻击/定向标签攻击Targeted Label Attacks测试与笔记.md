# 定向标签攻击（Targeted Label Attacks）原理与安全测试笔记

> 适用范围：AI/ML 数据安全学习、训练管线威胁建模、授权红队测试和上线前安全评估。测试必须使用隔离环境、合成标签、测试账户和可恢复的模型版本，不得污染生产训练集或真实反馈回路。

> 相关笔记：[[AI数据攻击总结详解与测试笔记]]、[[标签翻转Label Flipping攻击测试与笔记]]。

## 使用方式：定向标签攻击快速入口

```text
选择 source 与 target → 建自然混淆基线
→ 只翻转选中 source 标签 → 公平重训
→ 测 source→target 方向 → 分组与消融复测
```

```text
[ ] source、target、目标样本/群体定义明确
[ ] source != target
[ ] 污染率以 source 类为分母并记录实际数量
[ ] 测试集和目标回归集保持干净
[ ] 保存样本 ID、原标签、新标签和来源
```

核心指标：

$$
TMR_{s\to t}
=
\frac{\#\{y=s\land\hat y=t\}}
{\#\{y=s\}}
$$

同时报告自然与污染后的 `source→target rate`、Source Recall、Target Precision、总体指标、其他类别副作用和多 seed 结果。总体指标稳定但指定方向显著上升，才符合典型定向影响。

## 0. 一页速记

### 0.1 定义

定向标签攻击是一种具有明确目标的数据投毒攻击。攻击者只修改特定类别、群体、来源或样本的训练标签，使模型按照攻击者预期的方向产生误判。

```text
选定目标类别或目标群体
    ↓
将部分真实标签改为攻击者指定类别
    ↓
模型学习错误的定向关联
    ↓
特定类别 Recall 下降或定向误判率上升
```

例如：

- 把部分恶意文件标签改为“良性”；
- 把部分欺诈交易标签改为“正常”；
- 把部分正面评论标签改为“负面”；
- 把某类疾病样本改标为其他诊断；
- 只攻击某地区、设备、客户群或数据来源。

### 0.2 与一般标签翻转的区别

| 对比项 | 一般/随机标签翻转 | 定向标签攻击 |
|---|---|---|
| 目标 | 整体降低模型质量 | 操纵特定类别或群体 |
| 样本选择 | 整个训练集随机选择 | 按类别、属性、来源或边界条件选择 |
| 翻转方向 | 经常双向或随机 | 通常单向、攻击者指定 |
| 隐蔽性 | 总体指标可能明显下降 | 总体指标可能正常，局部指标严重下降 |
| 关键指标 | Overall Accuracy、Macro F1 | 目标类 Recall、定向误判率、分群指标 |

### 0.3 最重要的测试原则

> 定向攻击不能只看总体 Accuracy。必须检查目标类别、目标群体和指定错误方向。

一个模型总体准确率为 98%，仍可能把某个关键类别中的大部分样本稳定误判为攻击者指定类别。

### 0.4 核心风险链

```text
标签写入/标注/处理权限失控
    +
攻击者能够识别目标类别
    +
训练与验证缺少标签完整性检查
    +
只使用总体指标验收模型
    =
定向偏置被训练进模型并通过上线门禁
```

## 1. 攻击原理

### 1.1 监督学习依赖标签真值

监督学习通过样本与标签对学习关系：

```text
(特征 x, 正确标签 y)
```

训练算法通常默认标签代表真值。如果攻击者保持特征不变，只把目标样本标签改为另一个类别：

```text
(x, target_class) → (x, attacker_class)
```

模型不会自动知道标签被篡改，而会尝试让预测符合错误监督信号。

### 1.2 为什么会产生定向边界偏移

对于 Logistic Regression，二元交叉熵为：

$$
L=-\frac{1}{N}\sum_{i=1}^{N}
\left[y_i\log(p_i)+(1-y_i)\log(1-p_i)\right]
$$

假设某样本的特征强烈属于 Class 1，因此 $p_i$ 接近 1。其标签若被改成 Class 0，损失会从较小的 $-\log(p_i)$ 变为很大的 $-\log(1-p_i)$。

优化器为了降低这些错误标签产生的损失，会调整权重和偏置，使决策边界向目标类别区域移动。因此，更多合法目标类样本会落到攻击者指定类别的一侧。

### 1.3 定向攻击不等于模型后门

两者可能产生相似的“特定条件下错误”，但机制不同：

| 对比项 | 定向标签攻击 | 后门攻击 |
|---|---|---|
| 触发条件 | 类别、群体或自然特征区域 | 人为植入的特殊触发模式 |
| 攻击数据 | 目标类标签被改写 | 常同时植入触发器和攻击标签 |
| 生产表现 | 某类样本普遍更易误判 | 通常只在触发器出现时激活 |
| 测试重点 | 分类别和分群指标 | 触发器专项测试与攻击成功率 |

### 1.4 攻击目标的不同粒度

- 类别级：让所有 Class A 更容易被判为 Class B；
- 群体级：只影响某地区、设备、年龄段或业务渠道；
- 来源级：只影响某供应商或某采集系统的数据；
- 样本级：让少量特定对象被错误分类；
- 时间级：只污染某次再训练窗口；
- 边界级：优先修改最能推动决策边界的样本。

目标越精细，攻击可能越隐蔽，测试也越不能只依赖总体统计。

## 2. 现实攻击入口

### 2.1 标注平台

攻击者可能通过：

- 窃取标注员账户；
- 控制外包标注人员；
- 篡改标注指南；
- 修改黄金样本或质检规则；
- 批量调用缺少授权的标签修改接口；
- 利用审计不足的管理员功能。

测试时应确认标签修改是否记录原值、新值、操作者、时间和原因。

### 2.2 数据库存储

训练标签可能存储在：

- CSV、JSON、Parquet；
- PostgreSQL 等关系数据库；
- 对象存储和数据湖；
- 特征仓库；
- 数据集版本管理平台。

攻击者获得写权限后，可以只修改目标类别的标签列，而不改变样本文件本身。

### 2.3 数据处理与标签映射逻辑

攻击者不需要直接编辑标签文件。修改处理代码同样可以实现定向翻转：

```text
if sample.source == TARGET_SOURCE:
    label = ATTACKER_CLASS
```

常见攻击对象：

- 类别编码字典；
- 标签归一化脚本；
- 规则引擎；
- 数据清洗作业；
- Airflow DAG；
- Spark 转换任务；
- Notebook 中未经审查的临时代码。

### 2.4 用户反馈与在线再训练

如果点赞、举报、点击、退款或人工纠错会被自动转成标签，攻击者可以持续制造特定方向的反馈，让目标类别逐步被映射到错误类别。

这种在线定向投毒的特点是：

- 使用正常业务入口；
- 单次行为看似合法；
- 污染跨多个训练周期积累；
- 容易被误认为自然数据漂移。

### 2.5 第三方数据和预训练资产

第三方供应商可能提供带有定向标签偏差的数据集。组织若只验证文件格式和总体质量，可能无法发现某个类别或群体被系统性错误标注。

## 3. 测试前的威胁建模

### 3.1 识别关键类别

优先关注错误成本高的类别：

- 恶意/良性；
- 欺诈/正常；
- 高风险/低风险；
- 需要治疗/无需治疗；
- 合规/违规；
- 授权/未授权。

测试必须记录攻击方向。例如“恶意→良性”和“良性→恶意”的业务影响完全不同。

### 3.2 识别攻击者可控标签路径

画出：

```text
数据源
  ↓
标签生成者或标签规则
  ↓
标签存储
  ↓
清洗与映射
  ↓
训练集构建
  ↓
模型训练和验证
```

对每个阶段询问：

- 谁可以创建标签？
- 谁可以修改标签？
- 修改是否需要审批？
- 是否保留历史版本？
- 标签能否追溯到独立证据？
- 训练任务如何选择数据版本？

### 3.3 定义安全目标

测试前明确：

- 目标类别是什么；
- 攻击者希望它变成哪个类别；
- 最大允许污染比例；
- 允许的目标类 Recall 下限；
- 允许的定向误判率上限；
- 哪些群体必须单独评估；
- 什么结果会阻止模型发布。

## 4. 授权测试流程

### 4.1 第一步：建立干净基线

使用批准的数据版本训练基线模型，并记录：

- Overall Accuracy；
- Macro、Micro、Weighted F1；
- 每个类别的 Precision、Recall、F1；
- 混淆矩阵；
- ROC-AUC、PR-AUC（适用时）；
- 预测概率和校准；
- 模型权重、版本和数据谱系；
- 各敏感群体、来源和时间窗口的指标。

没有干净基线，无法判断后续差异来自攻击还是正常训练波动。

### 4.2 第二步：构造最小定向污染

只在隔离副本中：

1. 找出目标类别索引；
2. 从目标类别中选择少量测试样本；
3. 将它们单向改为指定类别；
4. 保存翻转索引、原标签和新标签；
5. 确保特征和测试集未改变。

安全验证逻辑：

```python
assert all(original_labels[indices] == target_class)
assert all(poisoned_labels[indices] == attacker_class)
assert clean_test_labels_are_unchanged
```

测试目的不是追求最大破坏，而是找到系统何时能够检测或阻止定向污染。

### 4.3 第三步：逐级增加污染比例

可在授权环境中测试多个小比例，并记录剂量—效果关系：

```text
污染比例上升
    ↓
目标类 Recall 如何变化？
    ↓
定向误判率何时超过门限？
    ↓
数据或模型监控何时告警？
```

每个比例都应使用：

- 同一份干净测试集；
- 相同模型配置；
- 明确的随机种子；
- 独立抽样或嵌套抽样说明；
- 多次重复实验，而不是只运行一次。

### 4.4 第四步：训练污染模型

保持特征、算法、超参数和测试集不变，只替换训练标签副本。

```text
干净训练标签 → 基线模型
定向污染标签 → 污染模型
同一干净测试集 → 公平比较
```

### 4.5 第五步：验证攻击方向

必须检查攻击是否沿指定方向发生：

- 目标类别被预测为攻击类别的数量；
- 目标类 Recall 是否下降；
- 攻击类 Precision 是否出现异常变化；
- 混淆矩阵的目标单元格是否增加；
- 目标群体或来源是否出现局部退化；
- 模型概率是否向攻击类别偏移。

### 4.6 第六步：使用独立干净数据复测

使用不同时间、来源或随机批次的干净测试数据，确认攻击影响能够泛化，而不是只对训练集过拟合。

要区分：

- 同分布新样本：只更换样本；
- 分布变化测试：同时改变来源、时间或噪声；
- 对抗测试：故意选择边界和困难样本。

不要把分布变化导致的性能下降全部归因于投毒。

### 4.7 第七步：验证检测与阻断控制

观察以下控制是否触发：

- 标签修改审计告警；
- 类别比例异常；
- 单向标签迁移异常；
- 高损失样本检测；
- 近邻标签冲突；
- 数据版本完整性校验；
- 分类别模型门禁；
- 自动部署阻断；
- 人工复核和回滚流程。

## 5. 实际测试应检测什么

### 5.1 标签层检测

| 检测项 | 目的 |
|---|---|
| 标签值变化历史 | 发现原标签被批量改写 |
| 单向迁移矩阵 | 发现大量 A→B，但很少 B→A |
| 类别比例变化 | 发现目标类数量异常减少 |
| 修改主体聚合 | 发现同一账户或任务集中改标 |
| 时间窗口异常 | 发现短期或周期性投毒 |
| 来源分组 | 发现某供应商或渠道独有的偏差 |
| 近重复冲突 | 相似样本却拥有相反标签 |
| 独立真值核验 | 与人工、规则或权威记录比对 |

### 5.2 数据分布检测

- 目标类别样本数量是否异常下降；
- 攻击类别数量是否同步上升；
- 类别条件下的特征分布是否突然变化；
- 某一群体是否出现异常标签比例；
- 标签变化是否集中在决策边界附近；
- 数据源、设备、地区、标注员与标签是否出现异常关联。

### 5.3 模型指标检测

定向攻击至少应检查：

```text
目标类别 Recall
目标类别 F1
目标类别到指定攻击类别的误判率
每类混淆矩阵
Macro F1
分群/分来源指标
目标类别预测概率分布
模型校准与 Log Loss
```

### 5.4 定向误判率

目标类 A 被预测为攻击类 B 的比例：

$$
TMR_{A\rightarrow B}
=\frac{\#(y=A\land\hat{y}=B)}{\#(y=A)}
$$

二分类中若目标是 Class 1→0：

$$
TMR_{1\rightarrow0}=\frac{FN}{TP+FN}=1-Recall_1
$$

多分类中不能只使用二分类的 TN/FP/FN/TP，需要直接读取混淆矩阵的 `[A, B]` 单元格。

### 5.5 分群检测

攻击可能只影响某个子群：

```text
总体 Class 1 Recall：正常
某供应商的 Class 1 Recall：严重下降
```

因此要按以下维度拆分：

- 数据来源；
- 地区；
- 设备；
- 用户群体；
- 时间；
- 模型版本；
- 标注员或标注任务；
- 业务产品线。

### 5.6 高损失与模型分歧

被翻转样本通常表现为“特征像 A，标签却是 B”，可能产生：

- 较高训练损失；
- 与邻近样本标签冲突；
- 与独立模型预测冲突；
- 与业务规则或人工判断冲突；
- 在嵌入空间中落入另一类别聚类。

但高损失也可能来自合法困难样本，不能自动删除，必须进入复核流程。

## 6. 测试用例设计

### 6.1 基础用例

| 编号 | 测试 | 预期安全行为 |
|---|---|---|
| TLA-01 | 低权限账户修改标签 | 写入被拒绝并记录 |
| TLA-02 | 批量修改同一类别 | 触发数量或速率告警 |
| TLA-03 | 大量 A→B 单向迁移 | 触发迁移矩阵异常 |
| TLA-04 | 修改处理脚本中的标签映射 | 代码审查或签名校验失败 |
| TLA-05 | 替换训练数据版本 | 数据摘要或批准状态不匹配 |
| TLA-06 | 小比例目标类污染 | 分类别评估发现 Recall 变化 |
| TLA-07 | 总体 Accuracy 仍合格 | 目标类门禁仍能阻止发布 |
| TLA-08 | 某来源局部污染 | 分来源指标发现异常 |
| TLA-09 | 在线反馈定向操纵 | 贡献限制、信誉或异常检测生效 |
| TLA-10 | 修复后重训 | 指标恢复且污染样本可追踪清除 |

### 6.2 攻击方向覆盖

对每一对高风险类别分别测试：

```text
恶意 → 良性
良性 → 恶意
欺诈 → 正常
正常 → 欺诈
高风险 → 低风险
低风险 → 高风险
```

两个方向的影响、检测难度和风险等级可能不同。

### 6.3 污染位置覆盖

同一种定向标签攻击可以从不同位置进入：

- 数据接入时标签已经错误；
- 入库后标签列被修改；
- 处理脚本运行时被重映射；
- 人工复核结果被覆盖；
- 用户反馈被错误转换为标签；
- 数据集版本或 manifest 指向错误标签文件。

测试不能只覆盖一个 CSV 文件。

## 7. 证据与验证要求

### 7.1 数据证据

保存：

- 干净数据版本和哈希；
- 污染数据副本和哈希；
- 翻转样本的唯一 ID；
- 原标签与新标签；
- 目标类总数和实际污染比例；
- 标签来源、修改主体和时间；
- 数据处理代码版本。

### 7.2 模型证据

保存：

- 基线与污染模型版本；
- 模型训练参数；
- 完整混淆矩阵；
- 每类别和每群体指标；
- 目标定向误判率；
- 模型概率变化；
- 训练和测试数据谱系；
- 发布门禁是否触发。

### 7.3 不能作为充分证据的结果

- 训练作业成功结束；
- 单个 Accuracy 分数；
- 一张决策边界图；
- 一个随机种子的单次结果；
- 训练集上的高准确率；
- “看起来像被投毒”的几个样本；
- 没有干净基线的性能下降。

## 8. 风险判定

### 8.1 低风险或无有效影响

- 标签修改被权限控制拒绝；
- 异常在进入训练集前被隔离；
- 小比例测试未产生超出随机波动的目标指标变化；
- 模型发布门禁正确阻止异常版本；
- 只影响无业务后果的测试类别。

### 8.2 中风险

- 可污染少量目标标签；
- 目标类别指标出现可测下降；
- 需要较高权限或大量样本；
- 有告警、人工门禁和可靠回滚；
- 生产影响范围有限。

### 8.3 高风险

- 普通用户输入或反馈可进入再训练；
- 较少污染即可显著降低关键类别 Recall；
- 总体指标仍通过，现有门禁无法发现；
- 攻击影响跨模型版本持续存在；
- 目标类别涉及欺诈、安全、医疗或关键业务决策。

### 8.4 严重风险

- 攻击者可稳定控制关键类别的错误方向；
- 可让恶意对象被系统识别为良性；
- 攻击跨租户、群体或高敏感业务范围；
- 自动再训练和自动部署无需人工批准；
- 无法追踪污染来源或恢复干净模型；
- 模型输出直接触发高影响自动化动作。

---

## 9. 防御措施

### 9.1 标签完整性

- 标签采用不可变版本；
- 记录原值、新值、修改者和原因；
- 批量修改需要审批；
- 关键标签需要独立证据或双人复核；
- 对标签文件、数据库快照和 manifest 做哈希校验；
- 训练只能使用批准的数据版本。

### 9.2 最小权限与职责分离

- 数据采集账户不能修改历史标签；
- 标注人员不能批准自己的批量变更；
- 训练任务只读批准数据；
- 数据管理员不能单独发布模型；
- 部署系统不能回写训练标签；
- 在线反馈不能直接成为高可信真值。

### 9.3 数据质量门禁

- 类别比例上下限；
- 单向标签迁移阈值；
- 近重复样本标签一致性；
- 高损失样本抽样复核；
- 来源和群体分布检查；
- 新旧数据版本差异报告；
- 标签规则单元测试和黄金样本。

### 9.4 模型发布门禁

发布不能只依赖 Overall Accuracy。至少设置：

```text
每个关键类别 Recall 下限
每个关键类别 F1 下限
目标方向误判率上限
分群性能下降上限
模型概率/校准变化上限
与最后已知安全模型的回归阈值
```

### 9.5 在线再训练控制

- 用户反馈先进入低信任区；
- 限制单一账号、设备和来源的贡献；
- 检测协同行为和慢速累积；
- 延迟聚合，避免即时吸收；
- 再训练模型必须离线验证；
- 禁止未经门禁自动部署；
- 保留反馈来源以支持清除和重训。

## 10. 修复后复测

```text
1. 确认标签写权限已最小化，并测试越权写入被拒绝。
2. 重放单向 A→B 批量修改，确认审计和告警生效。
3. 验证数据版本、哈希和批准状态不可绕过。
4. 对处理代码中的标签映射执行黄金样本测试。
5. 使用隔离数据重放已确认的最小定向污染。
6. 检查目标类 Recall、定向误判率和分群门禁。
7. 确认异常模型不能进入自动部署。
8. 演练定位污染样本、恢复标签和重新训练。
9. 在独立干净数据上确认模型指标恢复。
10. 检查事件日志能否完整还原攻击入口和影响范围。
```

## 12. 常见误区

### 12.1 “总体准确率很高，所以没有定向攻击”

目标类别可能占比较小，严重退化会被其他类别的高准确率稀释。

### 12.2 “Precision 很高，所以目标类表现很好”

模型可能极少预测目标类别，导致 Precision 高但 Recall 很低。必须结合混淆矩阵判断。

### 12.3 “标签文件没变，所以标签没有被攻击”

处理脚本、类别映射或反馈转换逻辑也能在运行时生成错误标签。

### 12.4 “随机翻转测试能覆盖定向攻击”

随机翻转主要测试总体鲁棒性，无法充分模拟攻击者只操纵关键类别或群体的行为。

### 12.5 “污染比例按整个数据集计算”

定向攻击比例通常以目标类别数量为分母，测试报告必须明确分母。

### 12.6 “模型训练成功就是攻击成功”

训练成功只说明模型完成拟合。必须证明指定方向的误判显著增加。

### 12.7 “一次实验就能确定安全阈值”

结果受随机种子、样本位置、模型和数据分布影响。应进行多次重复和置信区间分析。

## 13. 记忆卡片

### Q1：定向标签攻击是什么？

选择特定类别、群体或样本，将其训练标签改为攻击者指定类别，使模型产生可预测的定向误判。

### Q2：它与随机标签翻转最重要的区别是什么？

随机翻转关注整体退化；定向攻击关注特定类别和指定错误方向。

### Q3：测试时为什么不能只看 Accuracy？

目标类别的严重退化可能被大量正常类别掩盖，整体 Accuracy 仍然很高。

### Q4：最重要的检测指标是什么？

目标类 Recall、目标类到指定攻击类的误判率、混淆矩阵目标单元格和分群指标。

### Q5：定向误判率如何计算？

目标类 A 被预测为攻击类 B 的数量，除以所有真实 A 样本数量。

### Q6：标签攻击只能发生在标签文件中吗？

不能。它还可能发生在标注平台、数据库、处理代码、类别映射、第三方数据和在线反馈中。

### Q7：为什么需要干净基线和干净测试集？

基线用于判断正常波动，干净测试集用于衡量模型面对真实标签时的定向退化。

### Q8：什么控制最关键？

端到端标签谱系、最小权限、不可变版本、单向迁移检测、分类别模型门禁以及可恢复的重训练流程。

---

## 14. 最终总结

定向标签攻击的危险不在于让模型普遍“变笨”，而在于让模型对攻击者选定的类别或群体稳定地产生特定方向的错误。

实战评估应始终围绕以下问题：

1. 攻击者能从哪个标签路径进入？
2. 哪些关键类别和群体最值得攻击？
3. 少量定向污染能否绕过总体指标门禁？
4. 目标类 Recall 和指定方向误判率如何变化？
5. 标签、数据处理和模型监控能否及时发现异常？
6. 异常模型能否被阻止部署？
7. 能否定位污染样本、恢复标签并重训干净模型？

核心原则：

```text
不要只问“模型总体准不准”。
还要问“它对哪个类别错、向哪个方向错、为什么会这样错”。
```
