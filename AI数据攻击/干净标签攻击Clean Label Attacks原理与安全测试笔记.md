# 干净标签攻击（Clean Label Attacks）原理与安全测试笔记

> 适用范围：AI/ML 数据投毒学习、训练管线威胁建模、授权红队测试和上线前安全评估。测试必须在隔离数据副本和可恢复模型上进行，不得修改生产特征、真实样本或在线再训练数据。

> 相关笔记：[[AI数据攻击总结详解与测试笔记]]、[[标签翻转Label Flipping攻击测试与笔记]]、[[定向标签攻击Targeted Label Attacks测试与笔记]]。

## 使用方式：Clean Label 攻击快速入口

```text
选独立目标 → 找攻击类别基础样本 → 受限修改特征
→ 标签保持真实不变 → 公平重训 → 测目标翻转与副作用
```

```text
[ ] 目标来自独立测试/回归集
[ ] 攻击类别、目标类别和成功条件明确
[ ] 污染标签不变且仍有独立真值依据
[ ] 记录原始单位、标准化空间和业务约束下的扰动
[ ] 保存样本 ID、原/新特征、距离和哈希
```

核心断言：

```text
y_poisoned == y_clean
changed_feature_rows == selected_rows
目标本身未被修改
数据大小与划分符合设计
修改后样本仍真实属于原类别
```

必须结合目标预测翻转、边界/置信度变化、总体和逐类副作用、扰动预算、检测/删除消融及多 seed 结果。“代码没改标签”本身不能证明属于严格 Clean Label。

## 0. 一页速记

### 0.1 定义

干净标签攻击是一种不直接修改训练标签的数据投毒攻击。攻击者改变一个或多个训练样本的特征，使样本仍然带有看似合理或经人工确认正确的标签，但这些样本会在训练过程中推动模型改变决策边界或内部表示，最终让特定目标样本发生误分类。

```text
标签保持不变且看似正确
    +
特征被精心扰动或构造
    +
污染样本进入训练
    =
模型边界或表示空间被定向改变
```

### 0.2 与标签翻转的区别

| 对比项 | 标签翻转 | Clean Label Attack |
|---|---|---|
| 标签是否修改 | 是 | 否 |
| 主要操纵对象 | Ground Truth 标签 | 输入特征或模型表示 |
| 传统标签审计 | 较容易发现异常 | 标签审计可能完全通过 |
| 人工检查 | 可能看到标签明显错误 | 样本和标签可能看起来一致 |
| 常见目标 | 整体退化或定向类别偏置 | 特定目标样本或小范围目标误判 |
| 检测重点 | 标签历史、类别迁移、分群指标 | 特征完整性、近邻、表示空间、目标行为 |

### 0.3 制造业示例

质量检测模型根据长度、重量等特征，把零件分为：

- Class 0：Major Defect；
- Class 1：Acceptable；
- Class 2：Minor Defect。

攻击者希望某批真正合格的 Class 1 零件被拒绝为 Class 0。他选择一批仍可合理标为 Class 0 的训练样本，细微修改它们的特征，使其在模型使用的特征空间中靠近目标 Class 1 样本，同时保持标签 Class 0。

模型为了正确拟合这些“靠近 Class 1、标签却仍是 Class 0”的训练样本，会把 Class 0/1 决策边界推向目标位置，最终可能吞入目标 Class 1 样本。

### 0.4 最重要的测试原则

> 标签全部正确，不代表训练数据没有被投毒。Clean Label Attack 的测试必须验证样本来源、特征完整性、变换过程和模型表示，而不能只复核标签。

## 1. 攻击原理

### 1.1 基本对象

攻击通常涉及：

- 目标样本 $x_t$：攻击者希望在推理时被错误分类的对象；
- 基础样本 $x_b$：来自攻击者期望的错误类别；
- 污染样本 $x_p$：由基础样本经过受限扰动得到；
- 干净标签 $y_b$：污染样本仍保留基础样本的正确标签。

```text
基础样本 (x_b, y_b)
    ↓ 修改特征但保留标签
污染样本 (x_p, y_b)
    ↓ 进入训练
模型把目标 x_t 推向或判为 y_b
```

### 1.2 为什么称为 Clean Label

“Clean Label”强调标签没有被攻击者改成明显错误值。理想情况下，即使由人工或可靠标注器重新检查，样本仍会得到原标签。

例如图像攻击中：

- 基础图像在人眼看来仍属于原类别；
- 像素扰动足够小或自然；
- 标签和可见语义一致；
- 但模型的特征表示被推向目标样本。

### 1.3 决策边界移动

污染样本位于目标样本附近，却带有攻击类别标签。模型为了降低训练误差，会扩大攻击类别在该区域的覆盖范围：

```text
攻击前：目标样本位于真实类别区域
    ↓ 加入靠近目标的干净标签污染样本
攻击后：决策边界移动并包围目标样本
```

### 1.4 特征碰撞（Feature Collision）

攻击者不一定要求原始输入非常接近目标，而是让模型内部特征提取器 $f(\cdot)$ 产生相近表示：

$$
f(x_p)\approx f(x_t)
$$

同时约束污染样本在输入空间仍接近基础样本：

$$
\lVert x_p-x_b\rVert\leq\epsilon
$$

典型优化目标可抽象为：

$$
\min_{x_p}
\lVert f(x_p)-f(x_t)\rVert^2
+\beta\lVert x_p-x_b\rVert^2
$$

第一项让污染样本在模型表示中靠近目标，第二项限制它不要偏离原类别语义太远。

### 1.5 凸包与多污染点

攻击者还可能构造多个污染样本，使目标表示落入攻击类别污染样本形成的区域或凸包中。单个样本检查时每条数据都可能显得合理，但组合起来会对目标区域产生定向影响。

### 1.6 迁移学习为什么值得关注

当系统使用固定或部分冻结的预训练特征提取器，只重新训练最后的分类层时，攻击者若了解或近似该表示空间，可能更容易构造特征碰撞样本。

测试应确认：

- 特征提取器是否公开；
- 攻击者能否获得相同或相似模型；
- 微调时冻结了哪些层；
- 污染样本是否会被反复用于多个下游模型。

### 1.7 选择边界附近的目标样本

目标样本应满足三个条件：

```text
真实标签属于目标类别
    +
基线模型当前预测正确
    +
距离攻击类别/目标类别决策边界较近
```

边界附近的样本分类裕量较小，模型边界轻微移动就可能使它跨入攻击类别，因此通常比远离边界的样本更容易成为攻击目标。

对于 Class 0 和 Class 1 的线性分类分数：

$$
z_0=\mathbf{w}_0^T\mathbf{x}+b_0
$$

$$
z_1=\mathbf{w}_1^T\mathbf{x}+b_1
$$

定义分数差：

$$
f_{01}(\mathbf{x})=z_0-z_1
=(\mathbf{w}_0-\mathbf{w}_1)^T\mathbf{x}
+(b_0-b_1)
$$

若课程约定：

```text
f01(x) < 0 → 相对更偏向 Class 1
f01(x) = 0 → Class 0/1 边界
f01(x) > 0 → 相对更偏向 Class 0
```

那么从真实 Class 1 样本中寻找“最大的负数”，就是寻找仍位于 Class 1 一侧、但最接近边界的候选目标。

```python
class_1_indices = np.where(y_clean == 1)[0]
X_class_1 = X_clean[class_1_indices]

w_diff = w_0 - w_1
b_diff = b_0 - b_1

f01_values = X_class_1 @ w_diff + b_diff
correct_side = np.where(f01_values < 0)[0]

relative_target_index = correct_side[
    np.argmax(f01_values[correct_side])
]

absolute_target_index = class_1_indices[
    relative_target_index
]
```

### 1.8 多分类目标选择的额外检查

`f01(x)<0` 只证明 $z_1>z_0$，不能证明 Class 1 的分数高于所有其他类别。例如三分类中还需要确认 $z_1>z_2$。

因此必须使用模型最终预测进行 sanity check：

```python
target_prediction = baseline_model.predict(
    X_target.reshape(1, -1)
)[0]

assert y_target == 1
assert target_prediction == y_target
assert target_f01 < 0
```

若目标在攻击前已经被误判，就不能把攻击后的错误归因于投毒。

对于同一条线性边界，点到边界的几何距离为：

$$
d(\mathbf{x})=
\frac{|f_{01}(\mathbf{x})|}
{\lVert\mathbf{w}_0-\mathbf{w}_1\rVert}
$$

所有候选点使用同一条边界，分母相同，因此按 $|f_{01}|$ 排序与按几何距离排序一致。

更严格的授权测试应从独立干净测试集选择目标，而不是从训练集中选择；否则目标本身已经参与训练，评估可能混入训练记忆和数据泄漏因素。

### 1.9 选择目标附近的攻击类别邻居

选定目标 $x_t$ 后，从攻击者希望目标最终被预测成的类别中寻找最近邻。例如目标真实属于 Class 1，攻击者希望它被判为 Class 0，就只在 Class 0 训练样本中搜索。

```python
attack_class_indices = np.where(
    y_train == attack_class
)[0]

X_attack_class = X_train[
    attack_class_indices
]

nearest_neighbors.fit(X_attack_class)
distances, relative_indices = nearest_neighbors.kneighbors(
    X_target.reshape(1, -1)
)

absolute_neighbor_indices = attack_class_indices[
    relative_indices.flatten()
]
```

这里存在两层索引：最近邻返回的是攻击类别子集中的相对位置，必须通过 `attack_class_indices[...]` 映射回完整训练集索引。直接使用相对索引会修改错误样本。

选择局部邻居的原因：

- 它们靠近目标所在区域；
- 较小扰动就可能跨过当前边界；
- 对目标附近局部边界影响更直接；
- 通常比修改远处样本更隐蔽。

最近邻距离依赖特征尺度。必须先确认使用批准的 scaler，且相同预处理应用于训练、查询和复测；否则量纲最大的特征会主导距离。

### 1.10 沿边界法向量构造扰动

Class 0/1 线性边界的法向量是：

$$
\mathbf{v}_{01}=\mathbf{w}_0-\mathbf{w}_1
$$

若要把 Class 0 样本从 $f_{01}>0$ 推向 Class 1 一侧 $f_{01}<0$，可沿法向量反方向移动：

$$
\mathbf{u}_{push}
=-\frac{\mathbf{v}_{01}}
{\lVert\mathbf{v}_{01}\rVert}
$$

扰动为：

$$
\delta_i=\epsilon_i\mathbf{u}_{push}
$$

污染样本为：

$$
\mathbf{x}'_i=\mathbf{x}_i+\delta_i
$$

由于：

$$
f_{01}(\mathbf{x}_i+\epsilon_i\mathbf{u}_{push})
=f_{01}(\mathbf{x}_i)
-\epsilon_i\lVert\mathbf{v}_{01}\rVert
$$

使样本刚刚跨过边界所需的最小扰动可写成：

$$
\epsilon_i>
\frac{f_{01}(\mathbf{x}_i)}
{\lVert\mathbf{v}_{01}\rVert}
$$

实际测试可增加一个很小的安全 margin：

```python
normal_norm = np.linalg.norm(w_diff)
if normal_norm < 1e-9:
    raise ValueError("Boundary normal is too small")

unit_push = -w_diff / normal_norm
f01_original = X_neighbor @ w_diff + b_diff

if f01_original <= 0:
    raise ValueError(
        "Neighbor is not on the expected attack-class side"
    )

epsilon_required = (
    f01_original / normal_norm
    + crossing_margin
)

X_neighbor_poisoned = (
    X_neighbor
    + epsilon_required * unit_push
)
```

为所有邻居使用同一个固定 `epsilon` 便于演示，但每个点到边界的距离不同，可能出现：

- 部分点没有跨界；
- 部分点被推得过远；
- 扰动模式过于一致，容易被检测；
- 修改后标签不再符合业务真值。

逐样本计算最小扰动更适合严谨评估。

### 1.11 创建污染训练集时保持标签不变

```python
X_train_poisoned = X_train.copy()
y_train_poisoned = y_train.copy()

for index in poison_indices:
    X_train_poisoned[index] = perturbed_features[index]

# Clean Label 的核心断言
assert np.array_equal(
    y_train_poisoned,
    y_train,
)
```

数据集大小必须保持一致。若课程演示从训练集中选择目标，还要确认目标自身没有被修改：

```python
assert target_index not in poison_indices
assert X_train_poisoned.shape == X_train.shape
assert y_train_poisoned.shape == y_train.shape
```

更严格的测试应从独立测试集选择目标，此时目标本来就不在训练数组中，不应拿测试集索引与训练集索引直接比较。

只允许预期行发生特征变化：

```python
changed_rows = np.where(
    np.any(X_train_poisoned != X_train, axis=1)
)[0]

assert np.array_equal(
    np.sort(changed_rows),
    np.sort(poison_indices),
)
```

### 1.12 严格 Clean Label 判定

“代码没有修改 `y`”不是充分条件。修改后的样本还必须由独立人工、业务规则、物理真值或权威标注器确认仍合理属于原类别。

测试必须同时验证：

```text
标签数组没有变化
    +
输入扰动处于允许范围
    +
修改后业务语义仍属于原类别
    +
模型表示或边界发生攻击者希望的变化
```

若数值特征在标准化空间中修改，应执行 `inverse_transform()` 回到原始单位，检查长度、重量、金额、温度等是否仍符合物理和业务约束。

## 2. 与相邻攻击的边界

### 2.1 Clean Label 与 Dirty Label

| 类型 | 标签 | 特征 | 典型检测 |
|---|---|---|---|
| Dirty Label | 被错误修改 | 可变或不变 | 标签复核、迁移矩阵 |
| Clean Label | 保持正确或合理 | 被精心修改 | 特征异常、表示空间、来源验证 |

### 2.2 Clean Label 与对抗样本

| 对比项 | Clean Label Poisoning | Evasion/Adversarial Example |
|---|---|---|
| 发生阶段 | 训练阶段 | 推理阶段 |
| 修改对象 | 训练样本 | 生产输入 |
| 影响持续性 | 进入模型版本，可长期存在 | 通常影响单次或一批推理 |
| 主要结果 | 改变模型学习到的边界或表示 | 欺骗已经训练好的模型 |

### 2.3 Clean Label 与后门攻击

Clean Label Attack 可用于植入后门，但并非所有 Clean Label Attack 都依赖触发器。

- 目标误分类攻击：让预先选定的目标样本错误分类；
- Clean-label backdoor：污染样本标签仍正确，但包含能被模型学习的触发模式；
- 广泛类别偏移：让某个自然特征区域更容易被判为攻击类别。

### 2.4 “特征变得像另一类”是否仍算 Clean Label

这是审计时必须精确判断的问题。如果特征被修改到一个独立、可靠标注者会改变标签的程度，那么它更接近错误标签或语义冲突样本，而不再是严格意义上的 Clean Label。

因此测试报告应分别记录：

- 标签是否与人类可见语义一致；
- 标签是否与权威业务真值一致；
- 原始输入空间中扰动是否合理；
- 模型表示空间中是否出现特征碰撞。

不能只因为代码没有修改 `y` 就自动把攻击称为 Clean Label。

## 3. 现实攻击入口

### 3.1 用户上传内容

- 图片分类平台中的用户图片；
- 恶意软件检测系统中的样本提交；
- 垃圾邮件和内容审核反馈；
- 推荐系统中的商品图像和描述；
- 语音、生物识别或传感器数据。

攻击者提交的样本可能拥有合理标签，但特征经过针对性设计。

### 3.2 特征数据库或特征仓库

攻击者若能修改已提取特征，不需要改变原始数据。原图、原文本或原始业务记录仍然干净，但训练任务读取的向量已经被操纵。

### 3.3 数据处理逻辑

处理脚本可能只对目标来源或特定样本执行：

- 数值缩放偏移；
- 图像增强偏置；
- 文本特征替换；
- 嵌入向量修改；
- 选择性降维或归一化；
- 元数据到特征的错误映射。

### 3.4 第三方和公开数据集

公开贡献、爬取内容、供应商数据或预训练数据集中可能包含精心构造但标签合理的污染样本。常规标注复核可能无法发现攻击。

### 3.5 在线反馈和再训练

攻击者可以逐步提交看似合法的数据点，让目标区域在多次再训练中发生缓慢边界变化。这类攻击可能被误认为正常分布漂移。

## 4. 测试前威胁建模

### 4.1 确定攻击者知识

| 知识级别 | 攻击者可能拥有的信息 |
|---|---|
| 白盒 | 模型、权重、特征提取器、训练流程和数据 |
| 灰盒 | 模型家族、预训练骨干、输入处理和部分数据 |
| 黑盒 | 只能提交样本或查询预测 |

Clean Label Attack 经常依赖对特征空间的了解。测试时应覆盖与现实攻击者能力匹配的知识等级。

### 4.2 确定攻击者能力

- 能提交多少训练样本；
- 能否选择或影响样本标签；
- 能否观察样本是否进入训练；
- 能否修改原始特征、派生特征或二者；
- 是否知道目标样本；
- 是否能多次试验并观察新模型；
- 是否能控制某个数据源或供应商。

### 4.3 确定安全目标

- 哪些类别或具体对象是高价值目标；
- 允许的目标攻击成功率上限；
- 允许的单来源贡献比例；
- 可接受的特征扰动范围；
- 目标类别 Recall 和分群指标下限；
- 什么异常应阻止模型发布。

## 5. 授权测试流程

### 5.1 建立干净基线

记录：

- 模型版本和训练配置；
- 数据、特征提取器和 scaler 版本；
- 总体与分类别指标；
- 目标样本的真实标签、预测标签和概率；
- 目标样本在表示空间中的近邻；
- 目标样本到决策边界的距离；
- 多次训练的正常波动。

### 5.2 选择目标样本

目标样本应来自隔离测试集，并满足：

- 有明确、独立的真实标签；
- 未参与训练；
- 当前基线模型正确分类；
- 业务影响明确；
- 不包含真实敏感数据。

如果基线本来就会误判目标，就不能证明后续错误由投毒造成。

不要只选择最靠近边界的单个“最容易目标”。完整测试应覆盖：

- 边界附近的低裕量目标；
- 中等分类裕量目标；
- 远离边界的高裕量目标；
- 不同类别、群体和数据来源；
- 多个独立随机种子。

这样才能衡量攻击能力范围，而不是只证明最脆弱样本可以失败。

### 5.3 选择基础样本

基础样本通常来自攻击者希望目标最终被预测成的类别。应记录：

- 来源和原始标签；
- 与目标的输入空间距离；
- 与目标的表示空间距离；
- 是否通过人工或规则复核；
- 是否满足业务有效范围。

对每个基础样本还应记录它与目标的输入空间距离、表示空间距离，以及最近邻搜索使用的预处理和距离度量。

### 5.4 构造受限污染样本

在授权副本中修改特征，并设置严格约束：

```text
标签必须保持正确或合理
扰动不得破坏业务语义
特征值必须位于合法范围
不能污染测试集
必须保存原始样本和差异
```

从最小样本数和最小扰动开始，不以造成最大破坏为测试目标。

将污染样本数量和扰动幅度视为两个独立攻击预算：

```text
Poison Count：修改多少个训练样本
Perturbation Budget：每个样本允许修改多大
```

分别增加两个预算，观察目标攻击成功率、总体性能和检测控制何时发生变化。

### 5.5 重新训练并公平比较

```text
干净训练集 → 基线模型
干净训练集 + 少量 Clean Label 污染 → 测试模型
同一干净测试集和目标样本 → 比较
```

除污染样本外，模型、参数、随机种子和环境应尽量一致。

### 5.6 验证目标影响

检查：

- 指定目标是否被预测为攻击类别；
- 目标攻击成功率；
- 目标预测概率变化；
- 目标在表示空间中的位置变化；
- 攻击是否影响其他非目标样本；
- 总体指标是否仍然正常；
- 多个随机种子下攻击是否稳定。

### 5.7 验证检测控制

观察：

- 上传或入库时是否检测异常特征；
- 特征提取前后是否有完整性检查；
- 近邻冲突是否告警；
- 高影响样本是否进入人工复核；
- 数据来源和贡献限制是否生效；
- 模型发布门禁是否检查目标行为；
- 是否能够定位、移除污染并重训。

## 6. 实际测试应检测什么

### 6.1 原始特征完整性

- 原始文件、记录和传感器读数是否有哈希；
- 数据入库后是否可被无审计修改；
- 数值特征是否超出物理或业务范围；
- 图片、音频和文本是否包含异常微扰或隐藏内容；
- 元数据是否与主体内容矛盾；
- 同一对象的多个版本是否存在无法解释的细微变化。

### 6.2 派生特征完整性

- 特征提取器、scaler 和 tokenizer 是否版本固定；
- 相同原始输入是否可重现相同特征；
- 原始数据哈希与特征向量是否有映射记录；
- 特征缓存能否被直接覆盖；
- 不同来源是否使用了不同的隐藏处理路径；
- 归一化和降维参数是否只从批准训练集拟合。

### 6.3 近邻与局部一致性

检测：

- 样本最近邻是否大多属于另一个类别；
- 标签与局部特征簇是否冲突；
- 某些样本是否异常靠近高价值目标；
- 同一来源是否贡献大量目标附近样本；
- 污染样本删除后目标预测是否恢复。

### 6.4 表示空间检测

- 类内样本是否形成异常子簇；
- 污染样本是否位于目标表示附近；
- 特征向量是否有异常高相似度；
- 类中心、协方差和局部密度是否突变；
- 不同模型层中的异常是否一致；
- 新模型版本的表示结构是否异常移动。

### 6.5 数据来源与贡献

- 单一用户、供应商或设备贡献比例；
- 同一主体是否反复提交相似样本；
- 样本进入训练的时间是否集中；
- 是否存在协同账户或批量生成痕迹；
- 低信任来源是否与高信任数据混合；
- 第三方数据是否具备来源、签名和版本证明。

### 6.6 模型行为

```text
Targeted Attack Success Rate
目标样本预测概率变化
目标类 Recall 与 F1
攻击类 Precision/Recall
分群与分来源指标
模型校准和 Log Loss
目标附近局部鲁棒性
删除可疑样本后的影响变化
```

### 6.7 数据影响函数与消融

可在授权环境中使用影响估计、留一法或小批次消融，判断哪些训练样本对目标预测影响最大：

```text
移除可疑样本
    ↓
重新训练或近似更新
    ↓
目标预测恢复
    =
可疑样本与目标行为存在较强关联
```

关联并不自动证明恶意，需要结合来源、变更历史和内容复核。

## 8. 检测方法的局限

### 8.1 异常点删除可能伤害正常长尾

真实数据中本来就存在罕见但合法的样本。简单删除所有离群点可能：

- 降低少数群体覆盖；
- 破坏模型对罕见事件的识别；
- 放大偏见；
- 删除关键安全样本。

### 8.2 人工复核不一定看得到模型表示攻击

污染样本可能在人眼看来完全正常，但在模型特征空间中靠近目标。人工复核必须结合特征和模型证据。

### 8.3 单一异常检测器可能被适应

攻击者可以把扰动限制在统计阈值以内，或使用多个样本分散影响。应结合来源、局部密度、表示空间和模型行为。

### 8.4 不同模型的脆弱性不同

一个模型上成功的特征碰撞不一定迁移到另一个模型。反过来，使用公开预训练骨干的多个系统可能共享相似风险。

## 9. 风险判定

### 9.1 低风险

- 污染样本在进入训练前被检测或隔离；
- 需要大量明显异常样本才能产生影响；
- 目标行为变化不超过正常随机波动；
- 有可靠数据谱系、门禁和回滚。

### 9.2 中风险

- 少量样本可改变低影响目标行为；
- 攻击需要较高权限或较强白盒知识；
- 有检测但需要人工分析；
- 模型可以快速回滚和重训。

### 9.3 高风险

- 普通用户或第三方可以向训练源贡献样本；
- 标签检查全部通过但目标攻击仍成功；
- 总体指标正常，现有门禁无法发现；
- 少量污染可稳定影响关键目标；
- 攻击跨多个模型版本持续存在。

### 9.4 严重风险

- 可让恶意对象被判为良性或绕过关键安全控制；
- 影响医疗、工业安全、金融或身份认证；
- 可规模化选择多个目标；
- 自动再训练和部署缺少人工门禁；
- 无法定位污染来源或恢复干净模型。

---

## 10. 防御措施

### 10.1 数据与特征谱系

- 保存不可变原始数据；
- 记录每个特征向量对应的原始对象；
- 固定特征提取器和处理参数版本；
- 对数据与派生特征分别计算完整性摘要；
- 记录来源、时间、主体和变换步骤；
- 训练集只能引用批准版本。

### 10.2 来源控制

- 对外部贡献设置低信任等级；
- 限制单一主体的训练贡献；
- 检测近重复与协同提交；
- 第三方数据要求来源和变更证明；
- 高价值类别使用可信数据优先；
- 新来源先进入隔离和观察期。

### 10.3 鲁棒训练与数据清理

- 使用局部一致性和表示异常检测；
- 对高影响样本进行人工与模型联合复核；
- 使用数据消融验证目标影响；
- 测试不同模型和随机种子；
- 限制单个样本或来源的训练权重；
- 对可疑样本采用隔离而不是不可逆删除。

### 10.4 模型发布门禁

除总体指标外，检查：

- 高价值目标样本回归集；
- 每类和每群体指标；
- 目标攻击成功率；
- 目标附近局部鲁棒性；
- 预测概率和校准变化；
- 与最后已知安全模型的表示差异。

### 10.5 监控与恢复

- 保存最后已知安全数据和模型；
- 支持按来源或批次隔离数据；
- 记录模型版本使用的每个数据版本；
- 发现异常时暂停自动部署；
- 支持删除污染、重建特征和重新训练；
- 对目标行为变化建立持续监控。

---

## 11. 修复后复测

```text
1. 验证原始数据和特征存储写权限已经收紧。
2. 验证特征提取代码和参数具有版本及完整性校验。
3. 重放最小 Clean Label 测试样本，确认来源和异常检测生效。
4. 检查近邻、表示空间和单一来源聚合告警。
5. 重新训练并执行目标样本专项回归。
6. 验证总体指标正常时，目标门禁仍能发现异常。
7. 删除测试污染并重新生成派生特征。
8. 确认目标预测恢复到干净基线范围。
9. 演练按数据谱系定位所有受影响模型版本。
10. 确认自动再训练和部署不会绕过新控制。
```

## 13. 常见误区

### 13.1 “标签都是正确的，所以数据是干净的”

Clean Label Attack 正是利用这一假设。标签正确只能证明标签层没有明显问题。

### 13.2 “样本肉眼正常，所以模型表示也正常”

人类语义相似度与模型特征相似度并不相同。

### 13.3 “只检查原始文件就够了”

攻击也可能发生在特征提取、缩放、嵌入缓存和特征仓库中。

### 13.4 “总体 Accuracy 没下降，所以攻击失败”

Clean Label Attack 通常高度定向，可能只影响一个或少量目标。

### 13.5 “所有离群点都是污染”

真实长尾样本也会表现为离群点。自动删除可能引入新的偏见和安全盲区。

### 13.6 “代码没有修改标签，就一定是 Clean Label”

还要确认修改后样本的标签对独立标注者或业务真值仍然合理。

## 14. 记忆卡片

### Q1：Clean Label Attack 修改什么？

主要修改训练样本的特征或模型表示，标签保持正确或看似合理。

### Q2：攻击为什么能成功？

污染样本推动模型的决策边界或表示空间，使预先选定的目标被归入攻击类别。

### Q3：为什么普通标签审计可能失效？

污染样本的标签本身没有被翻转，甚至能通过人工复核。

### Q4：实际测试最重要的检测方向是什么？

特征完整性、近邻与局部一致性、表示空间异常、来源贡献和目标模型行为。

### Q5：Clean Label 与对抗样本的区别是什么？

前者污染训练过程并影响后续模型；后者在推理阶段修改输入欺骗已有模型。

### Q6：什么是特征碰撞？

污染样本在输入语义上仍像基础类别，但在模型表示空间中被构造成接近目标样本。

### Q7：标签不变是否足以证明属于 Clean Label？

不足。修改后标签还必须对独立标注者或权威真值保持合理。

### Q8：为什么需要目标样本专项回归集？

总体指标可能完全正常，而攻击只影响少量高价值目标。

### Q9：为什么优先选择边界附近的目标？

它的分类裕量较小，较轻微的边界移动就可能改变预测，适合验证最小攻击预算。

### Q10：最近邻索引为什么必须映射？

最近邻通常返回类别子集中的相对位置，必须通过该类别的原始索引数组转换成完整训练集索引。

### Q11：扰动应沿什么方向？

在线性 Class 0/1 边界中，应沿攻击类别到目标类别方向的边界反法向量移动；方向必须结合所采用的分数差符号约定判断。

### Q12：固定 epsilon 有什么问题？

不同样本到边界距离不同，固定值可能让部分样本没有跨界、部分样本过度扰动。逐样本最小跨界扰动更严谨。

### Q13：代码没有修改标签是否就属于 Clean Label？

不是。还必须证明修改后的样本对独立标注者或业务真值仍然合理属于原类别。

## 15. 最终总结

Clean Label Attack 的隐蔽性来自一个容易被系统默认信任的事实：标签看起来是正确的。攻击者把恶意影响放在特征、表示空间或数据处理路径中，使污染样本通过传统标注质检，并在训练时定向改变模型。

典型构造流程是：选择基线模型能够正确分类但靠近边界的目标，从攻击类别中寻找目标附近的训练样本，沿边界法向方向施加受限的最小特征扰动，保持原标签不变，再通过重新训练验证目标是否跨过边界。

实际测试必须回答：

1. 攻击者能否向训练源贡献或修改特征？
2. 原始数据到派生特征是否具备完整谱系？
3. 标签正确的样本是否在局部或表示空间中异常？
4. 少量样本能否稳定影响高价值目标？
5. 总体指标正常时，目标专项门禁能否发现攻击？
6. 能否定位污染来源、移除样本、重建特征并重新训练？

核心原则：

```text
Clean Label 不等于 Clean Data。
标签可信只是数据可信链中的一个环节。
```
