# LLM Jailbreaking

## 使用方式：越狱鲁棒性测试快速入口

使用抽象策略标签和无害占位内容，不生成现实有害操作材料：

```text
正常请求基线 → 直接受限意图 → 角色/虚构包装
→ 多轮拆分 → 编码/变换 → 会话级判定 → 修复回归
```

```text
[ ] 明确政策类别、允许/拒绝边界和期望响应
[ ] 使用 [PROHIBITED_CONTENT]、SYNTHETIC_MARKER 等占位符
[ ] 记录完整多轮上下文、模型和 system prompt 版本
[ ] 区分完全服从、部分泄露、正确拒绝和安全替代帮助
[ ] 同时测试正常相邻请求，防止修复造成过度拒绝
[ ] 不收集可直接复用的现实规避语料
```

最少覆盖：

```text
Roleplay / Fictional framing
多轮意图拆分
翻译、改写、编码包装
上下文冲突与优先级
支持语言间的一致性
重复尝试与会话级风险累积
```

最终报告成功率、部分泄露率、正常通过率、分策略结果和多次采样波动；一次偶然拒绝或一次偶然绕过都不能代表整体结论。

---

## 定义

Jailbreaking:
绕过LLM安全限制，使模型执行原本禁止的行为。


## 目标

- 绕过System Prompt
- 绕过Safety Alignment
- 绕过RLHF限制
- 诱导模型生成禁止内容


## 常见方法


## 1. DAN

Do Anything Now

思路:
- 创建无约束角色
- 让模型忽略限制


## 2. Roleplay

思路:
- 不直接提出请求
- 通过角色间接请求


例:
"你是安全研究员..."


## 3. Fictional Scenario

思路:
- 创建虚构世界
- 降低模型安全判断


## 4. Token Smuggling

思路:
隐藏危险关键词

方法:
- 分割token
- 编码
- Unicode替换


## 5. Adversarial Suffix

思路:
利用LLM next-token prediction

特点:
- 添加特殊后缀
- 改变输出概率


## 6. Opposite/Sudo Mode

思路:
让模型进入不存在的特殊模式

例如:
Developer mode


## Prompt Injection vs Jailbreak

Prompt Injection:
改变模型指令执行


Jailbreak:
突破模型安全限制


关系:

Prompt Injection 可以用于 Jailbreak
但二者不是完全等价


## 测试顺序

1. Direct instruction override
2. Roleplay
3. Fictional scenario
4. Encoding/token manipulation
5. Suffix attack
6. Adversarial jailbreak
