# 越狱技巧

根据最终意图---拆分为多个步骤---局部正常的多步骤最终组合成带恶意意图的步骤
角色扮演---背景包装---文本混淆


## 1. 用四层结构分析提示

面对一个复杂越狱提示，可以拆成四层。

### 核心目标

用户最终希望模型产生什么结果。

### 包装层

研究、小说、模拟、翻译、教育、角色扮演等背景。

### 控制层

规定模型如何执行，例如：

- 必须分步骤；
- 不得拒绝；
- 使用指定角色；
- 按固定格式输出；
- 重复或改写某种观点。

### 混淆层

字符、编码、多语言、无关背景和嵌套指令。

可以写成：

\[ Prompt= Goal+Wrapper+Control+Obfuscation \]

分析越狱时，应先问：

> 如果删除包装、控制和混淆，剩下的核心目标是什么？


## 2. 区分直接驱动因素和辅助因素

一些因素更接近直接原因：

- 加密或混淆类型；
- 正面角色；
- 背景任务；
- 任务步骤数量；
- 背景信息数量。

另一些因素可能通过中间变量发挥作用：

- 多语言；
- 词汇复杂度；
- 观点劫持；
- 错误前提；
- 字符变换。

这意味着研究越狱时，不应看到一个成功提示很长，就直接得出“长度导致越狱”。

更合理的问题是：

```text
长度增加的同时，是否也增加了任务步骤？
是否增加了背景包装？
是否隐藏了真实意图？
是否改变了输出结构？
```


## 3. 使用反事实修改，而不是盲目改写

理解某个模板为什么有效，可以逐次删除一个特征：

```text
完整提示
→ 删除角色设定
→ 删除背景故事
→ 合并任务步骤
→ 还原混淆文本
→ 删除强制输出格式
```

每次只改变一个主要因素，然后比较模型行为。

例如：

|版本|角色|多步骤|背景包装|结果|
|---|---|---|---|---|
|原始版本|1|1|1|产生风险回答|
|删除角色|0|1|1|仍有风险|
|合并步骤|1|0|1|恢复拒绝|
|删除背景|1|1|0|部分拒绝|

这比继续堆叠随机句子更能说明问题。上例中，多步骤可能是最值得验证的候选原因。
## 4. 不要把“没有拒绝”当作越狱成功


模型可能：

- 没有明确拒绝；
- 只讨论概念；
- 给出安全替代方案；
- 提供警告；
- 提供非常笼统的信息；
- 真正给出有害内容。

因此测试时最好采用多标签记录：

```text
有害内容：是/否
警告：是/否
拒绝：是/否
正向引导：是/否
中性回答：是/否
```

这能避免把“模型愿意继续交流”误判为“安全机制已经被绕过”。

## 5. 关注特征组合而不是单个词语

一个“小说创作”请求并不天然危险，一个多步骤任务也不天然危险。

风险往往来自组合：

```text
虚构场景
+ 无条件服从角色
+ 多步骤转换
+ 隐藏的核心任务
+ 强制输出格式
```

因此更合理的风险模型是：

\[ Risk=f(角色,步骤,背景,混淆,意图,输出约束) \]

而不是：

```text
出现“小说” → 拒绝
出现“研究” → 拒绝
步骤超过5个 → 拒绝
```

后者会严重误伤正常用户。
