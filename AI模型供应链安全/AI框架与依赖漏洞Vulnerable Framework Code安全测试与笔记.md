# AI 框架与依赖漏洞（Vulnerable Framework Code）安全测试清单与学习笔记

> 适用范围：Ollama、MLflow、TorchServe 等 AI/ML 框架，模型服务、训练编排、Tracking Server、模型注册表及其第三方依赖的授权安全评估。优先采用版本核查、SBOM、配置审计、源码回归测试和隔离环境验证；不得对生产服务实施崩溃测试、任意文件读取、反序列化利用或代码执行。

## 0. 核心判断

```text
Vulnerable Framework Code
  = AI 应用自身业务代码可能没有漏洞
  + 但所依赖的模型服务、生命周期平台或解析库存在安全缺陷
  -> 整个 AI 应用继承该风险

常见影响
  = DoS / LFI / 路径穿越 / SSRF / 权限绕过 / 反序列化 / RCE
```

不要混淆以下问题：

| 问题 | 核心对象 | 典型证据 |
|---|---|---|
| 框架代码漏洞 | MLflow、Ollama、TorchServe 或底层依赖 | 易受影响版本与可达代码路径 |
| 配置错误 | 管理 API、监听地址、认证和网络策略 | 未授权主体可访问受限接口 |
| 模型部署篡改 | 已批准模型在交付或运行阶段被替换 | 运行摘要与批准摘要不一致 |
| 数据投毒 | 训练、反馈或标签数据被操纵 | 数据版本与来源发生未授权变化 |
| 不安全模型文件 | 模型格式加载时可执行行为 | 解析或反序列化发生在信任验证之前 |

漏洞判定需要同时回答：

```text
组件及版本是否受影响？
漏洞代码是否包含在实际构建中？
危险功能是否启用并可从攻击面到达？
认证、网络隔离、沙箱或最小权限是否阻断利用链？
无害验证是否证明了实际安全影响？
修复是否覆盖所有等价输入，而非只过滤单一字符串？
```

## 0.1 进入环境后的 5 分钟路线

### 第 1 分钟：识别组件与版本

```text
[ ] 记录框架名称、版本、构建号和运行模式
[ ] 记录容器镜像 digest、基础镜像和操作系统
[ ] 导出直接依赖、传递依赖和 SBOM
[ ] 记录插件、模型加载器、文件解析器和 URL 客户端
```

### 第 2 分钟：确定暴露面

```text
[ ] 推理 API、管理 API、Tracking Server 和模型注册表
[ ] 模型拉取、Artifact 下载、上传和导出接口
[ ] 文件路径、URL、归档、YAML、JSON 和模型清单解析入口
[ ] 监听地址、反向代理、认证、网段和容器端口
```

### 第 3 分钟：建立版本风险结论

```text
[ ] 将实际版本与可信漏洞公告、厂商修复和发行说明对应
[ ] 区分“版本命中”“功能可达”“控制阻断”和“已验证影响”
[ ] 记录修复版本或厂商缓解措施，不只记录 CVE 编号
[ ] 检查 Backport，不能只比较表面版本号
```

### 第 4 分钟：选择最低影响验证

```text
[ ] DoS 优先使用源码测试、厂商回归或隔离实例，不打生产
[ ] LFI 只读取自己创建的 canary 文件，不读取系统文件
[ ] SSRF 只访问自有接收器，不探测内网或云元数据
[ ] 反序列化只验证危险解析路径，不使用执行 gadget
```

### 第 5 分钟：确认修复与补偿控制

```text
[ ] 升级或 Backport 后重放安全回归用例
[ ] 验证认证、网络策略、文件根目录和出站限制仍有效
[ ] 验证异常输入被安全拒绝且服务继续健康
[ ] 确认日志能关联请求、版本、阻断位置和运行实例
```

## 1. 测试变量与安全边界

### Linux / macOS

```bash
export LAB_URL="http://127.0.0.1:8080"
export CVF_MARKER="SYNTHETIC_CVF_$(date +%Y%m%d_%H%M%S)"
export CANARY_ROOT="/tmp/cvf-authorized-canary"
```

### Windows PowerShell

```powershell
$LabUrl = "http://127.0.0.1:8080"
$CvfMarker = "SYNTHETIC_CVF_$(Get-Date -Format yyyyMMdd_HHmmss)"
$CanaryRoot = Join-Path $env:TEMP "cvf-authorized-canary"
```

安全测试前置清单：

```text
[ ] 环境为本地实验、隔离靶场或书面授权的测试环境
[ ] 已记录服务负责人、测试窗口、停止条件和恢复方法
[ ] 生产流量、生产数据和真实凭据与测试环境隔离
[ ] 测试文件只包含唯一 marker，不包含系统或用户数据
[ ] DoS 测试具有进程监控、自动恢复和单次请求限制
[ ] 禁止并发压测、持续重试、资源耗尽和跨系统扩散
[ ] 禁止读取 `/etc/passwd`、SSH Key、云凭据或真实 Artifact
[ ] 禁止上传恶意模型、Pickle、YAML gadget、类文件或执行载荷
[ ] 一旦观察到非预期真实数据或生产影响，立即停止
```

## 3. 漏洞情报与版本判定清单

```text
[ ] 漏洞信息来自厂商公告、维护者提交、CVE 记录或可信漏洞库
[ ] 记录 CVE、CWE、受影响范围、修复版本和公告日期
[ ] 记录版本字符串、包管理器结果和镜像 digest 作为证据
[ ] 确认发行版是否 Backport 修复，避免仅凭版本号误判
[ ] 确认易受影响函数是否被编译、安装或打包进当前制品
[ ] 确认危险功能、插件或端点是否启用
[ ] 确认攻击者所需身份、网络位置和输入控制能力
[ ] 确认网关、WAF、沙箱和最小权限是否真实阻断影响
[ ] 区分“组件存在”“版本命中”“路径可达”“影响已验证”
[ ] 对无官方修复的漏洞记录禁用功能、隔离和监控方案
[ ] 修复完成后更新 SBOM、基线镜像和资产台账
```

建议使用以下状态：

```text
不适用：组件或危险功能不存在
版本不受影响：确认已包含官方修复或可信 Backport
版本命中但不可达：漏洞代码存在，入口被可靠移除或隔离
可达但被控制阻断：请求到达组件，但权限或沙箱阻断影响
影响已验证：在隔离环境中通过无害方法证明安全影响
待确认：版本、配置、编译选项或网络路径证据不足
```

## 4. 通用框架攻击面测试清单

### 4.1 网络与认证

```text
[ ] 服务是否只监听业务所需接口和地址？
[ ] 管理、Tracking、注册表和调试端口是否暴露到非管理网络？
[ ] 未认证请求是否能读取版本、配置、模型列表或错误详情？
[ ] 所有修改状态的接口是否强制认证和服务端授权？
[ ] 反向代理与后端是否采用一致的路径和身份解析？
[ ] 内部服务是否错误地把网络位置当作唯一信任依据？
[ ] 默认口令、匿名模式和开发模式是否已关闭？
[ ] 失败认证是否限速、审计并避免详细枚举信息？
```

### 4.2 文件、路径与 Artifact

```text
[ ] 用户可控路径是否在规范化后限制于固定根目录？
[ ] 是否拒绝绝对路径、父目录、驱动器路径和 UNC 路径？
[ ] URL 的 path、query、fragment 和编码形式是否统一验证？
[ ] 多次编码、混合分隔符和 Unicode 规范化是否产生差异？
[ ] 符号链接、挂载点和归档解压是否可逃逸根目录？
[ ] Artifact 下载是否同时检查实验、Run、模型和对象权限？
[ ] 文件读取是否使用固定对象 ID，而非直接接受服务器路径？
[ ] 响应是否避免泄露绝对路径、目录结构和文件存在性？
```

### 4.3 URL 与远程下载

```text
[ ] 远程下载功能是否可关闭或仅允许受控注册表？
[ ] 是否限制协议、主机、端口、路径和最终解析地址？
[ ] 是否拒绝 loopback、私网、链路本地和保留地址？
[ ] DNS 重绑定和每次重定向后是否重新校验？
[ ] TLS 证书、主机名和下载身份是否严格验证？
[ ] 是否限制下载大小、时间、压缩比和文件数量？
[ ] 下载内容是否在解析前验证类型、摘要、签名和批准状态？
[ ] 出站请求是否通过网络策略和代理进一步限制？
```

### 4.4 解析器、反序列化与插件

```text
[ ] 不可信 YAML 是否使用安全解析模式并禁止任意类型实例化？
[ ] Pickle 或等价对象格式是否被排除在不可信加载路径之外？
[ ] JSON、XML、压缩包和模型清单是否设置深度与大小限制？
[ ] 解析前是否完成来源、摘要和签名验证？
[ ] 插件、Handler、Hook 和自定义代码是否只能来自批准制品？
[ ] 模型加载进程是否缺少 Shell、编译器和非必要网络权限？
[ ] 解析异常是否安全失败，而非回退到更宽松加载器？
[ ] 解析器版本是否纳入 SBOM、漏洞扫描和升级基线？
```

### 4.5 可用性与资源控制

```text
[ ] 数组、张量、层数、维度和清单项数量是否在使用前校验？
[ ] 对空数组、缺失字段、负值、零值和超大值是否安全处理？
[ ] 下载、解压、哈希、解析和模型加载是否有独立资源上限？
[ ] 单个请求能否导致进程 panic、OOM 或长期阻塞？
[ ] 异常是否被请求边界捕获，而非终止整个服务？
[ ] 服务是否具备超时、取消、并发限制和熔断？
[ ] Worker 崩溃是否与控制面隔离，并避免崩溃循环？
[ ] 健康检查是否能区分存活、就绪和模型可服务状态？
[ ] 自动重启是否配合速率限制和告警，避免掩盖持续攻击？
```

## 5. Ollama DoS 场景测试清单

材料中的 CVE-2025-1975 示例涉及模型下载时对异常 Manifest 数组处理不足。生产验证应停留在版本与代码路径确认；只有隔离实例才允许执行一次厂商回归测试或等价的最小异常 Fixture。

### 5.1 非破坏性优先验证

```text
[ ] 记录 Ollama 版本、构建提交和二进制摘要
[ ] 记录模型拉取功能是否启用、由谁可调用
[ ] 检查目标版本是否包含维护者发布的修复
[ ] 检查下载 Manifest 的数组长度与必填字段校验代码
[ ] 查找官方单元测试或回归测试是否覆盖空层、缺字段和异常长度
[ ] 验证 API 是否需要认证并限制模型来源
[ ] 生产环境不发送已知崩溃输入
```

### 5.2 隔离实例受控回归

```text
[ ] 使用无模型、无生产数据的本地隔离实例
[ ] 限制 CPU、内存、磁盘、网络和进程权限
[ ] 测试前记录 PID、健康状态、日志位置和恢复命令
[ ] 只发送一次最小异常 Manifest Fixture
[ ] 不并发、不循环、不扩大数组和响应体
[ ] 记录 HTTP 结果、异常、进程状态和健康检查
[ ] 修复版本应返回受控 4xx/错误，不应 panic 或退出
[ ] 若进程退出，停止测试并保存日志，不重复触发
[ ] 测试后删除 Fixture、停止接收器并恢复隔离环境
```

安全预期：

```text
异常 Manifest
  -> Schema 与边界检查拒绝
  -> 当前请求返回受控错误
  -> 服务进程保持存活
  -> 其他合法请求仍可处理
  -> 记录低敏感度审计与错误信息
```

## 6. MLflow LFI 场景测试清单

材料中的 CVE-2023-6909 与 CVE-2024-1594 示例说明：只过滤 URL query 中的 `..` 不足以覆盖 fragment、编码和规范化差异。验证时只能读取专用 canary 文件，不得使用系统文件作为证据。

### 6.1 Canary 准备

```text
[ ] 在隔离实例的专用测试根目录创建唯一 marker 文件
[ ] 文件权限只允许测试服务按预期访问
[ ] 路径中不放置凭据、配置、用户数据或生产 Artifact
[ ] 记录 canary 绝对路径、内容摘要、创建时间和清理方式
[ ] 创建正常 Artifact 作为阳性功能基线
[ ] 创建不存在文件作为阴性对照
```

### 6.2 Experiment、Run 与 Model 权限

```text
[ ] 创建 Experiment 是否需要认证和项目权限？
[ ] `artifact_location` 是否只能引用批准存储根？
[ ] 创建 Run 是否验证 Experiment 所属租户与权限？
[ ] 注册模型和创建版本是否需要独立权限？
[ ] `source` 是否必须来自当前 Run 的已批准 Artifact？
[ ] 下载 Artifact 是否再次校验用户、Experiment、Run 和模型权限？
[ ] 普通用户能否把其他主体的 Run 绑定到自己的模型？
[ ] 删除或归档后，旧 Artifact URL 是否仍可访问？
```

### 6.3 路径规范化回归

对 query、fragment、path 和 source 字段分别使用只指向 canary 的安全变体：

```text
[ ] 原始父目录序列
[ ] 百分号编码与重复编码
[ ] 正斜杠、反斜杠和混合分隔符
[ ] URL query 中的路径成分
[ ] URL fragment 中的路径成分
[ ] 绝对路径与 file URL
[ ] 多余点、空段、尾点和尾斜杠
[ ] Unicode 等价字符与规范化差异
[ ] 符号链接指向测试根外的另一个 canary
[ ] 不同代理、SDK 和 API 路由对同一值的解析差异
```

安全预期：

```text
解析 URL 与用户输入
  -> 统一解码和规范化
  -> 解析为受控 Artifact 对象，而不是服务器任意路径
  -> 验证最终真实路径仍位于批准根目录
  -> 验证对象级与租户级权限
  -> 仅返回批准 Artifact
```

### 6.4 不完整修复检查

```text
[ ] 修复是否只搜索原始字符串中的 `..`？
[ ] 是否只检查 query，却遗漏 fragment 或 path？
[ ] 是否在 URL 解析之前检查，导致解析后语义变化？
[ ] 是否只覆盖一个 API 路由，遗漏 AJAX、REST、SDK 或旧版路由？
[ ] 创建时验证后，下载时是否重新解析出不同路径？
[ ] Windows 与 Linux 路径语义是否分别测试？
[ ] 符号链接和挂载点是否绕过字符串前缀检查？
[ ] 回归测试是否覆盖同类输入空间，而非单一公开 Payload？
```

## 7. 漏洞链组合测试清单

单个问题的影响可能被其他控制限制，也可能与其他问题组合升级：

```text
[ ] 未认证管理面 + 任意模型拉取
[ ] 任意 URL + SSRF + 未受限出站网络
[ ] 任意下载 + 不安全 YAML/Pickle 解析
[ ] LFI + 配置/凭据泄露 + 管理面接管
[ ] DoS + 无速率限制 + 自动重启循环
[ ] Artifact 越权 + 模型注册权限 + 生产部署权限
[ ] 过期框架 + root 运行 + 可写宿主挂载
[ ] 详细错误 + 版本暴露 + 公共已知漏洞
```

组合测试原则：

```text
[ ] 分别验证每个前置条件，不执行最终破坏性步骤
[ ] 用日志、配置和无害 canary 证明链条可达性
[ ] 明确记录在哪一层被认证、网络、文件或沙箱控制阻断
[ ] 不因多个“可能存在”直接宣称 RCE 已验证
[ ] 当前置条件已经足以判定严重风险时，停止继续利用
```

## 8. 快速测试用例表

| 编号 | 测试目标 | 无害操作 | 漏洞信号 |
|---|---|---|---|
| CVF-01 | 组件识别 | 收集包版本与镜像摘要 | 组件版本无法追踪 |
| CVF-02 | SBOM 完整性 | 对照实际运行包与 SBOM | 关键依赖缺失或版本不一致 |
| CVF-03 | 已知漏洞匹配 | 对照可信公告和 Backport | 实际构建包含未修复漏洞 |
| CVF-04 | 管理面暴露 | 未认证无状态请求 | 非管理网络可访问受限接口 |
| CVF-05 | 修改接口授权 | 普通测试账户请求创建测试对象 | 未授权操作成功 |
| CVF-06 | 版本信息泄露 | 触发普通 4xx 错误 | 返回精确版本、路径或栈信息 |
| CVF-07 | URL 来源限制 | 使用自有无害接收器 | 服务可向任意来源发起请求 |
| CVF-08 | 重定向复检 | 安全重定向至另一测试地址 | 未重新验证最终目标 |
| CVF-09 | Manifest 边界 | 隔离实例使用最小异常 Fixture | 单次请求导致服务退出 |
| CVF-10 | 异常隔离 | 异常后执行正常健康请求 | 整个服务不可用 |
| CVF-11 | Artifact 根目录 | 请求测试根外 canary | canary 内容被返回 |
| CVF-12 | Query 规范化 | 使用 query 中的安全路径变体 | 逃逸批准 Artifact 根 |
| CVF-13 | Fragment 规范化 | 使用 fragment 中的安全路径变体 | 绕过 query 专项过滤 |
| CVF-14 | 编码规范化 | 使用编码后的 canary 路径 | 解码后发生目录逃逸 |
| CVF-15 | 符号链接边界 | 测试链接指向另一 canary | 真实路径检查缺失 |
| CVF-16 | 对象级授权 | 用户 A 请求用户 B 的测试 Artifact | 越权读取成功 |
| CVF-17 | 解析器安全 | 普通未知 YAML 类型 | 尝试实例化任意类型 |
| CVF-18 | 资源限制 | 单个边界大小测试请求 | 缺少大小、时间或内存限制 |
| CVF-19 | 沙箱影响 | 审查测试实例运行身份 | root、宿主写入或不受限出站 |
| CVF-20 | 不完整修复 | 重放 query/fragment/编码矩阵 | 等价输入仍能绕过 |
| CVF-21 | 日志与告警 | 完成一次 canary 测试 | 无法关联请求、实例和阻断位置 |
| CVF-22 | 修复回归 | 重放全部 CVF 用例 | 原漏洞或变体仍可复现 |

## 10. 根因审计清单

```text
[ ] 是否缺少完整资产清单、SBOM 和组件责任人？
[ ] 是否使用停止维护、长期不升级或来源不明的框架版本？
[ ] 依赖是否未锁定、可被镜像或构建过程静默替换？
[ ] 安全扫描是否只看直接依赖，忽略传递依赖和基础镜像？
[ ] 管理面是否默认暴露、无认证或仅依赖内网假设？
[ ] 用户可控 URL 是否缺少协议、主机、地址和重定向校验？
[ ] 用户路径是否在多套 URL/文件解析器之间反复转换？
[ ] 路径边界是否使用字符串过滤，而非规范化后的真实路径判断？
[ ] Artifact 是否缺少对象级、项目级和租户级授权？
[ ] 数组、维度、层和清单字段是否在边界检查前被索引？
[ ] 单个请求异常是否能逃逸请求边界并终止服务？
[ ] 不可信文件是否在来源和完整性验证前被解析？
[ ] 模型服务是否以 root、高权限挂载或不受限网络运行？
[ ] 修复是否只拦截公开 Payload，未覆盖等价语义输入？
[ ] 是否缺少针对历史 CVE 根因的自动化回归测试？
[ ] 版本升级失败时是否自动回退到旧的易受影响镜像？
```

## 11. 修复与回归清单

### 11.1 依赖治理

```text
[ ] 使用受支持版本并及时应用官方修复或可信 Backport
[ ] 锁定直接与传递依赖，保存来源与完整性信息
[ ] 每次构建生成 SBOM，并与实际运行镜像持续对比
[ ] 对互联网暴露和高权限组件设置更短修复时限
[ ] 将框架、解析库、基础镜像和插件纳入统一升级流程
[ ] 无法及时升级时关闭危险功能并实施网络与权限隔离
```

### 11.2 安全配置与纵深防御

```text
[ ] 管理面与业务面分离，默认不对外暴露
[ ] 所有状态修改接口实施认证、授权、限速和审计
[ ] 远程下载采用严格 allowlist、证书验证和出站网络限制
[ ] 文件访问基于受控对象 ID，并验证规范化后的真实路径
[ ] 不可信数据使用安全解析器、严格 Schema 和资源上限
[ ] 服务以非 root、只读文件系统和最小网络权限运行
[ ] 将 Worker 与控制面隔离，限制单个异常影响范围
[ ] 错误响应隐藏版本、路径、栈和内部网络细节
```

### 11.3 修复后复测顺序

```text
1. 实际组件、镜像和 SBOM 均显示已修复版本或可信 Backport
2. 管理、Tracking 和注册接口只对授权身份与网络开放
3. 普通账户不能创建、绑定、下载或部署未授权 Artifact
4. Ollama 异常 Manifest 在隔离实例返回受控错误且进程保持健康
5. MLflow 的 path、query、fragment、编码和分隔符变体均不能逃逸根目录
6. 符号链接、挂载点和不同操作系统路径语义受到相同边界控制
7. 远程 URL 不能访问未批准主机、地址、协议或重定向目标
8. 不可信 YAML、模型和归档在信任验证前不会进入危险解析器
9. 单个异常请求不会导致控制面或其他模型服务中断
10. 日志能关联请求、组件版本、阻断位置、实例和恢复结果
11. 补偿控制失效时系统失败关闭，不回退到不安全模式
12. 重放 CVF-01～CVF-22，确认原漏洞与等价变体稳定阻断
```

## 12. 最终判定口径

```text
安全：组件版本可追踪且已修复；危险入口受认证、网络、路径、解析和资源控制保护；历史根因具有自动化回归测试。

中风险：版本命中或信息暴露，但危险功能不可达，或可靠补偿控制在实际影响前稳定阻断。

高风险：未授权主体可触发服务崩溃、读取专用根目录外的 canary、访问任意 URL，或进入危险解析路径。

严重：框架漏洞可读取真实敏感文件、修改模型/Artifact、获得服务器代码执行，或造成大范围持续服务中断。达到此结论不应继续扩大验证。
```

一句话总结：**AI 框架不是可信黑盒；必须知道运行了什么版本、开放了哪些入口、输入会进入哪些解析器，并用最小权限和根因级回归把单个组件漏洞限制在最小影响范围。**
