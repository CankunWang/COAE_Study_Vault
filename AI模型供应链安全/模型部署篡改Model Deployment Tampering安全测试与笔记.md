# 模型部署篡改（Model Deployment Tampering）安全测试清单与学习笔记

> 适用范围：模型注册、制品存储、CI/CD、模型服务框架、容器与 Kubernetes、对象存储、共享卷和生产推理服务的授权安全评估。默认使用无害、不可执行的测试制品、错误摘要和合成行为标记；不得上传恶意反序列化载荷、建立反向 Shell、修改生产模型或读取真实训练数据。

## 0. 核心判断

```text
训练数据被修改
  -> Data Poisoning（数据投毒）

模型文件含不安全序列化对象并在加载时执行代码
  -> Unsafe Deserialization（不安全反序列化）

已经批准的模型在注册、存储、传输、部署或运行阶段被替换或修改
  -> Model Deployment Tampering（模型部署篡改）

部署平台漏洞导致攻击者获得修改模型或部署配置的能力
  -> 基础设施入侵路径；若最终改变生产模型，则形成部署篡改
```

完整攻击链通常为：

```text
未授权控制面 / 被盗 CI 身份 / 可写模型仓库 / 任意 URL 拉取
  -> 替换模型、处理代码、配置或容器制品
  -> 部署端未验证来源、审批、签名和摘要
  -> 未批准制品进入生产
  -> 决策边界改变、后门、性能退化、数据泄露或代码执行
```

测试目标不是制造恶意模型，而是证明以下任一安全门是否缺失：

```text
谁可以提交和批准模型？
部署的究竟是哪一个不可变版本？
从哪里拉取？传输身份是否可信？
拉取前后、加载前后是否验证签名和摘要？
部署配置、处理代码和依赖是否与模型一起受保护？
运行中的文件能否在校验后再次被替换？
异常版本能否被发现、停止和可靠回滚？
```

## 0.1 进入环境后的 5 分钟路线

### 第 1 分钟：确认生产模型身份

```text
[ ] 记录服务名、环境、模型名称、版本和部署时间
[ ] 记录模型注册表 URI、制品摘要、签名者和批准记录
[ ] 记录容器镜像摘要、配置版本和预处理代码版本
[ ] 确认运行实例能报告与部署清单一致的模型身份
```

### 第 2 分钟：枚举写入与部署入口

```text
[ ] 模型上传 API 与管理 API
[ ] 模型注册表、对象存储和共享卷
[ ] CI/CD、GitOps 仓库和部署控制器
[ ] 容器镜像仓库、Helm Chart 和 Kubernetes 清单
[ ] 远程 URL 加载、插件、工作流和热更新接口
[ ] 训练数据、评估数据与自动再训练入口
```

### 第 3 分钟：验证最小权限

```text
[ ] 未认证主体不能访问管理面
[ ] 普通用户不能上传、注册、批准、部署或回滚模型
[ ] 提交者不能批准自己的制品
[ ] 生产运行身份不能写模型注册表或覆盖已批准版本
[ ] CI 身份只具备目标环境与目标仓库所需权限
```

### 第 4 分钟：验证完整性门禁

```text
[ ] 使用错误 SHA-256 的无害副本进行阴性测试
[ ] 使用未签名但格式正确的测试制品进行阴性测试
[ ] 使用未批准版本、可变标签或非注册表 URL 进行阴性测试
[ ] 确认拒绝发生在解析、解压、反序列化或模型加载之前
```

### 第 5 分钟：验证可观测与恢复

```text
[ ] 上传、审批、拉取、校验、部署和回滚均产生关联日志
[ ] 摘要或签名失败触发告警且安全停止
[ ] 部署失败不会降级到未验证的本地缓存或 latest 标签
[ ] 已批准版本可按摘要回滚，且回滚动作需要授权
```

## 1. 测试变量与无害制品

### Linux / macOS

```bash
export LAB_URL="http://127.0.0.1:8081"
export MDT_MARKER="SYNTHETIC_MDT_$(date +%Y%m%d_%H%M%S)"
export APPROVED_MODEL_SHA256="<approved-sha256>"
export TEST_MODEL_SHA256="<benign-test-artifact-sha256>"
```

### Windows PowerShell

```powershell
$LabUrl = "http://127.0.0.1:8081"
$MdtMarker = "SYNTHETIC_MDT_$(Get-Date -Format yyyyMMdd_HHmmss)"
$ApprovedModelSha256 = "<approved-sha256>"
$TestModelSha256 = "<benign-test-artifact-sha256>"
```

测试制品要求：

```text
[ ] 制品只能包含固定文本、零值张量或明确不可执行的占位数据
[ ] 不包含 Pickle gadget、YAML 类型实例化、宏、脚本或动态加载代码
[ ] 不包含真实模型权重、训练样本、凭据、URL 密钥或内部配置
[ ] 批准版与测试版使用不同名称、版本、摘要和 SYNTHETIC_MARKER
[ ] 测试版本不得复用生产版本号、latest 标签或生产对象路径
[ ] 所有写入仅发生在隔离测试注册表、测试 Bucket 或测试命名空间
[ ] 测试前记录原始部署摘要，测试后验证已恢复
```

生成摘要时只读取自建的无害测试文件：

```bash
sha256sum benign-test-model.bin
```

```powershell
Get-FileHash -LiteralPath .\benign-test-model.bin -Algorithm SHA256
```

## 2. 模型交付链盘点清单

| 阶段 | 关键资产 | 写入主体 | 审批主体 | 完整性依据 | 运行时读取主体 |
|---|---|---|---|---|---|
| 训练输出 | 模型、处理代码、指标 | 待确认 | 待确认 | 待确认 | 无 |
| 模型注册 | 不可变版本、元数据 | 待确认 | 待确认 | 待确认 | 部署系统 |
| 构建 | 镜像、依赖、配置 | 待确认 | 待确认 | 待确认 | 编排平台 |
| 部署 | 清单、模型引用 | 待确认 | 待确认 | 待确认 | 推理服务 |
| 运行 | 本地模型、缓存 | 部署系统 | 无 | 待确认 | 模型进程 |

盘点清单：

```text
[ ] 训练代码、数据快照、超参数和随机种子
[ ] 模型文件、Tokenizer、预处理器、标签映射和配置
[ ] 评估报告、安全门禁结果和批准记录
[ ] 模型注册表、对象存储、文件共享和本地缓存
[ ] 容器基础镜像、运行时依赖、模型服务框架和插件
[ ] CI Runner、构建缓存、制品仓库和部署凭据
[ ] Helm、Terraform、Kubernetes、GitOps 和环境变量
[ ] DNS、代理、证书、远程 URL、镜像加速器和下载重定向
[ ] 蓝绿、灰度、影子、回滚和灾备环境中的模型副本
[ ] 运行时热更新、自动扩缩容、新节点启动和缓存恢复路径
```

## 3. 管理面与访问控制测试清单

### 3.1 管理 API 暴露

先使用不改变状态的请求确认网络可达性：

```bash
curl -i -sS "http://127.0.0.1:8081/"
```

`401`、`403` 或网络不可达通常符合未认证基线；`404` 或 `405` 只能证明路由存在，不能单独证明可写操作已受保护。

```text
[ ] 管理 API 是否只绑定受控管理网络或本地接口？
[ ] 未认证请求能否获得版本、模型列表、工作流或详细错误？
[ ] 认证是否由网关与服务端共同执行，而非仅依赖网络位置？
[ ] 普通业务账户能否访问管理路由？
[ ] GET、POST、PUT、DELETE 和批量接口是否采用一致授权？
[ ] URL 编码、大小写、尾斜杠和代理重写是否绕过路由策略？
[ ] 管理接口是否要求 MFA、短期凭据或受控工作负载身份？
[ ] 失败响应是否泄露文件路径、依赖版本、内部地址或调用栈？
[ ] 管理操作是否记录真实主体、来源、对象、旧值和新值？
```

### 3.2 模型提交、审批与部署权限

```text
[ ] 普通用户能否上传无害测试制品？
[ ] 模型提交者能否直接标记为 Approved 或 Production？
[ ] 审批者能否部署未经独立评估的版本？
[ ] 部署身份能否覆盖、删除或重新标记已批准版本？
[ ] 注册表管理员与生产部署管理员是否适当分离？
[ ] 跨项目、跨租户或跨环境能否引用其他主体的制品？
[ ] 回滚是否只能选择历史已批准摘要？
[ ] 紧急发布是否限时、双人审批并完整审计？
[ ] 服务账户凭据是否长期有效、共享或出现在配置与日志中？
[ ] 权限撤销后，现有 Token、Runner 和缓存凭据是否立即失效？
```

## 4. 注册表与模型制品完整性测试清单

### 4.1 不可变版本与来源

```text
[ ] 每个模型版本是否具有唯一、不可变标识？
[ ] 已批准版本能否被相同名称或标签静默覆盖？
[ ] 生产清单是否固定 digest，而不是使用 latest、main 或浮动别名？
[ ] 模型、Tokenizer、处理代码和配置是否作为同一受控制品集？
[ ] 来源仓库、构建任务、提交和训练运行是否可追溯？
[ ] 外部预训练模型是否固定版本、来源和摘要？
[ ] 从开发提升到生产时是否复制制品，还是重新从不可信来源下载？
[ ] 镜像、模型和依赖的信任策略是否覆盖所有部署入口？
```

### 4.2 摘要与签名阴性测试

使用合法结构但不可执行的测试制品，分别构造以下阴性条件：

```text
[ ] 文件内容改变 1 个无害字节，但部署清单仍保留旧摘要
[ ] 模型摘要正确，但 Tokenizer 或预处理器摘要错误
[ ] 文件具有摘要但没有可信签名
[ ] 签名存在但签名者不在当前环境的信任策略中
[ ] 签名有效但制品版本未获得生产批准
[ ] 元数据声明的摘要与实际下载内容不一致
[ ] 清单固定模型摘要，但容器镜像仍使用浮动标签
[ ] 使用过期、撤销或用途不匹配的签名身份
```

安全预期：

```text
下载可以发生
  -> 在任何解析、解压、反序列化或加载之前验证来源、摘要和签名
  -> 任一不匹配立即失败关闭
  -> 不自动改用本地旧文件、未签名版本或 latest
  -> 产生可关联告警与审计记录
```

### 4.3 存储与缓存写保护

```text
[ ] 生产读取身份是否没有模型仓库写权限？
[ ] 已批准对象是否启用版本控制、对象锁或等价不可变控制？
[ ] 共享卷是否允许其他 Pod、用户或作业修改模型文件？
[ ] 构建缓存、下载缓存和临时目录是否可被低权限主体污染？
[ ] 新实例启动时是否重新验证缓存文件摘要？
[ ] 节点本地缓存是否按租户、环境和模型版本隔离？
[ ] 文件权限、所有者和挂载选项是否阻止运行时覆盖？
[ ] 备份恢复是否保留原始摘要、签名与批准状态？
```

## 5. 远程拉取与 SSRF 测试清单

模型服务允许提交远程 URL 时，应把它当作 SSRF 与供应链入口。仅向自有测试接收器发送唯一 marker，不探测云元数据、内网管理面或第三方地址。

```text
[ ] 远程 URL 功能是否为业务必需，能否完全关闭？
[ ] URL 是否只允许 HTTPS 和明确批准的主机、端口及路径？
[ ] 是否拒绝 loopback、私网、链路本地、组播和保留地址？
[ ] DNS 解析前后是否检查目标地址，防止重绑定？
[ ] 每次重定向后是否重新执行协议、主机和地址校验？
[ ] 是否禁止 file、ftp、gopher、jar 等非预期协议？
[ ] 下载是否要求可信服务身份和正确证书验证？
[ ] 是否限制文件大小、类型、压缩比、下载时间和重定向次数？
[ ] 下载内容是否在解析前验证摘要、签名和批准状态？
[ ] URL、最终地址、摘要和验证结果是否写入审计日志？
```

无害回连验证成功只能证明服务器发起了请求；不能单独证明模型篡改或代码执行。只有未批准制品最终被部署或加载，才能判定交付链篡改成功。

## 6. CI/CD 与部署配置篡改测试清单

### 6.1 构建与发布流水线

```text
[ ] Pull Request 是否需要独立审查与受保护分支？
[ ] 未受信 Fork 的流水线是否能读取发布凭据？
[ ] CI Runner 是否隔离、短生命周期并在任务后清理？
[ ] 工作流依赖、Action、容器和安装脚本是否固定不可变版本？
[ ] 构建过程是否限制任意网络下载和未声明依赖？
[ ] 模型构建是否可复现或至少可验证关键输入与输出摘要？
[ ] 发布凭据是否短期、最小权限并绑定仓库、分支和环境？
[ ] 构建者能否绕过安全扫描、签名或审批步骤直接发布？
[ ] 安全门失败、超时或不可用时是否失败关闭？
[ ] 流水线日志是否防止凭据、模型 URL 和签名材料泄露？
```

### 6.2 部署清单与编排平台

```text
[ ] 低权限开发者能否修改生产模型 URI、digest 或启动参数？
[ ] Admission Policy 是否拒绝浮动镜像标签和未签名制品？
[ ] Pod 是否以非 root、只读根文件系统和最小能力运行？
[ ] 模型卷是否只读挂载，且写入 Pod 与读取 Pod 分离？
[ ] Secret 是否通过受控机制注入，而不是写入镜像或清单？
[ ] Namespace、ServiceAccount 和 NetworkPolicy 是否限制横向访问？
[ ] Sidecar、Init Container 和调试容器能否修改模型目录？
[ ] GitOps 控制器是否只接受受保护仓库和已签名提交？
[ ] 手工热修复是否会被检测、记录和自动纠正？
[ ] 灰度、蓝绿和回滚路径是否执行相同完整性门禁？
```

## 7. 加载前后与运行时篡改测试清单

### 7.1 加载前安全顺序

```text
[ ] 先验证来源与授权，再下载
[ ] 下载到隔离、不可执行、不可共享的临时位置
[ ] 先验证大小、格式、摘要和签名，再解析内容
[ ] 先完成静态审查，再进行受限加载
[ ] 仅批准的加载器和安全格式可进入生产路径
[ ] 验证失败时删除隔离副本并保留最小必要证据
[ ] 加载服务无 Shell、编译器和非必要网络能力
```

### 7.2 TOCTOU 与运行时完整性

```text
[ ] 校验完成到模型加载之间，文件能否被其他主体替换？
[ ] 校验与加载是否针对同一不可变文件句柄或对象版本？
[ ] 模型加载后，共享卷上的文件变化是否影响后续实例？
[ ] 热重载是否重新执行来源、签名、摘要和审批检查？
[ ] 自动扩容节点是否从相同不可变摘要启动？
[ ] 崩溃恢复是否会加载未验证的临时文件或旧缓存？
[ ] 运行时文件监控是否检测摘要、权限和所有者变化？
[ ] 容器内模型文件是否可被应用进程、插件或调试进程覆盖？
[ ] 检测到变化后是否隔离实例、停止流量并保留证据？
```

### 7.3 行为一致性验证

```text
[ ] 部署前后在固定合成基准集上比较输出与指标
[ ] 对关键类别、拒绝策略和安全边界执行定向回归
[ ] 使用独立 canary 输入检测已知行为标记
[ ] 比较模型结构、参数数量、层名、Tokenizer 和标签映射
[ ] 检查总体准确率正常但特定子集显著退化的情况
[ ] 检查置信度分布、错误模式和公平性指标的异常漂移
[ ] 行为测试结果与模型摘要、镜像摘要和部署 ID 关联
[ ] 行为异常时阻断推广，而不是只记录告警
```

行为测试不能替代密码学完整性验证；两者分别发现“文件是否被替换”和“模型行为是否异常”。

## 8. TorchServe / ShellTorch 场景安全验证清单

该场景由管理面暴露、远程 URL 拉取和不安全依赖组合而成。验证每个薄弱点即可证明风险，不需要制作恶意 WAR、YAML gadget 或 Java 执行载荷。

### 8.1 未授权管理面

```text
[ ] 从预期非管理网络发起无状态请求
[ ] 记录是否能连接 8081 或实际管理端口
[ ] 记录 HTTP 状态码、服务标识和错误详情
[ ] 未认证情况下只进行只读探测，不注册或删除模型
[ ] 验证防火墙、绑定地址、反向代理和服务端认证是否同时生效
```

### 8.2 远程 URL 拉取

```text
[ ] 使用自有测试接收器和唯一 SYNTHETIC_MDT marker
[ ] 只验证服务器是否发起单次 HTTP 请求
[ ] 不把目标设置为云元数据、管理面、数据库或第三方系统
[ ] 不提供可执行模型、归档、类文件或反序列化内容
[ ] 记录来源地址、请求路径、User-Agent、时间和关联 ID
[ ] 验证协议、主机、地址、重定向和下载内容门禁
```

### 8.3 依赖与反序列化风险

```text
[ ] 通过 SBOM、包清单或镜像扫描确认 TorchServe 与 SnakeYAML 版本
[ ] 对照组织认可的漏洞源和厂商修复状态
[ ] 检查工作流、模型和配置解析是否启用危险类型实例化
[ ] 使用普通无效 YAML 验证解析错误，不使用公开 gadget
[ ] 验证未知类型在任何类加载或网络访问前被拒绝
[ ] 确认模型服务进程无非必要出站网络、Shell 和写入权限
```

### 8.4 组合风险判定

```text
仅管理端口可达
  -> 管理面暴露，需要继续验证认证与写操作授权

无害接收器收到请求
  -> SSRF / 任意 URL 拉取成立，但尚未证明代码执行

存在已知易受攻击依赖
  -> 版本风险成立，但尚未证明漏洞可达或可利用

三项同时存在且未被中间控制阻断
  -> 高概率形成严重攻击链；立即修复，不需执行 RCE 作为证明
```

## 11. 根因审计清单

```text
[ ] 管理 API 是否默认暴露或仅依赖“应该只在本机”的假设？
[ ] 是否缺少提交、批准和部署职责分离？
[ ] 模型注册表是否允许覆盖、删除或复用已批准版本？
[ ] 生产是否使用 latest、分支名、模型名等可变引用？
[ ] 是否只校验传输 TLS，而不校验制品摘要和签名？
[ ] 摘要是否来自与制品相同、可被共同篡改的位置？
[ ] 是否只在训练结束时校验，而未在生产加载前重新校验？
[ ] 模型、Tokenizer、处理代码和配置是否未作为整体绑定？
[ ] 远程加载是否接受任意 URL、重定向或不受限协议？
[ ] 下载内容是否在完整性验证前被解析或反序列化？
[ ] CI/CD 是否使用长期、共享或跨环境凭据？
[ ] 构建依赖是否可变且允许未声明网络下载？
[ ] 模型服务框架、解析库和容器基础镜像是否长期未更新？
[ ] 共享卷、缓存、Init Container 或调试入口是否可修改模型？
[ ] 是否存在校验后替换的 TOCTOU 窗口？
[ ] 完整性失败时是否自动使用未验证缓存或旧版本？
[ ] 是否缺少固定行为基准、运行时完整性和异常漂移监控？
[ ] 审计是否无法关联训练、注册、批准、部署和运行实例？
```

## 12. 修复与回归清单

### 12.1 供应链与身份

```text
[ ] 模型仅从受控、认证、不可变的注册表进入生产
[ ] 提交、评估、批准和部署采用职责分离
[ ] 人员管理面使用 MFA，工作负载使用短期绑定身份
[ ] CI/CD、注册表和部署身份实施最小权限与环境隔离
[ ] 外部模型和依赖固定版本、来源、摘要并生成 SBOM
[ ] 安全更新覆盖模型服务框架、解析库、容器和编排平台
```

### 12.2 制品与部署门禁

```text
[ ] 模型、Tokenizer、代码、配置和镜像使用不可变 digest 绑定
[ ] 生产加载前验证批准状态、来源、签名和摘要
[ ] 验证发生在解析、解压、反序列化和加载之前
[ ] 远程 URL 默认关闭；必须使用时采用严格 allowlist 与 SSRF 防护
[ ] 禁止浮动标签、未签名制品和失败后自动降级
[ ] 模型卷只读，运行身份不能修改注册表与模型文件
[ ] 使用策略引擎阻断不合规部署，并在策略不可用时失败关闭
```

### 12.3 检测、响应与恢复

```text
[ ] 注册、覆盖、批准、拉取、校验、加载和回滚全程审计
[ ] 摘要、签名、权限和运行时文件变化触发实时告警
[ ] 固定合成基准集覆盖总体性能、关键子集和安全行为
[ ] 异常实例可隔离、停止流量并保留取证信息
[ ] 回滚只能指向历史已批准且可验证的摘要
[ ] 定期从干净环境演练重新部署与凭据轮换
[ ] 维护模型、镜像、数据和部署配置的完整血缘关系
```

### 12.4 修复后复测顺序

```text
1. 非管理网络与未认证主体无法访问管理 API
2. 普通用户不能上传、注册、批准、部署或回滚模型
3. 提交者不能批准自己的版本
4. 生产清单固定模型、镜像、处理代码和配置的不可变摘要
5. 摘要错误、未签名、错误签名者和未批准制品均在解析前拒绝
6. 远程 URL 仅允许批准来源，并阻断私网、重定向和非预期协议
7. 新实例、热更新、扩容、缓存恢复和回滚执行相同门禁
8. 模型卷只读，运行身份和其他工作负载不能修改模型文件
9. 固定合成基准集验证模型行为与批准版本一致
10. 日志可关联提交者、审批者、制品摘要、部署 ID 和运行实例
11. 验证服务不可用时部署失败关闭，不加载未验证缓存
12. 重放 MDT-01～MDT-22，确认所有绕过路径稳定阻断
```

## 13. 最终判定口径

```text
安全：生产只加载来自受控注册表、经过独立批准、具有可信签名和固定摘要的不可变制品；所有入口执行相同门禁并可审计回滚。

中风险：存在管理面信息暴露、可变引用或依赖过期，但未批准制品仍在加载前被稳定阻断。

高风险：未授权主体可以写注册表、修改部署引用、控制远程下载或让未签名/错误摘要制品进入加载阶段。

严重：未批准制品已进入生产，或管理面暴露、SSRF 与不安全反序列化等问题形成可达的服务器接管链。
```

## 14. 可复用考试代码块：ShellTorch SSRF 到 RCE 链

用途：授权靶场中 TorchServe / ShellTorch 暴露管理端口，可通过远程 workflow URL 拉取恶意归档并触发 Java 反序列化/类加载执行。


```bash
def initialize(self, context):
```

核心技术点：

```text
[ ] SSH -L 暴露远端管理端口到本地 8081
[ ] SSH -R 让目标从 127.0.0.1:8000 拉取攻击者 HTTP 服务
[ ] spec.yaml 使用 URLClassLoader 指向可控 HTTP 目录
[ ] Java SPI 文件 META-INF/services/javax.script.ScriptEngineFactory 指向 payload 类
[ ] workflow 导入触发 YAML/类加载链，最终获得反连 shell
```

一句话总结：**部署系统不能相信文件名、标签或下载成功；必须在每次生产加载前验证可信来源、独立批准、签名与不可变摘要，并让运行身份无法改写模型。**
