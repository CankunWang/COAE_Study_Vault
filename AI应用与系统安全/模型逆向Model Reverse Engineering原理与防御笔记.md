# 模型逆向（Model Reverse Engineering）原理与防御笔记

> 适用范围：AI 应用与系统安全学习、模型 API 威胁建模、授权安全测试和防御评估。所有实验应仅针对自有模型、课程靶场或明确授权环境；不得对第三方付费或生产 API 执行批量探测。

> 当前进度：已完成 Model Reverse Engineering 的概念、攻击链、企鹅分类案例、代码逻辑、评估口径、局限性与分层防御分析。

---

## 0. 一页速记

### 0.1 定义

模型逆向，也常称 Model Extraction 或 Model Stealing，是指攻击者反复查询一个可访问的模型服务，收集输入与输出，再训练一个替代模型（surrogate model），使其近似复现原模型的行为。

```text
自选输入 X_query
    ↓
查询目标模型 f_target
    ↓
收集输出 y_target = f_target(X_query)
    ↓
形成伪训练集 (X_query, y_target)
    ↓
训练替代模型 f_surrogate
    ↓
使 f_surrogate(x) ≈ f_target(x)
```

攻击者不一定需要：

- 目标模型权重；
- 模型架构；
- 原始训练集；
- 训练代码；
- 服务器内部访问权限。

只要能稳定查询接口并观察足够多的输出，就可能在黑盒条件下逼近目标模型的决策行为。

### 0.2 攻击者真正复制的是什么

严格来说，攻击者通常不是逐字节还原原始模型，而是在复制其可观察行为。

```text
参数完全相同      通常做不到，也往往没必要
架构完全相同      不一定
训练数据完全相同  不需要
输入输出行为接近  核心目标
```

因此“模型逆向”与“精确恢复模型文件”不能画等号。只要替代模型在目标输入分布上做出足够相似的预测，它就可能具有实际利用价值。

### 0.3 主要风险

| 风险 | 含义 |
|---|---|
| 知识产权损失 | 攻击者低成本复制商业模型能力 |
| 服务替代 | 用本地替代模型绕过按次计费或访问控制 |
| 边界探测 | 离线分析决策边界、阈值和薄弱区域 |
| 规避攻击辅助 | 在替代模型上生成可迁移的对抗样本 |
| 隐私攻击前置 | 更方便地研究目标行为，但不等于已恢复训练数据 |

### 0.4 一句话记忆

> 模型逆向不是“把服务器里的模型文件下载出来”，而是利用目标 API 给出的答案，为攻击者自己生成一套带标签训练数据，再训练一个行为近似的替代模型。

## 1. 为什么它属于 AI application / system 安全

数据投毒主要发生在训练数据或训练管线；模型逆向主要利用部署后的推理接口。

| 对比项 | 数据投毒 | 模型逆向 |
|---|---|---|
| 典型阶段 | 训练前或再训练时 | 部署与推理时 |
| 攻击者主要能力 | 修改数据、标签或管线 | 查询模型并观察输出 |
| 直接目标 | 改变目标模型学到的行为 | 复制目标模型的行为 |
| 核心安全属性 | 完整性、可用性 | 机密性、知识产权 |
| 常见后续影响 | 错误预测、后门 | 规避、服务替代、隐私研究 |

这说明 AI 系统上线后，即使：

- 模型权重未泄漏；
- 训练数据存储安全；
- 主机没有传统漏洞；
- API 只暴露正常预测功能；

仍可能通过合法功能的高频组合产生安全风险。这里被利用的是系统能力与信息反馈，而不是传统意义上的代码执行漏洞。

## 2. 威胁模型

### 2.1 攻击者能力

最基本的黑盒攻击假设是：

```text
攻击者能够：
✓ 构造输入
✓ 重复提交查询
✓ 观察模型输出
✓ 在本地训练自己的模型

攻击者不能：
✗ 读取目标权重
✗ 访问原训练数据
✗ 查看内部架构
✗ 登录目标服务器
```

现实中的攻击难度还取决于接口返回的信息量：

```text
仅返回类别标签
    < 返回 Top-k 类别
    < 返回置信度或概率
    < 返回完整 logits / embedding / explanation
```

一般而言，反馈越细，单次查询泄露的决策信息越多。但只返回标签也不能消除模型提取风险。

### 2.2 攻击目标

攻击者可能追求：

- 高总体一致性：替代模型在大多数输入上与目标模型相同；
- 高局部一致性：只逼近某个业务区域或目标类别；
- 边界恢复：重点定位分类边界；
- 成本替代：获得足够可用、但不必完全相同的廉价模型；
- 规避辅助：让替代模型足以生成可迁移攻击样本。

### 2.3 攻击成功需要哪些条件

```text
可查询接口
    +
足够查询预算
    +
与真实业务分布相关的输入
    +
可观察且相对稳定的输出
    +
适合任务的替代模型
    =
可能获得高行为一致性
```

如果查询样本远离真实输入分布，即使数量很多，获得的替代模型也可能没有实用价值。

## 3. 企鹅分类案例

### 3.1 目标任务

隐藏分类器根据两个数值特征区分 Adelie 和 Gentoo 企鹅：

```text
输入：
flipper_length  鳍肢长度，单位 mm
body_mass       体重，单位 g

输出：
Adelie 或 Gentoo
```

示例接口：

```text
GET /?flipper_length=150&body_mass=5000
→ {"result": "Adelie"}
```

### 3.2 为什么这个案例容易提取

- 只有两个输入特征；
- 只做二分类；
- 输入范围容易从常识或公开资料估计；
- 决策边界可能接近线性；
- 接口直接返回预测标签；
- 替代模型只需逼近低维决策边界。

这不能直接外推到所有复杂模型。高维图像、语音或 LLM 的完整行为面要大得多，查询和训练成本通常显著增加。

### 3.3 攻击流程

```text
确定合理输入范围
    ↓
在二维空间中采样点
    ↓
逐点查询目标 API
    ↓
把返回类别作为伪标签
    ↓
训练 Logistic Regression
    ↓
在独立查询集上评估一致性
```

## 4. 采样阶段

### 4.1 参数含义

```python
N_SAMPLES = 100

MIN_FLIPPER_LENGTH = 150
MAX_FLIPPER_LENGTH = 250

MIN_BODY_MASS = 2500
MAX_BODY_MASS = 6500
```

这些上下界不是模型内部秘密，而是攻击者用于限定查询空间的先验知识。

### 4.2 均匀随机采样

```python
import random
import pandas as pd

samples = {
    "Flipper Length (mm)": [],
    "Body Mass (g)": [],
}

for _ in range(N_SAMPLES):
    samples["Flipper Length (mm)"].append(
        random.uniform(MIN_FLIPPER_LENGTH, MAX_FLIPPER_LENGTH)
    )
    samples["Body Mass (g)"].append(
        random.uniform(MIN_BODY_MASS, MAX_BODY_MASS)
    )

samples_df = pd.DataFrame(samples)
```

每个随机点本来没有物种标签。目标 API 在这里充当了“标注器”：

```text
随机生成特征 x
    ↓
目标模型返回 f_target(x)
    ↓
把 f_target(x) 当作训练标签
```

### 4.3 为什么先验范围重要

如果完全不知道输入分布而盲目采样：

- 大量查询可能落在无效区域；
- 接口可能拒绝异常值；
- 样本无法覆盖真实用户输入；
- 替代模型只学到无意义的外推行为；
- 查询预算被浪费。

因此有效样本数量比总查询数量更重要。

### 4.4 均匀随机采样的局限

均匀采样简单，但可能把大量查询浪费在远离决策边界的区域。更强的攻击会使用主动学习思想：

```text
先少量粗采样
    ↓
训练初始替代模型
    ↓
找出预测最不确定或靠近边界的区域
    ↓
在这些区域追加查询
    ↓
反复更新替代模型
```

防御评估时不能只测试固定频率的均匀扫描，还要考虑这种自适应查询模式。

## 5. 获取伪标签

原材料的核心逻辑是逐条请求目标服务并保存 `result`：

```python
predicted_labels = []

for i in range(N_SAMPLES):
    query = {
        "flipper_length": samples["Flipper Length (mm)"][i],
        "body_mass": samples["Body Mass (g)"][i],
    }

    # 仅可用于自有服务、课程靶场或明确授权环境。
    response = requests.get(CLASSIFIER_URL, params=query, timeout=5)
    response.raise_for_status()
    predicted_labels.append(response.json()["result"])
```

需要注意：

- 使用 `response.json()`，不必先取 `.text` 再 `json.loads()`；
- 设置超时，避免请求无限等待；
- 调用 `raise_for_status()`，不要把错误页当作正常 JSON；
- 验证返回字段和类别是否在允许集合内；
- 记录失败、重试与实际成功查询数；
- 正式测试必须遵守授权范围与速率上限。

获得的数据实际是：

```text
X_train_surrogate = 攻击者生成的输入
y_train_surrogate = 目标模型输出
```

这里的 `y_train_surrogate` 不是现实世界真值，而是目标模型的答案。若目标模型本身预测错误，替代模型可能连这些错误一起学习。

## 6. 训练替代模型

```python
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

surrogate_model = make_pipeline(
    StandardScaler(),
    LogisticRegression(),
)

surrogate_model.fit(
    samples_df,
    predicted_labels,
)
```

### 6.1 为什么使用 StandardScaler

两个特征量纲差异较大：

```text
flipper length：约 150–250
body mass：      约 2500–6500
```

标准化将不同尺度的特征转换到相近数值范围，有利于优化过程和正则化解释。

### 6.2 为什么 Logistic Regression 可行

若目标模型决策边界近似线性：

$$
w_1x_1+w_2x_2+b=0
$$

Logistic Regression 能用相对少的样本逼近它。替代模型不必与目标模型采用同一架构，只要其函数空间足以近似目标行为。

### 6.3 原材料中的形状细节

原材料把标签构造成单列 DataFrame：

```python
predictions_df = pd.DataFrame({"species": predicted_labels})
```

对单输出分类，scikit-learn 通常更适合接收一维标签：

```python
y_surrogate = pd.Series(predicted_labels, name="species")
surrogate_model.fit(samples_df, y_surrogate)
```

这样语义更清楚，也避免把任务误解为多输出分类。

## 7. 最容易混淆的评估口径

### 7.1 Fidelity：模型一致性

模型提取首先应衡量替代模型与目标模型是否一致：

$$
\text{Fidelity}
=
\frac{1}{N}
\sum_{i=1}^{N}
\mathbb{1}
\left[
f_{\text{surrogate}}(x_i)
=
f_{\text{target}}(x_i)
\right]
$$

它回答：

> 替代模型在多少输入上复制了目标模型的答案？

### 7.2 Task Accuracy：对真实标签的准确率

若另有独立真实标签 \(y_i\)，才可以计算：

$$
\text{Task Accuracy}
=
\frac{1}{N}
\sum_{i=1}^{N}
\mathbb{1}
\left[
f_{\text{surrogate}}(x_i)
=
y_i
\right]
$$

它回答：

> 替代模型在真实任务上有多准确？

### 7.3 两者不能混为一谈

```text
高 Fidelity
≠ 一定高真实准确率
≠ 恢复了原始权重
≠ 恢复了原始训练集
```

如果目标模型本身有偏差或错误，替代模型忠实复制这些错误时，Fidelity 可以很高，但真实准确率未必高。

原材料中实验端返回的 `accuracy: 0.9854`，若测试标签来自隐藏目标模型，应解释为约 `98.54%` 的行为一致性；只有评分端使用独立真实物种标签时，才是任务准确率。仅凭展示的返回字段名 `accuracy` 无法确定其语义。

### 7.4 推荐评估设计

```text
查询训练集：用于训练替代模型
独立查询测试集：用于计算 Fidelity
独立真实标签集：可选，用于计算 Task Accuracy
边界附近测试集：用于检查局部逼近质量
分布外测试集：用于观察外推差异
```

禁止使用训练时已经查询过的点作为唯一评估集，否则会高估提取质量。

## 8. 为什么 100 个点就可能达到高一致性

本案例具备：

- 二维；
- 二分类；
- 输入范围明确；
- 边界较简单；
- 采样覆盖较好；
- 替代模型与目标函数形式可能相近。

线性二分类器的决策边界只需要少量参数：

$$
w_1x_1+w_2x_2+b=0
$$

只要查询点分布在边界两侧，替代模型就能迅速估计边界位置。

这不意味着：

```text
100 次查询可以复制任意 AI 模型
100 次查询足以复制 LLM
98% 一致性意味着所有输入都相同
```

复杂任务的输入维数、类别数、输出空间、随机性和上下文依赖都会显著增加提取难度。

## 9. 与其他攻击的区别

| 攻击 | 攻击者要知道什么 | 主要输出 |
|---|---|---|
| 模型逆向/提取 | 大量输入输出关系 | 行为相似的替代模型 |
| 模型反演 | 模型输出或内部信息 | 某类典型特征或敏感属性重建 |
| 成员推断 | 模型对样本的响应差异 | 某条数据是否参与训练 |
| 对抗样本 | 模型或替代模型的边界信息 | 导致错误预测的特制输入 |
| 权重窃取 | 模型文件或内存访问 | 原始参数或模型制品 |

可能的组合链：

```text
模型提取
    ↓
本地分析替代模型
    ├─ 生成可迁移对抗样本
    ├─ 推测敏感边界
    └─ 辅助其他隐私攻击
```

但必须避免过度推断：

> 获得高一致性的替代模型，只说明目标行为被较好逼近，不自动证明原训练数据已经泄漏。

## 10. 检测思路

模型逆向查询通常看起来像正常预测请求，因此单条请求很难定性。检测更依赖活动级关联。

### 10.1 可疑信号

- 单个主体在短期内查询量异常高；
- 查询输入系统性覆盖整个特征空间；
- 数值输入呈网格、均匀随机或边界搜索分布；
- 连续查询围绕预测变化点逐步收敛；
- 多个账户、IP 或 API key 表现出协同采样；
- 查询与正常业务分布明显不同；
- 大量请求只关心预测结果，没有正常后续业务行为；
- 命中限速后持续切换身份或重试。

### 10.2 不能单靠请求量

合法批处理客户也可能有高查询量；高级攻击者也可能低速长期采样。因此需要组合：

```text
身份与账户历史
    +
查询速率
    +
输入空间覆盖模式
    +
业务工作流上下文
    +
跨账户关联
```

## 11. 分层防御

### 11.1 访问控制

- 对高价值模型要求身份认证；
- 按租户、用户、API key 和组织实施配额；
- 将免费试用与生产级访问隔离；
- 对批量接口单独授权；
- 撤销泄漏或滥用的凭据。

### 11.2 速率与预算控制

- 每秒、每分钟和每日多时间窗限速；
- 限制累计查询预算；
- 对持续高覆盖采样动态收紧配额；
- 对多账户协同使用组织级和设备级关联；
- 对异常行为进入冷却或人工复核。

限速的价值是提高时间和经济成本，不是绝对阻止模型提取。

### 11.3 最小化输出

根据业务需要只返回必要信息：

- 不需要时不返回完整概率向量；
- 不暴露 logits、embedding 或调试解释；
- 对精度进行业务允许范围内的裁剪；
- 错误响应不泄露内部模型结构和阈值。

但不能简单认为“只返回类别标签就安全”，因为硬标签仍可用于训练替代模型。

### 11.4 行为检测

- 建立正常业务查询分布基线；
- 检测网格扫描、随机覆盖与边界收敛；
- 关联账户、IP、设备和组织；
- 检查请求与后续业务动作是否匹配；
- 保存可审计的模型版本、请求和响应摘要。

### 11.5 模型与业务架构

- 将最敏感决策留在服务端；
- 避免把高价值中间表示直接暴露给客户端；
- 对不同用户群体采用分层能力；
- 对关键结果加入规则、人工或第二模型复核；
- 为高价值模型准备提取风险测试与响应流程。

### 11.6 输出扰动的权衡

向概率中加入噪声或降低精度可能增加提取难度，但也可能：

- 伤害正常用户；
- 破坏概率校准；
- 影响下游决策；
- 被多次查询平均掉；
- 只改变成本而不消除风险。

因此应先定义业务允许的效用下降，再评估真实防御收益。

## 12. 防御评估实验

授权测试不应以“能否完全阻止所有提取”为唯一目标，而应回答：

```text
攻击者达到目标 Fidelity 需要多少查询？
达到目标 Fidelity 需要多长时间？
需要多少账户或成本？
检测系统在第多少次查询时告警？
限速对合法批处理用户造成多少影响？
输出最小化使攻击成本增加了多少？
```

### 12.1 推荐指标

| 指标 | 含义 |
|---|---|
| Query Budget | 达到目标一致性所需查询数 |
| Fidelity | 替代模型与目标模型的一致率 |
| Boundary Fidelity | 边界附近的一致率 |
| Detection Rate | 模拟提取活动被发现的比例 |
| Time to Detect | 活动开始到首次可靠告警的时间 |
| Benign False Positive Rate | 合法用户被误报的比例 |
| Utility Impact | 防御对正常预测质量的影响 |
| Cost Amplification | 防御使攻击成本增加的倍数 |

### 12.2 安全测试边界

```text
[ ] 测试目标属于自有系统或有明确授权
[ ] 使用独立测试账户和测试模型版本
[ ] 明确最大查询数、速率和持续时间
[ ] 不使用真实客户数据
[ ] 不绕过第三方计费、认证或限速
[ ] 不从测试环境向真实业务触发下游动作
[ ] 保存请求清单、模型版本和停止条件
[ ] 测试结束后清理临时模型与数据
```

## 13. 原材料代码查漏点

### 13.1 缺少随机种子

`random.uniform()` 未固定 seed，导致每次采样不同。学习实验应记录：

```python
SEED = 1337
random.seed(SEED)
```

正式评估还应运行多个 seed，报告均值与波动，而不是只展示一次结果。

### 13.2 请求缺少健壮性处理

原代码没有超时、HTTP 状态检查、返回 schema 验证和失败重试记录。网络错误可能产生 `None` 标签并污染训练集。

### 13.3 标签形状可以更清楚

单列 DataFrame 应改为一维 Series 或数组，避免多输出语义。

### 13.4 评估集来源不清

必须说明评分端的“accuracy”究竟比较：

```text
替代模型 vs 目标模型输出  → Fidelity
替代模型 vs 独立真实标签  → Task Accuracy
```

### 13.5 上传模型文件存在信任边界

实验接口允许上传 `joblib` 模型。`joblib` 通常依赖 pickle 语义，服务端若直接反序列化不可信文件，会引入模型文件反序列化风险。

安全的课程或生产评估端应考虑：

- 在一次性、无凭据、低权限沙箱中解析；
- 禁止网络访问；
- 限制 CPU、内存、磁盘和执行时间；
- 使用受控格式或服务端重训协议；
- 任务结束后销毁隔离环境。

这个细节把本节与“AI 模型供应链安全”连接起来：为了评估模型逆向而开放模型上传端点，不能反过来制造任意代码执行入口。

## 14. 记忆卡片

### Q1：模型逆向必须知道原模型架构吗？

不需要。黑盒攻击可以仅依赖输入与输出训练替代模型。

### Q2：替代模型必须与目标模型使用相同算法吗？

不需要。只要替代模型适合任务并能逼近目标行为即可。

### Q3：高 Fidelity 是否表示恢复了原始模型权重？

不是。它只表示在给定评估输入上行为相似。

### Q4：为什么输入先验知识很重要？

它能让有限查询集中在真实、有效和高价值的输入区域。

### Q5：为什么边界附近样本特别有价值？

远离边界的样本通常只重复确认明显类别；边界附近样本能更精确地约束决策边界位置。

### Q6：只返回标签能否阻止模型提取？

不能保证。它减少了单次响应的信息量，但标签仍可作为替代模型的伪标签。

### Q7：限速能否完全解决问题？

通常不能。它主要增加攻击时间和成本，还可能被低速长期或多账户查询绕过。

### Q8：模型提取与模型反演相同吗？

不同。提取主要复制模型行为；反演主要尝试重建类别特征或敏感信息。两者可能组合，但不能混称。

### Q9：原案例的 98.54% 应如何解释？

先确认评分端标签来源。若比较的是隐藏模型输出，它是 Fidelity；若比较的是独立真实标签，它才是任务准确率。

### Q10：最有效的防御思路是什么？

没有单一开关。应组合身份与配额、输出最小化、活动级异常检测、跨账户关联、最小权限和事件响应。

## 15. 最终总结

模型逆向利用的是部署模型不断回答问题所产生的信息泄露。攻击者自行生成输入，让目标模型为这些输入“打标签”，再用得到的输入输出对训练替代模型。

```text
模型保密
≠ 权重文件没有公开就足够

模型提取风险
= 可查询性
+ 单次响应的信息量
+ 累计查询预算
+ 输入分布先验
+ 攻击者的自适应采样能力
```

企鹅案例之所以能用 100 个样本取得很高一致性，是因为任务低维、边界简单且输入范围明确。真正应该掌握的不是某段固定代码，而是以下逻辑：

```text
定义威胁模型
→ 构造有效查询
→ 收集目标输出
→ 训练行为替代模型
→ 用独立数据区分 Fidelity 与真实准确率
→ 评估查询成本、检测能力和正常用户影响
→ 采用分层控制提高攻击成本并缩小泄露面
```

## 16. 可复用考试代码块：黑盒模型提取

用途：目标提供预测接口，并要求提交一个替代模型达到指定准确率或一致性。

```bash
pip install pandas scikit-learn joblib requests
```

```python
import json
import random
import requests
import pandas as pd
import joblib
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

TARGET = "http://STMIP:STMPO/"
N = 300

RANGES = {
    "Flipper Length (mm)": (150, 250),
    "Body Mass (g)": (2500, 6500),
}

api_map = {
    "Flipper Length (mm)": "flipper_length",
    "Body Mass (g)": "body_mass",
}

samples = {name: [random.uniform(lo, hi) for _ in range(N)] for name, (lo, hi) in RANGES.items()}
X = pd.DataFrame(samples)

y = []
for i in range(N):
    params = {api_map[col]: X[col][i] for col in X.columns}
    r = requests.get(TARGET, params=params, timeout=10)
    y.append(json.loads(r.text)["result"])

model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X, y)

joblib.dump(model, "student.joblib")
with open("student.joblib", "rb") as f:
    resp = requests.post(TARGET + "model", files={"file": ("student.joblib", f)}, timeout=30)

print(resp.text)
```

核心技术点：

```text
[ ] 用目标 API 给自造样本打标签
[ ] 本地训练 surrogate model
[ ] 上传模型文件触发评分
[ ] 增大 N 或换模型可提升一致性
[ ] 特征名必须匹配评分端训练/推理字段
```

一句话总结：

> 防御模型逆向的核心不是假设 API 不会被反复调用，而是限制每个主体可累计获得的信息，识别跨请求的系统性采样行为，并让攻击者达到可用替代模型所需的成本显著上升。
