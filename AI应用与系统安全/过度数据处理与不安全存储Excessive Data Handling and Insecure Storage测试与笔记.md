# 过度数据处理与不安全存储测试清单与学习笔记

> 适用范围：AI/ML 应用、LLM 聊天系统、训练与推理数据管线、日志平台、向量数据库、对象存储、备份和分析系统的授权安全评估。仅使用合成数据与专用测试账户；不得收集、下载或传播真实个人信息、医疗信息、支付数据、凭据或生产训练数据。

## 0. 核心判断

```text
过度数据处理（Excessive Data Handling）
  = 收集、传输、推理、记录、保留或共享了完成业务目标并不需要的数据

不安全存储（Insecure Storage）
  = 数据虽有业务必要性，但其存储位置、访问控制、加密、隔离、保留或删除机制不足

风险链
  = 收集过多 -> 复制到更多系统 -> 保存过久 -> 任一存储点暴露 -> 泄露影响被放大
```

不能只证明“存在公开数据库文件”。完整结论需要回答：

```text
收集了什么？是否必要？
数据流经哪里？形成了多少副本？
谁能访问？使用什么可信身份授权？
是否以明文出现在日志、缓存、备份或模型上下文？
保存多久？用户请求删除后是否从全部副本移除？
漏洞能暴露哪些合成数据，影响范围如何？
```

## 0.1 进入靶场后的 5 分钟路线

### 第 1 分钟：建立数据最小化基线

```text
[ ] 写明应用的主要业务目的
[ ] 列出完成该目的所需的最少字段
[ ] 标记身份、位置、医疗、支付、凭据和生物特征等敏感类别
[ ] 准备与真实数据格式相似但不可用于真实身份或支付的合成 marker
```

### 第 2 分钟：观察应用主动索取的数据

```text
[ ] 记录注册页、聊天框、上传页和 API 要求的字段
[ ] 记录哪些字段为必填、选填或由模型主动追问
[ ] 对照业务目的判断每个字段是否必要
[ ] 检查是否提供用途、保留时间和共享范围说明
```

### 第 3 分钟：定位数据落点

```text
[ ] 浏览器请求与响应
[ ] 应用数据库和文件系统
[ ] LLM 对话历史与编排日志
[ ] 向量数据库、缓存和临时文件
[ ] 训练集、微调集、评估集和特征存储
[ ] 分析平台、监控平台、备份和第三方服务
```

### 第 4 分钟：检查低成本暴露路径

```text
[ ] 未认证静态文件与目录
[ ] 可猜测的 .db、.sqlite、.sql、.bak、.log、.json 和归档文件
[ ] 对象存储公开读取或目录列举
[ ] 普通用户读取其他用户的历史记录
[ ] API 过度返回、错误堆栈和调试端点
```

### 第 5 分钟：证明影响但不接触真实数据

```text
[ ] 仅查找自己预先写入的 SYNTHETIC_MARKER
[ ] 记录响应头、状态码、对象 ID、字段名和访问控制结果
[ ] 不打开、复制或保存与测试无关的真实记录
[ ] 一旦发现真实敏感数据，立即停止扩大读取并按授权流程报告
```

## 1. 测试变量与合成数据

### Linux / macOS

```bash
export LAB_URL="http://127.0.0.1:5000"
export EDH_MARKER="SYNTHETIC_EDH_$(date +%Y%m%d_%H%M%S)"
export TEST_USER="edh-test-user"
```

### Windows PowerShell

```powershell
$LabUrl = "http://127.0.0.1:5000"
$EdhMarker = "SYNTHETIC_EDH_$(Get-Date -Format yyyyMMdd_HHmmss)"
$TestUser = "edh-test-user"
```

合成数据要求：

```text
[ ] 姓名、地址、病情、订单和支付信息均为明确虚构内容
[ ] 支付字段使用系统提供的测试 token，不使用自行构造或真实卡号
[ ] 每个字段带唯一 marker，便于追踪其复制与删除情况
[ ] marker 不包含邮箱凭据、API Key、Cookie、Token 或内部地址
[ ] 建立“字段 -> 写入入口 -> 预期存储位置 -> 预期删除时间”表
```

## 3. Excessive Data Handling 测试清单

### 3.1 收集必要性

```text
[ ] 每个收集字段是否对应明确、当前、可验证的业务目的？
[ ] 删除该字段后，核心功能是否仍能完成？
[ ] 推荐商品是否真的需要医疗信息，还是普通偏好已足够？
[ ] 下单是否应跳转合规支付流程，而不是让聊天框接收支付数据？
[ ] 模型是否主动追问用户未提出且任务不需要的敏感信息？
[ ] 是否把选填字段伪装成必填字段？
[ ] 是否收集完整值，而部分值、范围、布尔值或 token 已足够？
[ ] 是否默认收集 IP、精确位置、设备指纹或完整 User-Agent？
[ ] 未登录用户的数据是否与账户长期关联？
[ ] 拒绝提供非必要字段后，用户是否仍可使用核心功能？
```

### 3.2 模型上下文与工具参数最小化

```text
[ ] 每次推理是否只发送完成当前任务所需的历史消息？
[ ] 是否把完整用户资料拼入所有 Prompt？
[ ] 工具只需要订单状态时，是否仍返回地址、医疗或支付字段？
[ ] RAG 检索是否返回超过答案所需的文档片段和元数据？
[ ] 是否在模型可见上下文中包含内部 ID、权限信息或秘密字段？
[ ] 多租户数据是否在检索前完成租户过滤？
[ ] 是否先在服务端裁剪和脱敏，再把数据发送给模型？
[ ] 第三方模型或插件是否收到超出其功能需要的字段？
[ ] 摘要、Embedding 或分类任务是否仍发送完整原文？
[ ] 模型拒绝回答后，输入是否仍被不必要地长期保存？
```

### 3.3 日志与分析最小化

```text
[ ] 原始 Prompt 和 Response 是否默认完整记录？
[ ] 日志是否包含 Authorization、Cookie、API Key 或会话标识？
[ ] 支付、医疗、身份和定位字段是否在写日志前脱敏？
[ ] 脱敏发生在客户端、应用层还是日志平台接收之后？
[ ] Debug 模式是否增加敏感字段或完整请求体记录？
[ ] Trace、APM、错误报告和会话回放是否形成额外副本？
[ ] 分析用途是否可使用聚合值、哈希值或匿名化数据？
[ ] 日志采样是否仍可能收集完整敏感会话？
[ ] 员工是否能通过搜索平台读取非工作所需的完整对话？
[ ] 用户撤回同意后，后续分析收集是否停止？
```

### 3.4 数据用途与共享边界

```text
[ ] 为提供服务收集的数据是否被自动用于训练或广告画像？
[ ] 训练、评估、人工审核和产品分析是否分别取得适当授权？
[ ] 隐私说明中的用途是否与实际数据流一致？
[ ] 第三方接收方、地区和保留设置是否可追踪？
[ ] 更换模型提供商时是否重新评估字段必要性？
[ ] 插件只能看到其任务所需的数据子集吗？
[ ] 数据导出是否包含未声明的派生字段、标签或评分？
[ ] 匿名化数据能否通过稳定 ID、稀有属性或外部数据重新识别？
```

## 4. Insecure Storage 测试清单

### 4.1 Web 根目录与静态文件暴露

先请求已知公共页面建立基线，再检查授权范围内的常见备份扩展名。目录枚举仅用于靶场或明确授权目标，并限制并发和请求速率：

```bash
gobuster dir \
  -u "http://127.0.0.1:5000/" \
  -w /path/to/authorized-small-wordlist.txt \
  -x db,sqlite,sql,bak,log,json,txt \
  -t 2 --delay 250ms
```

发现疑似数据文件时，先检查响应元数据：

```bash
curl -sS -I "http://127.0.0.1:5000/storage.db"
```

测试清单：

```text
[ ] 未认证请求是否返回 200、206 或可缓存的数据响应？
[ ] HEAD 与 GET 的授权策略是否一致？
[ ] 是否允许目录列举、Range 下载或通过大小判断文件存在？
[ ] 数据库、日志、备份和导出文件是否位于 Web 可访问目录？
[ ] 文件名是否固定、可猜测或暴露在 robots.txt、源码和错误中？
[ ] Content-Type、Content-Disposition 和缓存头是否适当？
[ ] CDN、反向代理和旧部署版本是否仍缓存已删除文件？
[ ] URL 参数、大小写、编码、尾点或备份后缀能否绕过规则？
[ ] 未认证与低权限账户的响应是否真正不同？
[ ] 修复后原 URL、缓存 URL 和历史版本是否全部失效？
```

若响应可能包含真实数据，不要直接下载。优先由系统所有者提供净化副本，或让目标方在服务器端确认文件类型、字段结构和测试 marker。

### 4.2 存储访问控制

```text
[ ] 数据库、对象存储、文件共享和备份是否默认拒绝访问？
[ ] 应用、分析、训练和管理员是否使用不同服务身份？
[ ] 普通用户能否访问其他用户的对话、导出或上传文件？
[ ] 对象级授权是否基于服务端可信身份，而非请求中的 user_id？
[ ] 多租户是否在数据库查询、对象路径和向量检索层强制隔离？
[ ] 是否存在共享管理员凭据、永久访问密钥或匿名链接？
[ ] 服务账户能否读取超出其任务需要的表、Bucket 或前缀？
[ ] 开发、测试和分析环境是否复制生产敏感数据？
[ ] 离职、角色变化和项目结束后，访问权限是否及时撤销？
[ ] 紧急访问是否限时、审批并完整审计？
```

### 4.3 静态、传输与密钥保护

```text
[ ] 客户端到应用、应用到模型、应用到存储是否使用受支持的 TLS？
[ ] 数据库、磁盘、对象和备份是否启用静态加密？
[ ] 高敏感字段是否采用字段级加密、Tokenization 或不可逆处理？
[ ] 密钥是否与密文分离，并由受控密钥服务管理？
[ ] 不同环境、租户或敏感级别是否使用适当的密钥隔离？
[ ] 密钥轮换后，旧副本和备份是否仍可按策略解密？
[ ] 日志、缓存、临时文件和崩溃转储是否绕过加密要求？
[ ] 导出与下载文件是否获得与源数据相同的保护？
[ ] 加密是否只防介质丢失，却无法阻止过宽应用权限？
[ ] 密钥访问和解密操作是否记录主体、目的、时间和结果？
```

### 4.4 保留、删除与副本一致性

```text
[ ] 每类原始数据、派生数据和日志是否有明确保留期限？
[ ] 到期删除是否自动执行并可审计？
[ ] 用户删除对话后，主库、搜索索引、向量库和缓存是否同步删除？
[ ] 训练集、评估集、导出、备份和第三方副本如何处理删除请求？
[ ] 软删除数据是否仍可被普通查询、模型或员工工具读取？
[ ] 临时文件、上传分片和失败任务中间结果是否按时清理？
[ ] 删除操作是否验证对象所有权并防止越权删除？
[ ] 法定保留或安全冻结是否有明确范围、审批和解除流程？
[ ] 备份到期后是否真正销毁，而非无限追加？
[ ] 删除证明是否记录对象、范围、时间、执行系统和失败项？
```

### 4.5 ML 专有数据与衍生物

```text
[ ] 训练语料是否保留来源、授权、用途和保留记录？
[ ] 数据清洗前后的副本是否采用相同访问控制？
[ ] Embedding、特征、标签和摘要是否仍可能泄露原始敏感信息？
[ ] 向量库是否按租户、用途和敏感级别隔离？
[ ] Checkpoint、Adapter 和缓存是否可能记忆训练样本？
[ ] Prompt 缓存、KV Cache 或批处理文件是否跨用户复用？
[ ] 人工标注界面是否最小化显示并禁止不受控导出？
[ ] 评估数据和失败案例库是否包含完整用户对话？
[ ] 数据血缘能否追踪某条测试 marker 进入了哪些模型工件？
[ ] 删除原始记录后，是否评估重训、反学习或停止使用受影响模型？
```

## 5. Pixel Forge 场景测试清单

### 5.1 聊天机器人数据最小化

```text
[ ] 用普通商品偏好请求推荐，记录完成任务所需字段
[ ] 观察机器人是否主动询问具体疾病或诊断信息
[ ] 使用明确虚构的病情 marker 测试是否进入对话历史
[ ] 尝试拒绝提供病情，确认推荐功能是否仍可使用
[ ] 请求下单，确认机器人是否要求在聊天框输入支付数据
[ ] 确认支付流程是否转交专用支付页面或测试 token 流程
[ ] 检查工具调用是否携带与推荐或下单无关的敏感字段
[ ] 检查响应、历史、日志和导出中是否复制完整输入
```

### 5.2 `storage.db` 暴露验证

```text
[ ] 未登录访问 `/storage.db`，仅记录状态码与响应头
[ ] 使用错误路径建立 404 阴性对照
[ ] 验证普通用户和管理员访问策略是否符合预期
[ ] 不下载包含未知真实数据的文件
[ ] 由系统所有者在服务器端搜索预置 SYNTHETIC_MARKER
[ ] 记录数据库是否包含 user_id、IP、query、response 等字段
[ ] 确认聊天原文是否被完整保存，是否存在脱敏
[ ] 追踪同一 marker 是否进入日志、备份、分析或训练管线
[ ] 修复后验证 Web 根目录、CDN 缓存和旧版本均不可访问
```

成功信号：

```text
未认证或越权主体能够读取数据库、日志、备份或导出文件
或
应用保存了完成业务目标不需要的敏感字段，且该字段可在存储、日志或下游副本中验证
```

## 6. 快速测试用例表

| 编号 | 目的 | 安全操作 | 漏洞信号 |
|---|---|---|---|
| EDH-01 | 字段必要性 | 拒绝提供非必要合成字段 | 核心功能被不合理阻断或持续索取 |
| EDH-02 | 模型主动追问 | 请求普通商品推荐 | 主动索取医疗、支付等非必要信息 |
| EDH-03 | 上下文最小化 | 检查一次推理的字段集合 | 发送完整资料或无关历史 |
| EDH-04 | 工具最小化 | 查询单一测试订单状态 | 工具返回无关敏感字段 |
| EDH-05 | 日志最小化 | 提交唯一合成 marker | 原始敏感格式进入多类日志 |
| EDH-06 | 用途限制 | 检查测试会话数据流 | 未经预期进入训练、分析或第三方 |
| EDH-07 | 保留期限 | 等待测试保留期后查询 marker | 到期后仍在活动存储中可用 |
| EDH-08 | 删除传播 | 删除测试会话并追踪 marker | 缓存、索引或下游副本继续可读 |
| IS-01 | 公开数据文件 | 未认证 HEAD 请求已知测试文件 | 返回成功或可推断文件存在 |
| IS-02 | 备份文件发现 | 低速枚举授权靶场扩展名 | 数据库、日志或备份可公开读取 |
| IS-03 | 对象级授权 | 用户 A 请求用户 B 的测试对象 | 越权读取成功 |
| IS-04 | 租户隔离 | 跨测试租户查询 marker | 返回其他租户数据 |
| IS-05 | 静态加密 | 审查存储与密钥配置 | 敏感存储或备份为明文 |
| IS-06 | 日志与临时文件 | 搜索自有 marker | 未受控副本出现在日志或临时目录 |
| IS-07 | 软删除 | 删除后通过正常入口查询 | 已删除内容仍可被模型或用户读取 |
| IS-08 | 备份删除 | 到期后检查测试备份目录 | 超期副本仍保留或可恢复 |
| IS-09 | 第三方存储 | 核对模型和插件保留设置 | 保留范围超过声明或无法删除 |
| IS-10 | 修复回归 | 重放全部 EDH/IS 用例 | 暴露路径或过度处理仍可复现 |

## 8. 根因审计清单

```text
[ ] 是否缺少数据分类、数据流图和存储资产清单？
[ ] 产品需求是否把“将来可能有用”作为无限收集理由？
[ ] 是否没有逐字段的目的、合法依据、保留期限和责任人？
[ ] 模型调用是否默认携带完整用户资料与对话历史？
[ ] 工具/API 是否使用宽字段查询或返回完整数据库对象？
[ ] 原始 Prompt、Response 和请求体是否默认完整记录？
[ ] 数据文件是否被构建或部署流程复制到 Web 根目录？
[ ] 数据存储是否默认公开、共享凭据或缺少对象级授权？
[ ] 加密密钥是否与密文同位置、长期不轮换或访问过宽？
[ ] 临时文件、缓存、索引和备份是否没有统一生命周期？
[ ] 删除请求是否只修改主库状态，而未传播到下游副本？
[ ] 生产数据是否直接复制到开发、测试或分析环境？
[ ] 第三方模型、插件和标注服务是否缺少数据范围限制？
[ ] 是否无法通过数据血缘追踪某条记录的全部副本？
[ ] 是否缺少对未认证访问、跨用户和跨租户访问的自动化回归？
```

## 9. 修复与回归清单

### 9.1 数据最小化

```text
[ ] 删除与当前业务目的无关的字段和模型追问
[ ] 用范围、布尔值、别名、Token 或聚合值替代完整敏感值
[ ] 在发送给模型、插件或日志系统前完成字段裁剪与脱敏
[ ] 将支付等高敏感流程迁移到专用、合规且隔离的处理通道
[ ] 训练、分析和人工审核采用独立授权与退出机制
[ ] 对匿名化结果执行重识别风险评估
```

### 9.2 安全存储

```text
[ ] 数据库、备份和日志移出 Web 根目录并默认拒绝访问
[ ] 采用服务端工具级、对象级和租户级授权
[ ] 按角色和工作负载拆分服务身份并实施最小权限
[ ] 传输、静态和必要的字段级保护覆盖全部副本
[ ] 密钥集中管理、轮换、限权并审计解密操作
[ ] 日志、缓存、临时文件、导出和备份纳入统一安全基线
[ ] 为每类数据设置自动保留、删除、失败告警和删除证明
[ ] 清除 CDN、代理、对象版本和历史部署中的旧副本
```

### 9.3 修复后复测顺序

```text
1. 核心业务在不提供非必要敏感字段时仍正常工作
2. 模型不再主动索取与任务无关的医疗或支付信息
3. 推理上下文、工具参数和日志仅包含必要字段
4. `/storage.db` 及常见备份路径对未认证请求稳定返回拒绝或不存在
5. 用户 A 和租户 A 无法读取其他主体的测试 marker
6. 数据库、日志、缓存、临时文件和备份均满足保护要求
7. 删除测试记录后，主库、索引、向量库、缓存和第三方副本同步处理
8. CDN、历史版本和对象存储版本不再暴露旧数据
9. 审计日志可关联收集目的、访问主体、解密、导出和删除事件
10. 重放 EDH-01～EDH-08 与 IS-01～IS-10，确认策略稳定
```

## 10. 最终判定口径

```text
安全：仅处理完成明确业务目的所需的数据；所有副本具备适当授权、隔离、保护、保留和删除控制。

低风险：存在不必要字段或过长保留，但使用合成数据验证时未发现未授权访问；仍需整改数据最小化和生命周期。

高风险：普通用户、跨租户主体或未认证请求可以访问对话、训练、日志、备份或导出数据。

严重：不安全存储与过度数据处理叠加，导致医疗、支付、凭据、身份信息或大规模训练/用户数据可能泄露。
```

同态加密可在特定高价值计算场景减少明文暴露，但性能和系统复杂度成本较高，不应替代数据最小化、访问控制、常规加密、密钥管理与生命周期治理。

## 11. 可复用考试代码块：Web 根目录数据库泄露

用途：AI 应用把对话、用户信息、训练数据或日志导出文件放在 Web 可访问目录。

```bash
TARGET="http://STMIP:STMPO"
WORDLIST="/usr/share/wordlists/seclists/Discovery/Web-Content/raft-small-words.txt"

gobuster dir -u "$TARGET/" -w "$WORDLIST" -x db,sqlite,sqlite3,txt,log,bak,zip,html
```

```bash
TARGET="http://STMIP:STMPO"

wget "$TARGET/database.db" -O database.db
file database.db
strings database.db | grep -Ei 'HTB\{|flag|medical|password|credit|admin|condition'
```

如果是 SQLite：

```bash
sqlite3 database.db ".tables"
sqlite3 database.db "SELECT name, sql FROM sqlite_master WHERE type='table';"
sqlite3 database.db "SELECT * FROM llm_queries;"
```

核心技术点：

```text
[ ] 目录枚举时加入 .db/.sqlite/.txt/.log/.bak
[ ] 下载后先 file 判断类型
[ ] 文本 dump 用 strings/grep，SQLite 用 sqlite3
[ ] 重点查 llm_queries、users、messages、orders、logs、sessions
[ ] 根因是不必要收集敏感数据，并把数据库/备份放在 Web 根目录
```

一句话总结：**先让应用少拿、少传、少存、少留，再确保每一个必要副本都只能被正确主体在正确目的下访问，并能按期彻底删除。**
